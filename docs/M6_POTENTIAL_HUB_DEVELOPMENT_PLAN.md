## 1. 本轮目标与优先级

构建 **势资源中心（Potential Hub）**：研究人员提供真实原子结构和分析目标，MaterialsX 自动寻找适合的机器学习原子间势，按需下载、准备环境、加载计算，并在聊天中呈现可追溯的结果与 3D 结构。

> 需求与结构 → 搜索势目录 → 判断适用性 → 选择 checkpoint → 按需下载与挂载 → 真实计算 → 3D 与双语报告。

同时建立持续增补机制：跟踪官方模型仓库、权重发布和新论文，自动形成目录候选；经过来源、许可、适配和运行检查的模型，进入用户可以自动使用的目录。

按用户最新指示，**M7 多尺度与统一材料研发方法论暂缓推进**。本阶段不依赖首个复合材料选型、宏观求解器或逆向设计研究，也不改变 M5 的支付与 Token 规则。

### 1.1 “全量”如何落实

| 层次 | 产品承诺 | 完成口径 |
| --- | --- | --- |
| 全面收录 | 持续覆盖已接入来源中的公开模型家族、具体权重和历史版本 | 记录来源范围、上次同步时间、收录/遗漏数量；按来源逐项补齐 |
| 按需安装 | 像模型下载工具一样搜索、下载、暂停、续传、导入和卸载 | 下载具体 checkpoint 的必要文件，显示权重与环境各自占用 |
| 自动挂载 | 已适配且满足本机条件的模型可由 AI 自动加载 | 任务前完成文件身份、环境、适用域和资源复验 |
| 自动增补 | 新发布进入候选库，审核通过后进入可运行目录 | 目录内容可独立更新；新架构需要新增经过测试的适配器 |

“全量”以公开且能够追踪的来源为边界，不承诺发现未公开、闭源或没有权重的所有模型。默认安装完整目录和通用任务 Skills，权重及大依赖按需安装；自动挂载是为任务加载模型，并不同时把所有势加载进内存。

借鉴 LM Studio 的搜索、模型卡片、下载队列和本机管理体验。MLIP 的权重格式、Python 依赖、计算头和适用域各不相同，需要多个计算器适配器，不能只用一个统一加载函数处理所有模型。

## 2. 当前基础与实际缺口

依据当前代码及 [M6.6 验收说明](m6/validation.md)：

| 当前已有 | 本轮补齐 |
| --- | --- |
| M6.0 的 7 家族、16 个具体 checkpoint 冻结目录；另有包含多类科学模型的 100 条模型目录 | 统一、可更新的 MLIP 专用目录；不能将 100 条科学模型算作 100 个机器学习势 |
| 可执行 `mace-mp-0b3-medium`、`chgnet-0.3.0`、`chgnet-r2scan` | 通用 checkpoint 身份、多个权重包和多个环境配置 |
| r2SCAN 扩展包固定来源、大小、SHA、下载/续传/导入/禁用 | 泛化多文件下载、环境安装、卸载、缓存容量与失败恢复 |
| 真实单点、FIRE 优化、受限 NVE/NVT、科学任务队列 | 将下载、挂载和计算组织为可恢复的一条任务链 |
| 硬条件过滤、LLM 候选选择、来源与排除理由 | 将“尚未安装但可安装”纳入选择；下载完成后再次验资格 |
| 原子 3D、前后对比、轨迹、真实产物与双语报告 | 统一势卡片、过程卡片、自动选势说明和版本追溯 |
| 默认原子任务 Skills、Pi 本地与云端受控工具 | 通用搜索/安装/自动分析工具；不把全部模型资料塞进 LLM 上下文 |

目前的科学运行边界主要是 **无机三维周期晶体的探索性 CPU 计算**。运行成功与科学精度验收是两项独立状态；已有 `needs_review` 不能因目录扩充而自动升级为领域验证通过。

关键实现点：`atomistic-runtime.ts` 中的可运行 ID 仍是固定枚举；M6.6 扩展合同与包管理器固定为单个 r2SCAN 包。本阶段必须扩展合同、包管理器和 Python 调度，单纯新增模型卡片无法实现自动运行。

## 3. 首个可交付价值

### 3.1 第一条闭环

用户导入受支持的周期晶体 CIF，并输入：

> 帮我选择本机适合的机器学习势，优化这个结构，展示优化前后差异，并说明为什么选它。

英文同等支持：

> Choose a suitable interatomic potential for this crystal, relax the structure locally, show the before-and-after comparison, and explain your choice.

系统依次完成：

1. 读取真实结构，核实元素、原子数、周期性、占位、距离和任务条件。
2. 查询已安装及可安装的合格候选；AI 在候选内选择，并给出证据与排除理由。
3. 若需要的审核包尚未安装，在用户已设定的自动安装与资源范围内下载，复用环境或安装审核环境。
4. 完成哈希验证、本机运行探针和最终任务资格复验，加载确切版本。
5. 执行受限单点或固定晶胞优化，持续展示真实进度。
6. 显示实际收敛状态、能量/力、3D 前后对比、模型来源和探索性限制。
7. 导出结构、原始计算数据、运行回执和中英文报告。

首次演示必须包括 **一个审核过、此前未安装的新 checkpoint，从下载到实际 CPU 计算的完整过程**。已有模型离线复用是第二条验收路径。

### 3.2 首批模型与任务

- 复用已有三种势，新增至少两个经审核的 MACE checkpoint；首批目标是至少五个可执行 checkpoint、两个已有家族。
- 优先核查 `MACE-MP-0b2 small` 与 `MACE-MPA-0 medium` 的固定官方文件、兼容版本及本机环境；这些是待验证候选，不预先宣告已安装或可运行。
- 首批自动任务限定为单点、固定晶胞优化；短程 MD 只在对应 checkpoint 的任务检查通过后开放。
- 首版 CPU 先形成闭环；GPU、分子、表面、带电体系分别验收后增加。
- AI 搜索不到合适模型时给出缺失条件或候选发现结果，不能拿不合适的势强行计算。

MACE 官方目录分别列出训练集、理论层级、目标体系、模型尺寸、框架版本和许可证，适合作为首批结构化接入来源。同一模型家族的不同 checkpoint 也需要分别建档。[官方模型目录](https://github.com/ACEsuit/mace-foundations)

## 4. 全面目录与分类

### 4.1 分类体系

| 分类轴 | 示例 |
| --- | --- |
| 体系 | 无机晶体、金属/合金、分子、分子晶体、表面/吸附、界面；允许多标签 |
| 任务 | 能量与力、应力、结构优化、短程 MD；后续专用任务单独扩展 |
| 覆盖方式 | 多元素通用、特定元素组合、特定材料专用、用户训练模型 |
| 模型家族 | MACE、CHGNet、SevenNet 等；家族不是具体可下载权重 |
| 理论与训练域 | PBE、PBE+U、r2SCAN 等；保留训练体系和来源证据 |
| 本机条件 | 操作系统/架构、CPU/CUDA/其他已验证后端、内存与依赖 |
| 可用性 | 仅论文、待审核、可下载、需授权、已安装、当前任务可运行 |
| 科学状态 | 未评测、运行检查通过、特定任务检查通过、特定领域验证通过 |

体系标签用于检索；只有细化到 checkpoint 的适用域与任务能力才参与自动执行。仅覆盖某元素不代表覆盖该元素的所有化学环境。

### 4.2 初始来源扩展队列

以下为目录接入和适配候选，不是本机默认下载清单：

| 来源组 | 目录接入计划 | 执行扩展计划 |
| --- | --- | --- |
| MACE | 补齐官方公开 checkpoint、版本、训练域和计算头 | 先扩充当前材料势，再单独评审其他域与多头模型 |
| CHGNet | 固定官方 checkpoint 及历史版本关系 | 复用现有加载与验证路径 |
| MatGL 势模型 | 区分 M3GNet/TensorNet 等势 checkpoint 与普通性质预测模型 | 评估后作为新增适配器候选 |
| SevenNet | 收录公开预训练权重与对应版本 | 与 MatGL 比较本机安装成本，选择一个先验收 |
| FAIRchem / UMA | 收录模型卡、访问条件、任务头和独立权重许可 | 获取访问授权且完成平台验收后启用 |
| NequIP / Allegro | 分开记录框架和具体作者发布的训练模型 | 按具体 checkpoint 的元素、配置和格式接入 |
| DeePMD | 收录具体发布的模型，而非将框架视为通用预训练势 | 单独适配后端、元素类型映射和模型文件 |
| MatterSim / ORB | 当前已有部分 checkpoint，补全历史版本、明确来源与各自科学域 | 加入 M6.10 适配队列；OrbMol 的分子域另行验收 |
| PET / GRACE / ALIGNN-FF | 收录作者官方公开发布，区分势与性质权重 | 进入环境与适用域评审队列 |
| NEP / NEP89 / GPUMD | 分开登记势方法、具体 checkpoint 与模拟引擎 | 专用势与原生引擎候选，GPU/编译条件单独验收 |
| ANI / AIMNet2 等分子势 | 建立分子势分类及具体模型记录 | 分子结构、电荷/自旋与任务合同扩展后启用 |
| SO3LR / BAMBOO / FeNNol 系列 | 补分子/电解液条目、组合物理项、权重许可与维护状态 | 分子与长程执行候选；当前不拓宽晶体 worker 范围 |
| GAP / MTP / SNAP / ACE 等 | 区分方法、训练工具和真正提供的势文件 | 按具体势文件及其计算器实现接入 |

全面覆盖任务及 M6.13–M6.15 可选扩展见 [机器学习势清单覆盖与增补规划](M6_POTENTIAL_CATALOG_COVERAGE.md)。用户资料中的全部名称均进入覆盖追踪；架构、描述符、商业服务和性质模型分别归类，不一律视为可下载势。

目录首轮按来源完成清点，目标覆盖约 10–15 个来源组；具体 checkpoint 数量以实际发布清单为准，不为凑数量复制镜像或虚构版本。随后持续扩展其他来源和用户私有模型。

新增执行家族优先比较 [SevenNet](https://github.com/MDIL-SNU/SevenNet) 和 [MatGL](https://github.com/materialyzeai/matgl) 的官方实现。实施时固定版本重新检查，不依据旧项目名称或旧文档直接安装。

## 5. 模型卡片、版本与证据合同

### 5.1 每个 checkpoint 的必备信息

| 信息组 | 必备字段 |
| --- | --- |
| 身份 | family、checkpoint、release、不可变 revision、别名、权重文件列表与 SHA-256 |
| 用户内容 | 中文/英文简介、适合与不适合的任务、1–2 个双语使用例子 |
| 科学信息 | 元素、周期性/体系、输出属性、训练域、理论层级、电荷/自旋与 head 要求 |
| 来源证据 | 官方仓库、模型卡、论文 DOI/arXiv、字段证据片段、抓取日期、来源快照 |
| 分发信息 | 权重许可、代码许可、依赖许可、访问门槛、是否允许再分发、上游引用 |
| 安装信息 | 审核过的下载资产、文件大小、展开大小、适配器 ID、环境锁、平台条件 |
| 运行证据 | 平台/设备/版本、测试输入、数值检查、任务检查及独立领域验证记录 |
| 更新关系 | 前驱/后继、官方推荐说明、废弃/撤回状态；保留历史运行可复现性 |

未知字段保存为未知，并说明缺失来源。自动翻译不能补造训练数据、元素范围、精度、许可证或硬件兼容性。展示上游声明时标明“作者声明”，本机测试结论单独展示。

### 5.2 各项状态独立保存

- 发现状态：`observed / paper_only / candidate / reviewed / withdrawn`。
- 安装状态：`absent / queued / downloading / paused / verifying / preparing_environment / checking / installed / failed / disabled`。
- 任务资格：针对当前结构、任务、平台返回 `eligible / blocked` 与原因。
- 科学状态：`unassessed / runtime_checked / task_checked / domain_validated`，领域验证记录必须带适用范围。

不能用一个“已安装”勾选同时代表文件下载、本机能运行和预测准确。界面可显示：“已安装 · 本机 CPU 可探索运行 · 科学精度待评测”。

同一文件在 GitHub 与 Hugging Face 上的镜像按身份和哈希去重；同名权重被上游替换时建立新 revision，不能覆盖旧记录。现有 M6 冻结文件保持历史语义，新目录采用版本化增量清单。

## 6. 通用下载、挂载与空间管理

### 6.1 权重包

将单模型包管理扩展为通用包管理器。每个包可包含权重、配置、元素表、归一化参数及许可证；按资产白名单下载，不拉取整个仓库和训练集。

- 支持下载队列、进度、暂停、续传、取消、失败重试和重启恢复。
- 续传核对资产身份与 ETag/Range；远端变化时重新开始，不能拼接不同版本。
- 文件大小与 SHA-256 通过后原子提交；失败文件不会成为可挂载模型。
- 支持已审核包的本地导入和离线包；第三方文件需匹配清单，不能只凭扩展名加载。
- 对 Hugging Face 使用固定 commit 与必要文件列表；下载配置、缓存回执和实际路径由包管理器统一负责。[官方下载与版本固定文档](https://huggingface.co/docs/huggingface_hub/en/guides/download)
- 权重存储按内容哈希去重；复用已有缓存时先验文件，不让 SDK 再生成一份完整副本。

### 6.2 运行环境与适配器

环境按“适配器 + 依赖锁 + 平台 + 后端”管理，兼容 checkpoint 共享环境，不兼容版本隔离。现有便携 CPU 环境优先复用。

适配器提供统一接口：

```text
describe_capabilities → probe_environment → validate_checkpoint
→ create_calculator → singlepoint / relaxation / supported_md
→ normalize_outputs → unload
```

统一的是任务输入、结果与生命周期；内部仍调用各自官方计算器。新模型格式不交给 LLM 临时编写并执行安装脚本。环境安装使用审核锁文件或固定平台运行包，不修改用户系统 Python，不升级正在使用的环境。

CPU 为首批标准路径；CUDA、MPS 等按适配器和具体平台记录实测支持，不能只检测到显卡就显示可运行。模型按任务加载，首版只保持一个科学计算活动槽位；空闲后释放模型进程和内存。

所有计算器使用本地已校验路径。科学 worker 不负责联网找权重；必要资源缺失时返回包管理请求，避免第一次推理时出现无进度的隐式下载。

### 6.3 空间预算

先估算 **权重 + 新增环境 + 下载临时文件 + 解压峰值 + 任务产物**，再启动安装。共享环境只算新增占用；无法可靠估计时不能当作零。

建议初始策略，可在设置中调整：

| 项目 | 默认规划 |
| --- | --- |
| 自动下载范围 | 审核通过、当前任务适用的包；首次启用时说明规则并保存授权 |
| 单任务自动新增权重 | 最多 1 GiB；优先已安装模型和可复用环境 |
| 自动新增环境 | 需要新环境时先显示实际预估；超出已授权范围才请求扩展 |
| 扩展包软配额 | 10 GiB，权重与新增环境分别统计；已有核心包单列 |
| 下载/安装/计算并发 | 最多两个下载、一个环境安装、一个科学计算；共享资源总预算仍生效 |
| 清理 | 展示可回收项；用户确认后删除未被任务使用的包和共享环境 |

不自动删除项目输入、科学结果或用户第三方缓存。卸载前检查运行引用及共享依赖；已完成任务保留版本回执，若权重被卸载则说明复现需要重新下载。界面直接提供“为什么占空间”的文件清单。

规模预估：纯目录与双语说明通常远小于权重和依赖；规划元数据控制在几十 MiB 内，源码仓库不提交大权重。安装包维持现有核心规模，新增依赖按需分发。实际新增空间取决于已选包，不能用“收录 100 个势”推算安装大小，也不承诺所有势固定总大小。

## 7. AI 自动选势与执行

### 7.1 两阶段资格检查

**阶段 A：可以考虑安装。** 系统筛选来源已审核、适配器可用、许可允许、目标平台有环境方案、科学域与任务匹配的候选。尚未安装的 checkpoint 可以进入此候选集。

**阶段 B：可以执行任务。** 安装后以真实文件、环境探针、输入哈希、资源和任务参数复验；只有通过者才进入执行集合。不能让 LLM 的推荐替代这些检查。

硬条件包括元素/化学域、PBC、输出属性、占位、最小距离、必要 head、电荷/自旋、计算条件、平台资源和运行验证记录。目标为变胞时要求已检查的应力能力；只有性质预测输出的网络不得接入力学积分器。

### 7.2 AI 如何决策

1. 从用户目标识别任务，结合真实结构检查形成结构化请求。
2. 检索中文/英文别名和模型卡，先做硬条件过滤。
3. 排序考虑同类任务验证记录、训练域匹配、本机资源、已安装状态与下载成本。
4. LLM 阅读少量候选及来源证据，提出 checkpoint、参数、理由和备用候选。
5. 系统验合同、候选身份与预算，再调用下载/执行工具。

用户可设置“本机优先”“节省内存”“优先已有领域验证”或固定模型；默认优先适用且已安装的模型。不存在独立精度依据时显示兼容候选及选择理由，不伪造准确率排序。最新版本、下载量或 GitHub 星数不能单独成为科学最佳的证据。

输入缺少结构、必要电荷或自旋时补充询问；可以使用用户选定的真实内置样本，但不把临时虚构结构当成用户材料。强度、寿命等不在当前合同内的目标应解释能力缺口，不用单点能量冒充宏观性能。

### 7.3 通用工具与恢复

新增或扩展以下受控工具，名称为拟定合同：

```text
potential_search(query, filters)
potential_describe(checkpoint_id)
potential_plan(task_id, preferences)
potential_install(plan_id)
potential_install_status(operation_id)
potential_analyze(plan_id)
potential_run_status(run_id)
potential_cancel(operation_or_run_id)
```

工具使用注册 ID 与已冻结计划，不接收任意 URL、安装命令或 Python 代码。泛化枚举时仍要求 ID 解析到可信 manifest，不能直接改成任意字符串即可执行。

将“计划—安装—环境—预检—计算—报告”保存成工作流状态；聊天中断或程序重启后根据实际回执恢复。下载重试不会重复创建科学任务；计算中断保留真实最后状态，不默认宣称积分器续算。备用势切换必须重新验资格，并显示最终实际使用的模型。

用户开启某一任务范围的自动安装/探索运行后，在已授权结构、步骤、网络/磁盘及计算预算内连续完成。平台云工具的授权回执应覆盖这条明确任务链，过期或扩展范围才重新确认；保留旧逐次确认模式作为兼容路径。

本地 LLM 与 M5 平台 LLM 使用同一科学合同。LLM 仅解释和调度，数值由本机计算器生成；本地 CPU 计算不扣云 Token 积分，云 LLM 用量仍走现有 M5。默认不把完整坐标上传到目录来源或模型服务。

## 8. 新论文与新势的自动增补

### 8.1 来源层

第一层跟踪作者官方仓库、GitHub Release 和官方 Hugging Face 组织，采用增量游标、分页、条件请求、超时和限流退避；不能只取 latest 而漏掉历史版本。[GitHub Release API](https://docs.github.com/en/rest/releases/releases)

第二层查询论文元数据及模型链接。首批使用 arXiv API；关键词同时包含中文需求映射与英文术语，如 interatomic potential、universal potential、machine learning force field。后续再接其他许可允许的元数据源。[arXiv API](https://info.arxiv.org/help/api/index.html)

第三层支持用户提交 DOI、论文、官方模型链接或私有清单，加入本机候选队列。单篇新论文没有公开权重时显示“仅论文”，不制造下载按钮。

### 8.2 增补流水线

```text
源更新 / 论文检索
→ 元数据抓取与快照
→ 家族 / checkpoint / revision 去重
→ 关联论文、官方代码、具体权重
→ 双语介绍与示例草稿
→ 来源 / 许可 / 依赖 / 适用域审核
→ 固定资产与环境、隔离运行检查
→ 发布可信目录版本
→ 客户端更新与按需安装
```

自动完成发现、去重、字段提取、翻译草稿、更新差异与已有适配器测试。来源或许可不明确、全新架构、依赖变化、未知序列化方式进入维护者审核队列。审核在公共目录发布侧完成，用户不必为每个模型重复做代码审计。

新 checkpoint 符合已有适配协议时，平台可自动执行检查并生成待发布包；检查通过也不能自行赋予领域科学验证。全新模型家族需要维护者增加适配器，不让论文中的代码指令直接控制本机。

### 8.3 部署方式与同步频率

- 初期采用仓库中的来源配置、采集脚本和审核清单，发布独立、签名的静态目录；无需先新建运营中心或数据库。
- 后续把采集任务迁到计划中的 GitHub Actions 或独立 worker，建议每日查官方发布、每周查新论文，均可配置。
- 客户端启动时及应用运行期间检查目录，默认最多每日自动刷新一次，提供“立即刷新”。软件关闭后由服务端采集维护目录，不承诺客户端仍后台运行。
- 联网失败使用上次可信目录，已安装的合格模型保持离线计算。
- 公共发现只交换模型元数据；私有论文、结构和结果默认留在本机。

以上调度属于待开发能力，本次仅制定计划，不创建定时任务。

### 8.4 信任、许可与回退

目录签名公钥随应用内置，发行清单固定资产 SHA、环境锁与审核记录；更新核对签名、版本序号、有效期和撤回信息。支持维护者签署的回退版本及密钥轮换，不能接受任意旧清单来绕过撤回。

SHA 校验证明文件身份，不证明模型可信。PyTorch/pickle 权重可能执行代码；HF 扫描也不是安全保证。兼容时使用安全加载格式/参数，其他格式经适配器评审并在受约束 worker 中加载。[Hugging Face 说明](https://huggingface.co/docs/hub/en/security-pickle)

普通子进程不等于安全沙箱。首批只加载经审核的官方包；新源试验环境需要实际实现网络、目录写入与进程权限限制，无法满足时继续保持候选状态。README、论文和模型卡均按不可信资料处理，不接受其中的工具调用或安装指令。

代码、权重和数据分别记录许可。需要用户访问授权的模型显示相应入口，下载凭据存入系统凭据库；这不改变 LLM 云接口无 BYOK 的产品规则。FAIRchem 官方说明 UMA 需要申请访问，并要求分别检查权重与数据许可。[官方安装与许可说明](https://facebookresearch.github.io/fairchem/install/)

撤回或损坏的包阻止新加载，并提供原因和合格替代项；保留已有报告与引用记录。目录更新不覆盖正在执行任务的固定版本。公共再分发不明确的权重优先提供上游下载方式，不能默认随 AGPL 项目一起打包。

## 9. 中英文界面、Skills 与结果展示

### 9.1 势资源中心入口

沿用“模型目录 → 机器学习势”，扩展为：

- **发现 / Discover**：关键词、家族、体系、元素、任务、硬件与可用性筛选。
- **已安装 / Installed**：权重、环境、当前占用、最后使用、禁用、卸载与定位。
- **下载 / Downloads**：真实进度、环境准备、暂停/继续、错误和可回收空间。
- **更新 / Updates**：新模型、新论文、已审核版本和暂不可运行原因。

所有页面继承现有系统主题及 Skills/模型目录样式；不增加独立主题设置。名称保留上游规范，简介、状态、筛选、错误、证据解释与示例完整支持中文/英文。

#### 页面样式与全局配色：必须满足的开发要求

按用户 2026-10-02 最新要求，**新增页面以现有 Skills 页面为样式和呈现形式的基准，统一使用 MaterialsX 全局配色**。该要求适用于 M6.7–M6.15 中新增的页面、详情、抽屉、弹窗及聊天过程/结果卡，不只适用于首页。

- **页面结构一致**：复用 Skills 页的标题区、内容宽度、搜索框、分类标签、卡片排列、间距和滚动方式；必要的下载进度、家族/版本等专有信息加入同一视觉结构。
- **卡片与详情一致**：字体层级、图标、边框、圆角、按钮尺寸、状态标签、悬停/选中/焦点反馈保持一致。点击资源进入与 Skill 详情一致的呈现方式，提供中英文介绍、使用例子和复制到输入框操作。
- **组件与样式复用**：优先使用现有共享组件、全局样式和主题变量；需抽取通用组件时兼顾 Skills 与新页面，不复制出独立的配色与组件体系。
- **单一主题来源**：背景、文字、主色、边框、状态、禁用态、进度条和图表界面使用全局主题变量。新增页面不设置独立配色或主题开关，不存储单独的页面主题偏好；全局主题切换时即时同步。
- **状态和媒体可读**：所有现有全局主题下检查正常、加载、空结果、错误、暂停、禁用和选中状态；状态同时有文字说明。3D 科学着色保留元素/力等物理含义，其外层界面、文字、图例和控件跟随全局主题。
- **中英文与窗口适配**：中文/英文标签、长模型名、窄窗口、详情抽屉和大目录滚动均沿用 Skills 页的布局原则，内容不重叠、不被按钮遮挡。

M6.7 的全部势目录和详情即按上述要求交付；M6.8 下载管理、M6.9 分析卡片、M6.11 更新发现及后续扩展各阶段同步验收，M6.12 再做集中回归。不能把风格统一推迟到发布前。

### 9.2 Skills 与模型内容的关系

保留通用选势、单点、优化、MD、对比和 3D Skills，按需新增“势检索与安装”“自动势分析”“新势发现”三个双语 Skill。

**每个 checkpoint 是结构化资源条目，不强制生成一个重复的独立 Skill。** 模型详情提供两条可复制示例，`@` 优先调用任务 Skill，并可搜索/绑定具体模型条目。LLM 通过搜索工具获取候选摘要和选中模型的详情，避免每次注入全目录导致上下文与响应开销增长。

例子必须区分“本机已验证可执行”和“接入后可用的规划例子”；当前仅目录收录的分子势不能展示为已经可以一键运行。示例关联实际样本或要求用户导入结构。

### 9.3 聊天中的过程与结果

过程卡按“检查结构 → 匹配势 → 下载 → 准备环境 → 加载 → 计算 → 生成报告”显示真实事件。下载量/总量、迭代步、最大力与资源监测由工具提供；没有可靠 ETA 时不编造百分比。文字保持现有缓冲流式展示，工具耗时不阻塞输入和取消操作。

最终结果卡包括：

1. 本次选择及理由、其他候选的排除原因。
2. checkpoint/revision/权重 SHA、计算器版本、head、设备、精度设置及实际修正项。
3. 实际数值、单位、收敛状态和当前任务范围；失败/未收敛明确标记。
4. 真实 3D 结构、优化前后对比；MD 使用已有真实轨迹播放器。
5. 可下载的结果 JSON、CIF/extxyz、力表、运行回执与双语 Markdown 报告。

多势对比使用相同输入和任务条件。不同能量基准或理论层级的绝对总能量不直接混合比较；差异不是经过校准的置信区间。不把生成的报告文字视为计算完成的证据。

## 13. 补充决策：能力目录、全目录页面与 Skills 扩展

补充日期：2026-10-02。用户进一步确认需要讨论目录如何支撑 AI 匹配，以及 Skill 创建和搜索能力。本节明确前文的实现分工，仍属于规划，不表示已添加这些功能。

### 13.1 能力目录是 AI 匹配的前置基础

必须先建立可被程序检索的能力目录。不能只保留模型名称和介绍，也不能依赖 LLM 记忆猜测某个势能否用于特定任务。模型页面、AI 工具与安装器共同读取同一版本化目录，避免形成三套互不一致的数据。

“全部目录”是持续维护接入范围内的公开模型；不要求穷尽全球模型才开始首条闭环。先将现有目录及官方来源已核实的 checkpoint 建档，随后增量完善。尚缺关键能力、权重或许可的条目可被搜索，但不自动运行。

能力合同分三部分：

| 部分 | AI 匹配所需数据 | 数据依据 |
| --- | --- | --- |
| 科学能力 | 元素、训练化学域、体系/PBC、能量/力/应力输出、理论层级、head、电荷/自旋、任务与已知限制 | 官方模型卡/配置/论文，逐字段保存来源；未知明确标注 |
| 执行能力 | 权重资产、计算器、环境锁、OS/架构/设备、内存、下载与安装峰值空间 | 审核发行清单及本机探针；不可只凭作者安装命令推断 |
| 验证能力 | 哪个平台能加载、哪些任务实算过、哪些材料范围有独立误差评测 | 分层验收记录，保留测试集与版本，不相互替代 |

匹配采用：**真实结构和目标 → 结构化硬过滤 → 检索候选证据 → AI 选择与解释 → 安装后资格复验**。中文/英文搜索先做别名、术语和字段索引；初期使用关键词及结构化过滤即可，不强制建设向量数据库。语义检索后续补充，不能绕过硬过滤。

每次选择保留目录版本、结构摘要、候选清单与排除理由。用户询问“为什么不用另外一个势”时，可直接从该记录回答。

### 13.2 全目录页面是首阶段交付内容

M6.7 必须交付“全部势 / All Potentials”，作为现有模型目录内的完整入口；前文 Discover 页默认展示全部已收录条目，不能默认只显示已安装模型。

页面包含：

- 当前来源范围、同步时间、家族数、去重后的 checkpoint 数、本机可运行数。
- 全部/当前任务适用/可安装/已安装/仅论文/待适配等筛选。
- 家族分组与具体权重版本展开，避免把近似名称当成重复模型。
- 中文/英文能力说明、任务、元素/体系、理论层级、空间占用、来源与状态。
- 模型详情中的证据、限制、两条双语例子，以及适用时的下载/使用入口。
- 已安装模型和下载管理复用同一资源身份；用户可选择隐藏历史版本，但仍可查询。

用户查看全部条目不等于一次加载全部卡片或向 LLM 注入全目录；前端采用分页/虚拟列表，模型侧只按需返回匹配候选。

### 13.3 推荐四层扩展架构

| 层 | 职责 | 新模型如何扩展 |
| --- | --- | --- |
| **Registry：结构化资源与能力目录** | 告诉系统模型是什么、适合什么、从哪里取得 | 新增 checkpoint manifest、双语内容和来源证据 |
| **Skill：任务方法与领域流程** | 指导 AI 如何选势、设参数、解释、检查和报告 | 新增或复用通用任务 Skill；特殊工作流附加专用 Skill |
| **Adapter：可执行计算器接口** | 将模型格式和官方库接入真实科学任务 | 已有架构复用适配器；新架构增加经过测试的适配器 |
| **Package/Runtime：包与环境管理** | 下载、校验、安装、加载、卸载、取消与资源管理 | 新增审核资产与环境 profile，兼容环境共享 |

推荐提供一个可分发的“势扩展包”：

```text
potential-extension/
├── manifest.json             # 身份、能力、资产、适配器/环境引用
├── descriptions.zh.json
├── descriptions.en.json
├── examples.json             # 双语例子与运行前置条件
├── sources.json              # 官方来源与证据引用
├── LICENSES/                 # 分别保留代码、权重等许可
└── skills/                   # 可选：特殊分析工作流的 SKILL.md
```

扩展包通过同一发行审核、固定版本与身份验证。计算器实现由应用认可的适配器提供，不能因为包里有 `SKILL.md` 就取得安装任意代码的权限。

相同架构的新 checkpoint 通常通过数据清单扩展，无需改动核心逻辑。只有方法说明的新 Skill 可单独扩展研究流程；只有 Skill 而没有权重/适配器的包不显示可执行。需要专用体系流程时，可使用“家族或场景 Skill + 多个具体 checkpoint”，不机械地为每个尺寸生成同一份 Skill。

## 14. 补充决策：默认 Skill 创建与搜索基础能力

### 14.1 Pi 本身提供什么

本轮核查基线是 MaterialsX 当前依赖的 `@earendil-works/pi-coding-agent@0.99.1`、本机随包文档及官方文档：

| 能力 | Pi 的现有支持 | MaterialsX 需补齐 |
| --- | --- | --- |
| Skill 发现与按需读取 | 支持目录扫描、名称/描述和 `/skill:name`；详细说明按需读取 | 保持现有 SDK 装配，并接入新建/导入的用户 Skills 与双语索引 |
| 创建 Skill | 可以由 LLM 借助文件工具编写 `SKILL.md`；提供格式规范 | 默认创建指导 Skill、模板、验证、保存/版本/示例/UI 集成；不是一个已完成的内置管理服务 |
| 文件搜索 | `grep`、`find` 等可选内置工具；默认启用集合并不包含所有工具 | 当前本地会话已显式启用 `find/grep/ls` |
| 工具搜索 | `tool_search` 用于检索未声明的已注册工具，包括相应 MCP 工具 | SDK 需显式装配、注册并启用；不是互联网或模型目录搜索 |
| MCP / codemode | CLI 有内置扩展；SDK 会话不自动装配 | 宿主按需接入已授权工具，不等同于拥有搜索供应商 |
| 互联网/论文搜索 | 基础工具集合没有一个开箱即用的通用联网搜索服务 | 自建搜索接口、官方来源连接器，或接入受控搜索 MCP/服务 |

依据：[Pi Skills](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md)、[Pi CLI 工具](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/cli.md)、[Pi SDK 扩展装配](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md)。

当前 `packages/pi-adapter/src/local-session.ts` 使用 `additionalSkillPaths`，但设置 `noExtensions: true`，仅显式提供本地文件/命令和科学工具。不能因安装了 Pi 就宣称联网搜索、MCP 搜索扩展或 Skill 创建管理已经生效。

MaterialsX 已内置 `research-lookup`，其当前上游说明依赖 Parallel 等外部服务及凭据。保留该 Skill 的独立来源与依赖说明，不能据此标记 MaterialsX 通用联网检索已开箱可用，也不将当前 Codex 环境中的 Skill 自动视作 MaterialsX 内置能力。

### 14.2 推荐默认集成的功能

| 产品能力 | 实现形式 | 默认边界 |
| --- | --- | --- |
| 创建 Skill / Create Skill | `materials-skill-creator` 指导 Skill + 受控创建/校验/登记工具 | 自然语言生成用户 Skill，保存至 MaterialsX 专用用户目录；不覆盖内置 Skill |
| 搜索 Skills / Search Skills | 内置索引与 `skill_search` 工具 + 详情页 | 先检索已安装内容，返回名称/双语描述/版本/依赖；支持 `@` 与示例 |
| 搜索势 / Search Potentials | 能力目录与 `potential_search` 工具 | 可离线运行；结构化条件与证据过滤 |
| 搜索论文 / Search Papers | 作者仓库/HF/arXiv 连接器及证据缓存 | 公共信息查询，保留来源、日期和抓取结果；不自动启用新模型 |
| 搜索网页 / Web Search、读取网页 / Web Fetch | 统一工具合同与可替换服务/MCP 适配 | 无服务时明确不可用；网页检索与正文读取分开，保留引用 |
| 搜索可用工具 / Tool Search | 需要大量 MCP 工具时启用 Pi 的对应扩展或等效宿主接口 | 只发现已注册能力，执行权限仍由宿主校验 |

联网检索首批优先免费公开来源，普通模型选势不依赖付费搜索供应商。通用网页搜索若需付费凭据，采用平台侧配置与受控服务，不要求用户提供 LLM API Key；费用政策与现有 Token 计费分开确定。M5 平台会话也要显式接通搜索工具与必要信息外发范围，不能只给本地会话增加工具。

Skill 生成流程：用户说明目标 → 检查可复用 Skill → 生成目录与双语说明/例子 → 格式、依赖与工具声明验证 → 保存版本 → 刷新注册 → 出现在 Skills 页与 `@` 菜单。文本流程可复用既有受控工具；包含新脚本或依赖的生成物先记录待验证状态，不因生成成功就宣称已可执行。实际用户目录位置和命名冲突规则在合同阶段固定。
