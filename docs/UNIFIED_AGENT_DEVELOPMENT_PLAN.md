## 2. 产品目标和首个结果

MaterialsX 理解材料研究目标，组织数据和证据，执行真实分析，检查适用性，并保存可延续的研究状态。公开 Codex runtime 与 Pi 都是保留的执行引擎，模型来源不限定引擎：本地 LM Studio 等服务与 M5 云端模型分别经兼容验收后可选 Pi 或 Codex。优先复用公开引擎的通用执行能力；材料领域逻辑由共同宿主、Skills 与 MCP 提供。模型能力、工具权限和科学有效性分别验证，替换模型或引擎不自动取得其他能力。

新增实验、配方、工艺、模拟、图片、性能数据优先通过 MOOS MCP 获取；用户明确的项目实测/指定文件先作为分析输入。MOOS 不足时按有效授权补外部数据和论文；arXiv 是默认外部预印本入口，不承诺覆盖全网或全部期刊。

首个交付闭环：

```text
研究问题 → MOOS MCP 查询 → 条件/版本/证据检查
→ 选定小型数据快照 → 真实分析 → 可编辑表格/图表/图片/报告
→ 保存项目状态，后续能继续或修正
```

已有结构→选势→真实计算→3D 仍是可靠性基准。后续围绕三条高频场景扩展：材料证据表、原始实验分析、受支持结构计算。模拟研究声明不能代替结构、可运行模型和真实计算。

## 3. 合并原则与禁止重复建设

自有代码单文件最多 600 个物理行，含空行，使用 `npm run source:size` 并纳入 check/CI；按职责拆分。确认无调用与兼容需求的无效/冗余实现直接删除，不压缩超长行或通过排除目录规避。

1. 一个能力只有一个主实现和一份领域合同。Codex/Pi、MOOS/外部来源、桌面/平台通过适配消费，不复制业务逻辑。
2. 按纵向任务交付，每阶段包含所需合同、后端、UI、验证、兼容和清理。不先建全部空目录、占位工具或微服务。
3. 优先复用已验证实现；先有能力差异证据，再增加适配器。既有 helper 可直接提取复用，不为相同职责新建多套 Manager/Service。
4. 任务监督不再实现 Codex/Pi 的第二套工具循环。原生终端/补丁由引擎执行一次，宿主关联授权、回执和结果；不能由另一个执行器再次运行。
5. Skill 组织方法和流程，后端提供真实执行/权限/验证。不同模型或材料势不分别复制完整业务流程。
6. 共用“技术完成、证据状态、科学适用、实验验证”合同；独立的检查职责可以分开，但状态与规则来源不能重复或互相覆盖。
7. 下载权重、读取数据、模型调用和计算费用有各自身份/预算，同一业务操作不重复启动、下载或扣费。
8. 每阶段迁移已涉及的旧调用，删除确认无调用的旧实现。必要兼容层须登记调用者、删除条件、回归案例和最迟清理阶段，不能永久保留两条默认路线。

| MOOS 服务 | MOOS 仓库 `services/materials-mcp/` 候选路径；白名单 HTTP adapter | MaterialsX 重写 MOOS 入库/复核/检索/数据库访问 |

| 科学执行与资格 | `packages/atomistic/src/`、Python/既有 worker 与合同 | 在研究 Skill 或聊天代码复制 M6 参数/适用性规则 |

工程依赖方向：contracts ← 领域/执行服务 ← 引擎薄适配和主进程组合 ← preload/renderer。上游 runtime 私有类型不得泄露到产品合同；服务不依赖 Vue/renderer。MCP server 和 client 分属服务/消费两端，共享版本化 JSON Schema，不复制同一业务数据库逻辑。

“一个状态源”不要求把所有数据塞在同一个表：任务步骤/执行回执由任务层拥有，样品/证据/研究决策由研究层拥有；通过稳定 taskId/projectId/ref 关联。MOOS 拥有原始事实，MaterialsX 保存有权限的输入快照和派生版本。

### 4.1 共同科研宿主与可选择的执行引擎

```text
MaterialsX 科研宿主
  ├─ 研究目标、约束、权限与预算（ResearchGoalPlan / TaskSupervisor）
  ├─ Skills、MOOS MCP、材料计算工具（共同能力目录与领域后端）
  ├─ 产物与科学证据验收（真实回执、输入版本、证据与适用性）
  └─ 选择一个执行引擎（AgentEngine）
       ├─ Pi（SDK / 既有会话与工具循环）
       └─ Codex App Server（独立打包的公开 runtime / 原生工具循环）

任一引擎 → 经兼容验收的模型连接
             ├─ 本地：LM Studio 等本机服务
             └─ 云端：MaterialsX M5 认证、网关与计量
```

**两个配置维度。** 用户先选模型来源/模型，再选该模型支持的执行引擎；本地模型不强制 Pi，云端模型不强制 Codex。Codex CLI 是公开运行时的终端入口，桌面通过其 App Server 接入，不另外维护第三套 CLI Agent。Pi 也可以调用云端模型。不存在“安装 Codex 就内置 GPT 权重”或“换引擎就自动改善科学精度”的产品承诺。

**一次执行只有一个引擎。** 同一 task attempt 固定 engineKind、engineVersion、modelConnectionRef 和兼容配置版本。引擎负责模型—工具—结果的循环，宿主负责合同、授权、预算、方法资格和验收。不能让 Pi 外层循环反复调用 Codex 内层循环，不能让协议代理、TaskSupervisor 或 MCP 再执行一次引擎已经执行的命令。

**共同能力，不要求相同工具名。** 两个引擎消费同一份 Skill 内容、MOOS 来源顺序、科学资格和材料 worker；原生 shell/patch 可以保留各自机制，薄适配映射产品能力和回执。MCP 生命周期、凭据与授权由共同宿主管理，引擎所需的协议连接由适配层维护，不另建 MOOS/材料数据库或收费系统。Skill 提供方法，不拥有权限；未通过验收的工具不能因换引擎变为可用。

**权限必须可执行。** 文件、进程、网络和数据外发边界在实际执行点检查，不能只写进提示词。Codex 保留原生审批/沙箱及必要外层隔离；Pi 使用宿主控制与按阶段验收的隔离能力，不能宣称两者已有相同沙箱。每个 OS/引擎单独记录支持范围。无法施加任务要求的限制时，该组合不可用，不降级为全盘访问。

**独立分发和配置。** 保留公开 Codex 固定版本程序、平台资源和许可证，全部放入 MaterialsX 专属安装资源及 userData；Pi 依赖也随程序提供。不依赖其他电脑安装 Codex、全局 PATH、用户 `~/.codex`、私人登录或订阅。模型服务和科学环境是另外的依赖，安装引擎不代表它们已经安装。版本升级先运行协议、恢复、权限与产物回归；保留可回退的应用版本。

**会话切换有边界。** 运行中先停止或完成当前 attempt，核实进程/计算回执后才能切换。相同引擎恢复其独立原生会话；跨引擎创建新原生会话，输入经过校验的研究目标、事实、计划与产物引用，不复制隐藏推理、不混用原生 thread ID。旧运行只读保留；已完成计算及账本不能被重新提交。用户未选择切换时不静默回退到另一引擎或云端模型。

**当前实现与目标分开。** UA.1 已有 AgentEngine、Pi/Codex 薄适配、独立分发及 macOS 平台 Codex 工程证据；v1.4 开放受控的本地 Responses + Codex 路径，见 [扩展验收](agent/ua-1-extension.md)。兼容探针、模型任务质量、科学准确性分别记录，未知组合不宣称可用。历史证据见 [ADR-0002](agent/adr-0002-native-engine-contract.md) 与 [独立分发](agent/codex-independent-package.md)。

## 5. 共用合同与数据边界

- TaskRef：taskId/projectId/conversationId、目标、权限引用、预算、输入版本/hash、步骤、尝试、真实 job/artifact ID、模型/协议、终态原因。
- ResearchRef：connectionId/sourceId/packageImportId/experimentId/generation/entityType/entityId；MOOS 原始 ID 与本项目 UUID 分开。
- Observation：原值/单位、归一值/单位与转换、含量基准、样品/试样、测试条件、重复数/不确定性、reported/calculated/predicted/digitized 等来源类型。
- Evidence/Asset：原文页/表/图/区域、来源版本、SHA、可读状态、权利、复核与关联状态；缺字段保留 unknown/null。
- AnalysisRun/MethodPackage：输入快照、固定代码/模型/环境、参数/种子、支持范围、参考验证、实际产物和回执。
- Hypothesis/Experiment/Decision：支持/反对证据、替代解释、否定条件、计划、真实测量、失败/偏离、人工纠错与影响依赖。

任务终态 completed/completed_with_limitations/blocked/failed/cancelled 与科学 needs_review/unsupported 等状态分开；实际实验未发生时保持待输入。模型文本、退出码、文件存在和多 Agent 一致都不自动升级科学结论。

### 5.1 研究目标与执行计划合同

本合同将用户需求、科学问题、执行步骤和交付验收关联起来，逻辑名暂定 `ResearchGoalPlan`。定义与校验唯一归属 `packages/contracts/src/`；UA.0 冻结字段与既有类型复用，UA.1 实现合同，UA.3/UA.4 消费同一版本。Codex、Pi、Skills、MCP、管线和 UI 不分别定义同义模型。

身份字段包括 schemaVersion、projectId、taskId、goalId/goalRevision、planRevision、executionMode、用户原始需求/后续修订引用、输入版本/hash，以及创建或修订原因。用户原话和用户确认内容保留，模型解释与补充假设单独标识，不将推测写成用户要求。

| 合同部分 | 至少保存的内容 | 执行要求 |
| --- | --- | --- |
| 目标 | 材料体系、问题类型、目标指标/单位/测试条件、优化方向、优先级、期望交付 | 未给定指标阈值或目标权重保留未知；不可擅自改变研究目标 |
| 约束 | 工艺范围、可变/固定因素、允许的数据来源、数据外发/执行权限引用、模型/计算预算引用、时间上限 | 区分硬约束与可协商偏好；合同中的文字不能扩大真实授权或修改 M5 余额 |
| 认知状态 | 已知事实及来源/条件/版本、缺失条件与影响、暂定假设及支持/反对证据、证据冲突 | 区分 reported/calculated/predicted 等来源类型；无证据保留 unknown，不伪造确定性 |
| 执行步骤 | 稳定 stepId、步骤目标、输入/版本引用、方法/Skill/tool 身份、依赖、预期产物、完成标准、实际 attempt/job/artifact 引用 | 复杂步骤依赖必须可校验；方法仍须通过现有可用性与科学资格检查 |
| 调整规则 | 补数据、换方法、重算、重试、停止的触发条件；影响步骤、有效授权范围、替代路径与调整原因 | 先查询实际执行状态，保护已完成且仍有效的结果；不能通过无限重试或放宽验收伪装成功 |
| 最终验收 | 必需/可选产物、完整性/hash、关键数值/单位/容差、证据与方法回链、允许的限制、任务完成判据 | 依据真实回执与产物验证完成；技术、科学、实验状态分别记录 |

**简单任务直接执行。** 输入充分、范围明确、低风险且无复杂依赖的查询、转换或已有工具任务使用 `executionMode=direct`。在已有任务记录内保留最小目标、约束、验收与回执，不强制额外调用模型生成长计划，不要求用户逐步批准，也不绕过任何权限或科学检查。

**复杂任务展开计划。** 多数据源、多步依赖、目标权衡、长计算或重要条件不确定时使用 `executionMode=planned`，保存有依赖关系的步骤，向用户展示简明目标、关键条件、执行路径和交付内容。步骤依赖须无环；迭代优化按真实尝试或新计划版本记录，不以循环依赖重复提交。可并行步骤仅由既有受管执行能力调度，UA.12 的子 Agent 仍须独立验收，不因有计划自动开启多 Agent。

**按影响程度澄清。** 已知条件不重复询问。影响方法选择、单位/含量基准、预算/权限、科学结论或不可逆操作的缺项和冲突，在对应步骤开始前必须解决；可以先进行不依赖答案且已获授权的读取与证据整理。可逆、低影响选择可以采用明确记录的默认值。没有数值目标时可以先做探索性比较，但不能宣称已经满足用户的性能目标。

**监督与工具执行分工。** 模型/引擎提出需求解释、计划或修改候选；宿主用共同 schema、实际权限、预算、方法资格和回执检查后保存有效版本。引擎继续负责自己的工具循环和执行，TaskSupervisor 只关联步骤、检查依赖/授权、管理预算/状态/完成证据，不成为再次调用同一工具的外层 Agent。读取文档、网页或第三方 Skill 得到的指令不能改写用户目标、权限、预算或验收标准。

**目标和计划可修订。** 用户多轮修改形成新的 goalRevision/planRevision，记录修改者、原因、差异和受影响输入/步骤/产物。保持未被取消的原目标；新增限制先作用于尚未启动步骤，运行中受影响任务通过真实取消/状态查询协调，取消未确认前不重复提交。关键输入改变时仅重算受影响依赖，保留历史和仍有效的结果。并发修订检查预期版本，过期模型响应不得覆盖新目标。

**调整受授权约束。** 数据不足时补充允许来源；方法不适用时选择合格替代方法；技术失败时按 UA.3 上限修复并核对结果。扩大费用、外发数据范围或执行权限时需要有效的新授权；已有授权内的步骤继续执行，不反复请求相同确认。预算/时间耗尽、明确取消、关键证据或工具缺失时输出真实原因，按共用终态处理，不把这些限制当成科学任务完成。

**完成标准在执行前确定。** 固定必需产物、参考方法与数值容差；来源或方法改变时记录影响及必要的重新验证。目标或交付标准实质变化必须保留用户依据及修订版本，不能为了通过验收降低要求。“没有合格候选”可按预定筛选交付标准完成；缺必需产物、无有效计算或关键证据不成立时不得 completed。允许的部分交付按 completed_with_limitations 及逐项验收结果展示。

**持久化复用已有所有者。** 目标、约束、认知状态、输入快照和研究决策由 ResearchProject/WorkspaceStore 既有基础拥有；步骤执行状态、尝试、权限/预算使用与回执由任务层拥有。合同以稳定 ID/版本引用关联，UI 读取组合视图，不保存第二份可变任务真相，不新建独立计划数据库。目标、关键约束、未解决问题和当前计划在上下文压缩与重启后仍可恢复；不要求保存或展示模型的隐藏推理过程。

**阶段归属。** UA.1 实现 schema、需求解释/规范化与 direct/planned 合同及校验；UA.3 实现依赖检查、版本化调整、权限/预算监督与回执恢复；UA.4 将目标和认知状态绑定真实项目/数据/产物，提供双语编辑、澄清和交付验收。UA.7/UA.9/UA.11/UA.12 及 PS 管线计划仅扩展方法、反馈和执行来源，不另起目标/计划模型。

### 5.2 MOOS 数据与调用边界

MOOS 已有 HTTP 代码和 generation/资产控制，本轮静态调查未证明运行状态/覆盖。首发 stdio MCP 只读，经受控本机 HTTP 访问 MOOS，不关闭 loopback/同源门槛，不读取数据库凭据或绕过 API 扫未入库目录。远程服务需 UA.13 的身份/权限验收。

默认八工具：moos_status、moos_search、moos_get_experiment、moos_get_evidence、moos_compare_observations、moos_search_assets、moos_read_asset、moos_get_simulation。图片/模拟声明/原始资产分别取证；初版不暴露采购、审核、索引重建或模拟执行。

材料获取顺序为用户指定项目输入→MOOS MCP→有权限的外部补充。获取回执区分无匹配、缺条件、拒绝、失联、旧版本与 metadata_only；用户只允许 MOOS 时不得静默改源。数据源凭据、签名 URL 留在 vault/宿主，原文/资产外发依项目授权与权利，不把 MOOS 全库送入上下文。

数值查询在数据库内按索引过滤/分页；先返回候选摘要，再按需读详情和证据。缓存键含连接/授权/合同/源版本，权限撤销后不得继续利用缓存访问；来源更新产生新分析版本，不覆盖历史。详细字段、资产与故障合同见 [MOOS 附件](local-agent/MOOS_MCP_SERVICE_PLAN.md)。

### 5.3 模型连接与引擎兼容合同

逻辑合同暂定 ModelConnection、EngineSelection、CompatibilityProfile、EngineSessionRef，统一定义在 `packages/contracts/src/`，复用已有模型配置、TaskRef、PermissionGrant 和 WorkspaceStore，不为每个引擎新建配置/状态数据库。

| 合同 | 必需内容与边界 |
| --- | --- |
| ModelConnection | local/platform 来源、受控 endpoint/provider 引用、真实 modelId/版本、协议、加载上下文与输出上限、reasoning/tool/image 能力、凭据引用；不存公开明文密钥 |
| EngineSelection | pi/codex、引擎版本、兼容配置引用、选择来源（用户或已配置默认）、任务所需能力；与 modelId 独立 |
| CompatibilityProfile | 引擎/模型服务/模型/协议/OS 组合、testedAt、验证集版本、可用/受限/不支持/未验证、原因及回执；不把同一家族全部模型视为通过 |
| EngineSessionRef | account/project/conversation、engineKind、独立原生 session/thread 引用、modelConnectionRef、task/attempt 和迁移版本；隔离不同引擎及账户 |

**本地 Codex 接入路径。** 先探测固定 App Server 接受的 provider/wire 协议与 LM Studio 实际端点。模型服务满足原生协议时使用直接传输；需要协议转换时，在宿主受控 loopback adapter 中将本机可用的 Chat Completions/Responses 映射到固定版本需要的请求与事件。两者择一，不让一次生成同时走两条路径。适配器仅负责传输、字段和事件转换，不执行工具、不生成第二套计划、不伪造 reasoning、工具结果或 usage。

不能把“兼容 OpenAI API”或 `/models` 可读等同于 Codex 可用。至少实测流式文本、完整工具参数与 ID、工具结果回传、多轮执行、停止、上下文/输出边界、错误与空响应处理、真实磁盘产物。Codex 的原生工具声明与 function/custom tool 格式按固定版本核实；若需映射，覆盖实际格式并拒绝不支持结构，不以简单问答通过宣布多步 Agent 通过。

本地路径不得经过 M5 云网关、扣云积分或静默上传研究数据；计算资源费用另按已有合同。工具桥与模型端点使用精确地址/端口范围和短期凭据，外层沙箱继续禁止未经授权的外部访问；loopback 代理不成为开放转发器。非 loopback 模型服务不因标为 local 自动可信，另行验证端点范围、认证、TLS 和数据外发授权。取消需要终止本轮模型请求与归属工具，无法证明终止时记录 unknown 并先查询，不立即重复提交。

能力状态在模型或服务版本、协议、引擎版本、OS 或上下文配置变化后重新检查；初次连接与关键变化使用最小无副作用探针，较完整保留集由验收任务执行，不在每次聊天前重复大测试。未知 usage 保留 unknown，本地 Token 用于性能观察但不是 M5 收费凭据。云端路径继续使用唯一 M5 账本，协议转换不得重复计量。

目标组合：本地+Pi、本地+Codex、云端+Pi、云端+Codex。只有通过对应验收的组合才提供“可用”选择，其他组合显示具体限制与诊断入口；模型推理能力和科研任务完成率另外评测。

M5 用量/积分仍是服务端账本真相。MOOS 只读不触发隐藏生成费；读取/下载回执和模型/计算计量分别关联，不为同一 Token 两次收费。网络/生成/实验验收在有效预算与授权内，缺费用资料不伪报成本。

## 9. 迁移、清理和每阶段交付

现工作区已有大量修改和未跟踪文件；Git 的 dirty 状态不自动等于代码质量差，也不能通过 reset/clean 清理他人或历史工作。UA.0 保存范围基线；后续只整理本次拥有的改动，使用明确差异/补丁和必要隔离，未授权不自动提交或推送。

每阶段在 `docs/agent/ua-N.md` 记录：目标、复用/新增/替换位置、受影响旧调用、合同/兼容、权限/预算、验证命令和结果、真实回执、UI/双语说明、已知限制、回退、清理记录。该目录按阶段实际交付创建，不提前建全部空文件。阶段状态只回写本文件，STATUS/BACKLOG 链接摘要。

兼容记录必须有：旧接口、实际调用者、临时原因、迁移路径、删除条件、最迟清理阶段。切换前验证旧项目/会话/M5/M6；切换后新旧实现不得同时对同一任务产生副作用。导入执行历史不重复分析，M5 权益/账本不由迁移重算。

Definition of Done：

- [ ] 从真实 UI/引擎/工具到产物的相关纵向场景可运行，不仅测试 mock 成功。
- [ ] 合同/schema只有一个来源；引擎适配无复制业务规则，源数据与用户已有修改受保护。
- [ ] 相关类型检查、构建、针对性合同/故障/数值/恢复测试通过，未解决失败记录影响；不为低影响改动增无意义测试。
- [ ] 中英文、全局主题、长标题/窄窗/全屏、进度/取消/产物可用。
- [ ] 默认路径没有临时重复实现、未使用注册或到期兼容；清理有 diff 和回归证据。
- [ ] 产物/事实/科学状态真实，预算/费用/来源可核对，文档和能力矩阵与实现一致。
- [ ] 涉及研究任务时消费第 5.1 节同一合同，保留目标/约束/认知状态与修订证据；依赖、权限、真实回执和交付判据成立，简单任务无强制多余规划。
- [ ] 模型来源与引擎独立，任务只用一个工具循环；共享 Skills/MCP/科学后端及账本；兼容状态、真实身份、隔离和跨引擎交接与产品声明一致。

全量构建/M5/M6/双平台回归用于边界变化或发布，不要求每个文字/小 UI 修改重复下载全部模型。新增检查入口应复用项目既有 scripts 构建链，真实费用和外部数据测试显式划分，不能在普通 unit test 隐式付款或下载。
