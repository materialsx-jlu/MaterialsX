## 1. 目标与交付边界

让研究人员在 MaterialsX 中描述任务后，系统能使用适当工具完成分析，遇到可修正的错误时自动恢复，并用真实产物判断任务是否完成。同时减少不必要的长上下文处理，让等待过程清楚、停止操作可靠。

原有本地可靠性目标保留：**导入结构 → 判断任务适用性 → 选择合格势 → 真实计算 → 检查结果 → 呈现报告与 3D**。新增优先研究交付：**研究问题 → MOOS MCP 获取材料数据 → 读取条件与证据 → 真实分析 → 可编辑表格/图片/报告 → 保存研究状态**。缺少匹配数据时记录原因，再依授权补外部来源或等待输入。

完整执行目标是：**同一个 MaterialsX Agent 在接入经验证的 OpenAI API 模型后，具备可对照 Codex 的通用文件、代码、终端、检索、Skills、MCP、持续任务和自我纠错能力。** 科研发展目标进一步包括项目级记忆、证据质量、方法适用性、实验数据分析和真实反馈；在具体材料任务中的优势必须用领域测试与独立验证证明。

用户的“换成 OpenAI API 就达到 Codex 能力”落实为可测试要求：更换模型不需要换 UI、换项目、重新安装基础 Skills 或失去本地执行工具；在相同模型、输入、权限和资源条件下，用真实任务对照验收。不能把“API 返回正常”当成“已达到 Codex 能力”，也不能以未经验证的所有桌面功能完全等同作为宣传。

详细工具、基础 Skill 清单、公开复用来源和能力验收见 [Codex 能力基线与基础组件清单](local-agent/CODEX_CAPABILITY_BASELINE.md)，与本计划共同作为实施依据。

根据最新要求，产品架构优先采用 **Codex 公开本地 Agent 执行底座 + MaterialsX 材料流程 Skills + 默认论文检索工具**。任务理解由模型结合项目、指令和 Skills 完成；通用工具调用、终端、补丁与会话能力优先复用公开 Codex runtime。MaterialsX 重点建设领域工具、证据、运行资格、计量及产品界面，避免先完整重写另一套通用 coding agent。

“本地 Agent”是执行器、文件与工具在本机，模型推理可以使用 OpenAI API，也可以在验证兼容后使用本地模型。复用 runtime 不等于把强模型权重安装在本机，也不保证弱本地模型获得相同任务理解能力。

新增 [材料流程 Skills 与论文检索实施规范](local-agent/RESEARCH_SKILLS_AND_PAPER_SEARCH_PLAN.md)，定义默认 paper_search、arXiv 接入、材料全流程 Skill、模块边界与真实验收。

v4 的科研阶段、数据对象、科学判断与产品指标见 [科研 Agent 发展计划](local-agent/SCIENTIFIC_AGENT_DEVELOPMENT_PLAN.md)，MOOS 服务责任、MCP 工具、数据优先级与六类数据验收见 [MOOS MCP 服务计划](local-agent/MOOS_MCP_SERVICE_PLAN.md)。三份配套文件与本主计划共同作为实施依据，RA 不重复开发 LA、M5、M6 或 MOOS 数据层。

本计划改进 Agent 的执行与管理能力，不把“增加 Skills 数量”作为智能化验收指标，也不承诺小模型达到所有更强模型的推理能力。系统必须区分“能自动修复”“需要补充条件”“现有工具不支持”和“模型能力不足”。

实施原则：

- 优先复用固定版本的公开 Codex runtime；App Server/SDK 只是接入途径，先通过运行与支持状态验证，再决定稳定集成方式。
- OpenAI 模式采用 Codex-first 路线；已有 Pi 0.99.1 保留为 LM Studio 兼容及迁移回退路径。不直接删除现有 Pi/M6 能力，不把 Codex 对某本地模型的兼容性预先视为通过。
- LA.0 与 LA.15.A 先验证 Codex 可直接提供的基础工具；已可复用的终端/补丁/会话不再次实现同等完整引擎，领域桥接与 API 计量另行补齐。
- 工具、任务状态、基础 Skills、MCP 和产物验收由 MaterialsX 共用；本地与平台模型拥有同一套可授权的能力，按模型协议适配。
- 普通任务交给通用 Agent；材料流程以 Skills 编排，调用已验证文献、选势、计算和验收工具；稳定的确定性后端保留，不把已有真实执行链退回纯提示词。
- 用户明确的本项目实测/文件作为分析输入；新增实验、配方、工艺、模拟、图片、性能数据优先通过 MOOS MCP 获取，保留来源版本、条件、审核和权利。服务失联、无匹配、缺条件、拒绝访问分别处理，不伪造获取成功。
- MOOS 负责原始入库、复核、索引和资产；MaterialsX 负责项目目标、选定快照、分析、假设、决策和派生产物。首发只读，不绕过 MOOS API 直接查询私人数据库或扫描未入库目录。
- 权限与资源限制由后端执行，不依靠模型遵守提示词；现有授权在有效范围内持续生效。
- 优化应保留结果质量与证据。不能通过删掉关键输入、降低科学检查或隐藏失败来缩短耗时。
- 只把真实状态与结果展示给用户。运行成功、任务完成与科学精度通过分别记录。
- 本地模式可以离线使用；paper_search 是默认安装的研究工具，联网查询可关闭，离线使用已有缓存。平台模型无 BYOK，沿用 M5 平台网关。

本轮不新增机器学习势家族、不扩大物理任务范围、不自动修改 MaterialsX 安装程序，也不直接修改正式支付与退款策略。

### 1.1 版本范围与变更

从本地性能优化扩展为“通用 Agent 基础 + 材料研究能力”。新增 LA.11–LA.18：共用工具、默认基础 Skills、项目指令与任务协作、OpenAI 正式通道、Codex 引擎适配、受控子任务、浏览器/视觉及最终能力对照。LA.0–LA.10 保留原编号，方便逐阶段实施。

v3 将公开 Codex 底座复用从可选参考提高为优先技术路线，并新增 **LA.19 论文搜索与文献库、LA.20 材料流程 Skills**。新编号便于追踪，不代表必须到最后才开发；它们列入首个研究闭环，并在 LA.18 完整验收前完成。

v4 保留 LA.0–LA.20 的编号和执行基线，增加 RA.0–RA.11 科研路线及 MOOS 优先 MCP。RA.0–RA.4 的最小子集与 LA 穿插交付；原始实验数据、下一轮实验、论文方法包、跨天计算和团队协作分阶段建设，不把全部远期功能作为首个研究预览前置。

### 1.2 默认研究搜索边界

arXiv 优先作为材料计算、物理与机器学习相关预印本发现来源，使用官方 API，不以浏览器抓取结果页为主实现。arXiv 不覆盖全网全部材料期刊论文，平台本身不进行同行评审，因此产品不能宣称“最新最全”或将所有条目标为已同行评审。没有搜到论文表示当前来源/查询未找到，不表示该研究不存在。[arXiv 官方介绍](https://info.arxiv.org/about/index.html)

默认 paper_search 同时服务材料 Skills 与普通研究问答。检索、摘要筛选、下载、全文读取和证据抽取分别记录；只读摘要时不声称已阅读全文。期刊/DOI 元数据补充优先预留 Crossref，后续其他来源按真实 API 和许可接入，不因来源增加保证全文可取得。

### 1.3 MOOS 优先与科学边界

材料数据任务先使用项目明确输入，随后优先 MOOS MCP；论文发现先复用 MOOS 已有来源，搜索新论文或补覆盖时使用 arXiv 等外部适配。用户指定来源或要求只用 MOOS 时优先遵从。原始数据、来源报告、模拟预测和 Agent 假设保持独立身份。

MOOS 当前代码已有相关 HTTP 接口和实验 generation/证据/资产控制，但静态调查不等于服务已运行或数据齐备。RA.0 冻结可用接口、SDK/协议版本、同机权限与数据覆盖；RA.1 建只读 MCP；RA.2 接 MaterialsX。远程入口需要另行通过生产身份、数据隔离和资产权限，不能关闭现有 loopback/同源限制作为接入办法。

任务执行完成、证据可定位、科学适用与实验验证分别验收。没有足够条件时返回缺口，未实际测量的实验保持待输入；不通过多 Agent 一致意见、退出码或文件存在升级科学结论。

## 2. 诊断基线与证据限制

依据用户提供的 `2026-10-05.1.log`、对应本机会话记录及当前代码，观察到以下情况：

| 项目 | 观察结果 | 解释 |
| --- | --- | --- |
| 连续调用 | 5 次 `/v1/chat/completions` | 已开启 `stream: true` |
| 输入大小 | 38,512–39,393 Token | 会话用量记录；不是通过日志字符数估算 |
| 消息与工具 | 每轮 60–68 条消息、18 个工具定义 | 长历史及工具定义进入请求 |
| 输入处理耗时 | 每轮约 68–71 秒，共约 349 秒 | LM Studio 日志的 prompt processing 阶段 |
| 后续耗时 | 每轮约 3–7 秒，共约 23 秒 | 包含生成及请求结束，不等同于精确解码耗时 |
| 总耗时 | 约 372 秒，输入处理约占 94% | 当前首要瓶颈是输入处理和无效多轮调用 |
| 参数错误 | `mode=local/platform`、`interaction=none` | 不符合当前科学工具合同 |
| 未注册工具 | 模型尝试调用 `search_file` | 实际有 `find/grep/read` 等工具 |
| 状态引用 | 部分历史把结构 ID 当评估 ID | 工具链需要真实状态和身份衔接 |

诊断时本机：Apple M4 Pro、48 GiB 内存；LM Studio 0.4.25+1；已加载 `openai/gpt-oss-20b`，MLX/MXFP4，权重约 12.1 GB；加载上下文 131,072，配置中 `parallel=4`。这只是当前机器的测试基线，不代表所有用户配置。

必须保留以下限制：

- 这段日志没有证明每轮都在重新加载权重，也没有证明缓存被关闭。
- 会话中的 `cacheRead=0` 可能源于服务端没有提供对应统计，不能直接当作缓存未命中证据。
- 128K 上下文与并行配置值得评估，但不能假定所有窗口均已预分配，也不能预先承诺降低窗口会提速多少。
- 当前服务声明推理默认值为 low；不能把慢归因于已经启用了高推理强度。
- 当前请求的 16,384 是输出上限，不是输入上限。降低它主要约束输出，不直接消除输入处理耗时。
- 单份失败记录不能代表整体成功率。LA.0 必须建立标准测试集后再比较。

原始日志和私人会话只留在本机。公开仓库保存脱敏统计与人工构造的复现样例，不提交 API Key、论文全文、私有结构或本机完整路径。

优先修改点：

- `packages/pi-adapter/src/local-session.ts`：会话创建、模型限制、工具注册、事件订阅与取消。
- `packages/pi-adapter/src/science-bridge.ts`、`atomistic-tools.ts`：科学工具合同与真实 ID 衔接。

- `packages/pi-adapter/src/platform-session.ts`：平台升级与终态/用量核对。
- `packages/contracts/src/desktop.ts` 及新增合同：任务、进度、错误、完成检查与能力描述。
- `apps/desktop/main/index.ts`、`preload/index.ts`、`renderer/src/stores/workspace.ts`：IPC、状态持久化与展示。

以上是代码范围，不是要求将全部功能继续堆入 `local-session.ts`。新增能力按上下文、监督、执行、能力适配与验收模块拆分。

## 4. 目标架构

```text
用户消息 + 当前项目/结构 + 已有授权
                   ↓
项目指令 + 基础/材料 Skills + 任务状态 + 完成条件
                   ↓
上下文构建：固定提示 + 相关工具 + 任务摘要 + 近期有效消息
                   ↓
AgentEngine：Codex 公开 runtime 优先 / Pi 本地兼容与回退
                   ↓
模型适配：本地 LM Studio / M5 管理的 OpenAI 或经验证中转
                   ↓
引擎工具循环与会话 ← MaterialsX 任务监督、预算与结果验收
                   ↓
复用 Codex 基础工具 + 领域 MCP：MOOS 优先材料数据、paper_search、科学计算
                   ↓
材料流程 Skills + 研究项目状态：检索、证据、分析、候选、真实反馈与报告
                   ↓
真实结果检查：文件身份、数值、工作流终态、科学适用性
                   ↓
聊天正文 + 过程卡片 + 文件/3D 产物 + 运行回执
```

新增组件建议：

| 组件 | 职责 |
| --- | --- |
| `AgentTaskStore` | 保存任务目标、约束、版本化状态、产物引用与恢复记录 |
| `ContextBudgetManager` | 请求前计算预算、检索历史、生成摘要、保护工具消息配对 |
| `ToolRegistry` | 按任务启用工具、维护版本化 schema 与权限元数据 |
| `TaskSupervisor` | 按错误与进展判断下一步，不重复执行 Pi 自身循环 |
| `ExecutionManager` | 执行回执、超时、取消、幂等、进程隔离和恢复查询 |
| `CompletionValidator` | 不同任务类型的完成条件检查 |
| `LocalProviderAdapter` | Chat Completions/Responses 与能力差异处理 |
| `AgentEventBus` | 带任务身份和序号的进度事件，关联 UI 和诊断记录 |
| `AgentEngine` | 统一 run/steer/cancel/resume 与能力声明，不暴露引擎私有状态为通用合同 |
| `InstructionResolver` | 系统、用户、项目与目录指令的作用域、来源与更新 |
| `SkillPackManager` | 固定来源、依赖映射、双语例子、审核、默认分发与更新 |
| `WorkspaceToolHost` | 同一套本地执行与文件工具供所有获授权模型/引擎调用 |
| `McpManager` | 本机/远程 MCP 的发现、认证、健康、工具索引和权限 |
| `ResearchService` | paper_search、论文身份/版本、缓存、筛选、下载/阅读与文献导出 |
| `MaterialsWorkflowSkills` | 全流程入口和专项流程，按任务选择工具并维护阶段证据 |
| `MoosMcpConnector` | 经 McpManager 访问 MOOS 的白名单只读工具，绑定身份、权限、版本和获取回执 |
| `DataSourceRouter` | 项目输入、MOOS、外部来源的选择与有理由回退；不重建数据检索引擎 |
| `ResearchProjectStore` | 样品/批次/条件、证据快照、分析依赖、假设、实验反馈和决策；复用现有持久层 |
| `ScientificQualityValidator` | 条件可比性、单位、证据、适用域和验证层级；与 CompletionValidator 分工 |
| `MethodRegistry / DatasetBuilder` | 固定方法资格及可运行范围，生成有来源/条件/版本的小型分析数据集 |

Codex 已有基础工具由其 runtime 执行，MaterialsX 通过公开事件、工作区/沙箱配置、MCP 和回执关联管理；不要将同一个 Codex 命令再交 WorkspaceToolHost 执行一次。Pi 路线调用 MaterialsX 执行器，两条路线共用授权语义、领域后端与产物格式，不要求内部执行代码完全相同。

最小任务状态包含：`taskId/projectId/conversationId`、目标、输入及 SHA/版本、任务类型、已授予权限引用、预算、计划步骤、真实 structure/assessment/job ID、已验证产物、未解决问题、尝试记录、终态原因、模型与协议版本。不能把所有状态压成一段不受校验的自然语言总结。

终态：`completed / completed_with_limitations / blocked / failed / cancelled`；非终态可用 `planning / running / recovering / verifying / waiting_for_input`。科学结果的 `needs_review` 是独立质量字段，不能被任务 completed 覆盖。

## 5. 指标、默认预算与测试口径

### 5.1 指标定义

- 首个界面反馈：提交到显示真实任务状态的时间。
- 首个模型输出：请求提交到首个文本或工具调用输出；没有正文的工具轮也应记录。
- TTFT：按服务端可取得的定义单独保存；不可取得时只报客户端观测值。
- 输入处理、生成、工具、压缩、下载、排队耗时分别记录，不能全部统称“模型慢”。
- 任务成功率以完成检查通过为准；合理拒绝不适用的科学任务属于正确处置，但不混入可执行任务成功率。
- 重复失败以工具名、归一化参数和错误代码的指纹统计；区分同名工具的有效新调用。
- 缓存统计记录 `reported/unavailable/inferred`；缺失值用 unknown，不填成实测零。

### 5.2 首轮性能目标

以下是发布目标，必须用实测验证；没有达到就记录阻碍，不能改报告数字。

| 项目 | 首轮验收目标 |
| --- | --- |
| 界面反馈 | 本机 P95 ≤500ms，展示提交/排队状态，不伪造模型输出 |
| 普通交互输入 | 常规目标 8K–12K；原子多步任务一般 ≤16K，必要时按明确预算扩展 |
| 长历史任务 | 关键约束保留，输入 Token 相对等价旧流程降低 ≥50% |
| 暖模型首个输出 | 标准任务集 P50 相对基线降低 ≥40%，P95 不退化超过 10% |
| 参数错误 | 有效工具调用率 ≥95%；可修正错误最多两次纠错后修复或清楚终止 |
| 重复失败 | 同一步同类无进展失败不超过两次，不继续无限请求 |
| 任务完成 | 首批 30 个可执行案例至少 27 个通过；另列拒绝/不支持案例 |
| 假结果 | 故障注入中“无产物却声明完成”拦截率 100% |
| 取消 | UI P95 ≤500ms 确认正在停止；受管本地进程通常 ≤5s 停止，超时明确显示 |
| 渲染 | 目标机器长文本流无超过 200ms 的持续主线程阻塞；用追踪记录验收 |

32K 加载窗口作为基线对照配置，不能替用户强制重载模型。先对长历史摘要再测试；输入预算满足：

```text
effective_input_limit = min(
  task_input_limit,
  loaded_context_limit - output_reserve - safety_margin
)
```

建议初始输出 4K，长报告 8K；安全余量至少 2K，并按模板和服务端行为校正。工具 schema、消息封装、Skill 说明和工具返回均计入输入。Token 估算不准时保守收缩，服务端实测 usage 用于校准。

不得把 128K 模型容量当成每轮交互预算，也不得把 keepRecentTokens 固定绑定最大输出额度。

### 5.3 初始任务预算

本地轻量交互默认最多 8 次模型请求、20 次工具调用、同一步两次纠错、10 分钟交互预算；全部可配置并记录来源。摘要、重规划与能力探针中的生成调用也计入模型预算。

通用复杂任务另设长任务配置：初始最多 32 次模型请求、120 次工具调用、30 分钟交互预算，结合用户已授予的平台额度与任务目标调整。不能用轻量配置的 8 次请求强行限制多文件修复等合理任务，也不能以“对标 Codex”为由无限增加费用。达到预算保存可继续的状态，授权续跑后不重复已完成步骤。无进展的相同错误仍最多两次纠错；不同有效步骤不算重复失败。

文献批处理和科学长任务使用专门预算，计算进程沿用现有原子数、步数、内存、下载与墙钟限制。交互超时不等于计算已停止；先查询真实任务状态再决定继续、停止或等待。

## 9. LA.2：错误恢复与任务监督

### 实施清单

- [ ] 将任务目标、当前步骤、尝试、最后有效状态与完成条件写入受校验状态。
- [ ] 分类：参数错误、未知工具、失效状态、暂时网络错误、模型输出格式错误、缺依赖、资源不足、权限不足、科学不适用、任务执行失败、结果缺失。
- [ ] 参数错误提供短反馈并最多两次纠错；失效状态先重新查询，不能猜 ID。
- [ ] 暂时错误只在可重试且幂等时有界退避；取消、权限拒绝、科学不适用不进入同样的重试循环。
- [ ] 检测同类错误及“多次目录/ls/find 调用却无新证据”；先改变工具或计划，再选择升级或明确终止。
- [ ] 每次纠错只带任务摘要、必要状态和相关错误，避免重新注入整份日志。
- [ ] 达到预算时保存恢复点和失败原因；最终说明卡在哪里、已完成什么、需要什么条件。

任务监督不能吞掉引擎工具结果、调用配对或正常终态。Codex 路线优先利用自身循环与公开事件，MaterialsX 补预算和领域验收；Pi 路线通过已有扩展点接入。没有公开控制点时不得假装能逐调用拦截，先明确由引擎沙箱、领域 MCP 或外层任务预算分别执行哪些检查。

### 验收

注入相同非法 mode、未知工具、陈旧 assessment ID、网络超时及不合格势。可恢复案例完成；不能恢复的案例有真实原因和状态，且在预算内停止。普通问答不强制先生成冗长计划；同一错误纠错不超过两次。

不向用户展示原始隐藏推理，也不默认持久化它；展示实际执行动作和结果即可。取消后迟到事件不能将终态改回 running，也不能继续拼接到其他任务正文。

### 验收

短文本、长 Markdown、公式、工具密集调用、3D 产物与取消均测试。1280px 与全屏、现有全部主题无溢出。断流和错误分别有可理解的提示；重复事件去重，乱序终态不倒退。

## 12. LA.5：受管执行、幂等与重启恢复

### 实施清单

- [ ] 为命令和工作流保存输入身份、受管 cwd、环境身份、执行键、进程/任务 ID、日志文件、开始/结束时间及退出码。
- [ ] 使用项目允许目录与受管 Python/原子环境；模型传入的路径做规范化与越界检查，必要项目外输入按现有授权处理。
- [ ] 常规文件读取、项目内写入和非破坏性命令沿用授权，不每一步弹确认；删除、安装、外部传输等按实际动作和既有授权检查。
- [ ] 设置 stdout/stderr 上限并落盘，输出截断可继续查询；执行在独立受管进程中，避免堵塞 Electron 主进程。
- [ ] 相同输入与配置生成执行身份；状态不明先查询，不再启动第二个任务。
- [ ] 有副作用的执行进入 intent → running → receipt/unknown 流程；超时或崩溃后的 unknown 必须核对。
- [ ] 停止进程树并核实退出，清理只覆盖本任务临时内容；完成产物、结构与共享环境保留。
- [ ] 重启后核对存活进程、已有科学 job 与产物身份；明确哪些支持续跑、哪些需重启计算，不能假装续算。

数据库/schema 迁移版本化。持久化敏感路径与环境信息遵循本地存储策略，日志不记录认证头。文件写入采用临时文件与原子提交，关键产物已有版本时保留旧版本。

### 验收

执行前、启动后未记回执、产物写入中与完成后分别模拟崩溃。恢复不重复计算，不误删共享环境，不将部分文件验为完成。Windows/macOS 分别测试进程树停止；无法保证停止的进程明确标记待核对。

## 13. LA.6：真实产物与科学完成检查

### 实施清单

- [ ] CompletionValidator 按任务类型注册，输入冻结的完成条件与真实执行回执。
- [ ] 文件任务检查输出存在、非空、格式合法、属于本次输入与执行，并保存大小、SHA 和 schema 版本。
- [ ] RPSME 复用原文证据、真实 JSON、中文摘要与校验报告检查，不放宽既有反模拟执行保护。
- [ ] 原子分析检查结构身份、checkpoint/head/环境、资格、任务终态、有限数值、单位及真实文件；3D 引用对应实际结构。

- [ ] 报告明确作者声明、本机工程验证、独立科学验证的区别；保留 needs_review。

- [ ] 修复在独立环境副本测试，再检查文件身份与运行探针；不直接改全局 Python 或共享生产环境。

- [ ] 项目脚本修复生成可查看差异，在授权范围内运行相关测试；修改应用核心源码和正式发布另走开发流程。

依赖安装受来源、版本锁、许可、下载预算与已有安装授权约束。没有搜索服务时明确不可用，继续离线方法；不把缺搜索凭据当作所有本地任务失败。

### 验收

用冻结网页/文档 fixtures 验证引用、注入指令、恶意 URL、超长内容、未知依赖及修复失败。联网实测单独记录，网络与外部服务故障不能使核心离线回归不稳定。

固定 Atom fixtures 覆盖查询、缺字段、版本、重复、空结果、限流、超时与缓存；受限联网验收核对真实 arXiv ID 和 API 返回，完整任务核对 PDF SHA、页码与导出文件。最新结果显示查询时间和缓存日期，不承诺未发布/未收录论文可被发现。正式详细合同、限速与指标见 [LA.19 规范](local-agent/RESEARCH_SKILLS_AND_PAPER_SEARCH_PLAN.md)。

## 31. LA.20：材料全流程入口与专项 Skills

### 实施清单

- [ ] 默认提供 materials-research-workflow 入口 Skill，按目标建立阶段计划、调用专项 Skills/工具并维护研究状态。
- [ ] 提供 paper-search-review、evidence-extraction、data-analysis、simulation-analysis、candidate-design、experiment-planning、research-validation-report 等功能模块；已有 Skill 先复用，具体 ID 在验收时冻结。
- [ ] 从研究问题、目标性能、已知材料/条件、真实数据和可用工具出发，不强行把所有材料任务套入一种流程。
- [ ] 材料数据任务优先 MOOS MCP，用户项目实测/指定输入保持优先；获取回执区分无匹配、缺条件、拒绝、失联、旧版本及只含元数据。配方/工艺/性能保留父实验、条件与来源。
- [ ] 研究状态接入 RA.3 对象与快照；科学检查调用 RA.4/既有 M6，后续原始数据/方法/实验反馈逐阶段启用，不只增加提示词。
- [ ] 原始事实、论文结论、模型计算、推断/候选、实验建议分别标记；每个重要结论有真实引用或明确未知。
- [ ] 跨阶段输入输出采用受校验数据与文件引用；LLM 的计划和中间产物经过相关验证，不以文字声称代替文件。
- [ ] 只有满足现有资格、结构与授权时调用材料计算，缺宏观/实验工具时记录限制；不把完整流程 Skill 当成已实现全部尺度预测。
- [ ] 实验阶段输出可审核计划和待填写记录，实际测量数据由真实输入或已接入设备取得，不能生成假实验。
- [ ] 每项默认 Skill 提供中英文说明、1–2 个双语例子、依赖与可运行范围；页面样式/主题沿用当前 Skills。

LA.20.A 在基础 Skill 和最小研究工具可用后，分别支持 MOOS 数据分析入口（RA.2.A/RA.3.A）和论文筛选入口（LA.19.A）；不以两种来源必须同时上线作为单一路径的前置。真实分析仍需 LA.6 对应验收。LA.20.B 随 LA.6/LA.19.B 与 RA 子集补证据、真实分析、科学检查及阶段恢复。

### 验收

至少覆盖晶体选势、文献实验抽取、已有实验数据分析及暂无宏观工具的材料研发计划。系统能够自动执行支持的步骤，对必须等待真实输入的步骤保留状态；既不把整项任务推回人工执行，也不捏造缺失步骤。研究方法与科学验证另行评估；M7 的统一多尺度研发研究不会因新增入口 Skill 自动恢复为已实施。

## 32. RA 科研发展路线与首发边界

RA.0–RA.2 交付 MOOS 调查、只读 MCP 和优先获取；RA.3–RA.4 建研究项目/样品/条件/版本与证据科学检查；RA.5–RA.6 补原始实验数据与方法选择；RA.7–RA.10 推进真实反馈/下一轮实验、论文方法包、跨天计算及团队服务；RA.11 独立产品与科学验收。

完整依赖、实施清单、候选工量与验收以 [科研 Agent 发展计划](local-agent/SCIENTIFIC_AGENT_DEVELOPMENT_PLAN.md) 为准。首发围绕证据表、实验报告、结构计算三个高频场景，先交付相应子集；远期不阻塞首个可用版本。

所有新增页面沿用 Skills/模型目录的样式和全局配色，支持中英文、长标题、全屏/窄窗及例子复制。方法/数据“目录收录、内容可读、可运行、参考复现、领域验证”分别展示；不在用户页面用阶段编号和宣传性措辞代替实际状态。

研发验收增加引用/数值正确性、条件可比性、适用域、可复现性、人工修改与到可用产物耗时；不以 Skill 数量、推理字数或自主执行时长判断研究价值。LA.18 的通用对照和 RA.11 的材料验证各自报告，领域优势不扩大为所有科研能力已超越 Codex。
