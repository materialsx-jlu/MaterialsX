# 本地 RPSME 分阶段抽取

使用 `@materials-literature-rpsme-json 提取 /绝对路径/paper.pdf，输出带证据的 RPSME JSON、中文摘要和校验报告。` 启动。当前受管流程面向单篇主文 PDF 的文本证据，使用设置中已选择的本地模型。不会自行下载模型。

## 本次修复

此前自由 Agent 会把脚本命令写错、重复查找文件，或者在完成预处理后自行结束。仅将缺失文件判定为调用失败，并不能保证它继续执行。现在应用负责固定脚本路径、逐页读取、落盘、重试和校验；模型每次只处理一页或一个受限文本块。抽取调用不注入全部 84 项 Skill 的描述或不断增长的工具历史。

Pi 继续使用 LM Studio 的 OpenAI 兼容 `POST /v1/chat/completions`，请求 `stream:true`。原生 `/api/v1/chat` 的进度事件不会自动补齐脚本依赖和科学数据。GPT-OSS 使用正常推理后输出 JSON；没有对该 MLX 后端强制施加导致空事实结果的 JSON grammar。

PDF 原生文本按完整文本块保留，避免双栏同高度的文字串成一行。证据检查只允许空白和跨行单词断字的布局差异，并恢复源文件的精确引文；不合并化学连字符，不删除负号，不更改单位、大小写或数值。唯一定位失败的候选事实会重试或保留为缺项。

## 产物与恢复

每次运行在项目的 `materials-output/rpsme-时间-随机标识/` 保存：

- 分页事实、原始模型文本输出及耗时/用量、运行状态；不保存模型的推理正文。
- RPSME JSON、中文证据摘要、结构检查、完整验证报告、源文质量审计和待完成审核记录。
- 已核验分页事实另存于 `materials-output/.rpsme-cache/`，缓存绑定流程版本、模型 ID、源文件哈希及分页文本哈希。同模型重试同一份文件可以复用；损坏的缓存会重新计算。

支持停止生成；已写入的页面保留。再次发送原始提取指令即可重试。脚本失败、推理失败和待复核状态分别保留，不用“模型说已经完成”作为交付证据。

## 质量边界

当前自动编译生成证据草稿，保留样品、原料、过程、性能、结构、机制及其他源文事实。跨页样品别名、配方继承、完整材料流、结构化比例、模拟领域实体、化学身份及图表视觉证据仍需要进一步核对。文本模型不能独立审阅图像；未提供的 SI 不能被视为已经读取。

摘要明确显示格式、覆盖率和抽取质量各自的结果。审核模板始终从 pending 开始；引文匹配不等于科学正确，更不等于专家批准。质量未通过时交付“待复核草稿”和真实未通过项，不能将其作为完整已验收的 RPSME 数据导入生产库。

`npm run check`、`npm test` 包含逐字证据、数值正负号、跨行断字、自动修复、取消、长页切分、部分事实保留，以及真实 Python 预处理/完整校验/三份文件落盘的集成测试。

真实模型复现：

```bash
node --import tsx scripts/rpsme-workflow-probe.ts /绝对路径/paper.pdf openai/gpt-oss-20b
```
