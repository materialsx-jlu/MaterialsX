# MaterialsX 0.3 全流程架构与官网介绍口径

更新：2026-10-07。本文是 0.3 的产品与工程架构说明；官网的对应章节位于「0.3 架构」。运行状态以登录后的服务端目录和发布记录为准，预览验证不能写作正式公开发行。

## 一句话边界

MaterialsX 桌面端是材料研究和 MX 点购买入口；MaterialsX Go 账户网关是身份、支付、钱包、计价和用量的唯一业务事实源；独立 LiteLLM 负责上游模型协议与路由；独立计费 Web 供具名运营人员查询和审批；官方网站负责公开介绍与下载。

## 系统图

```mermaid
flowchart LR
  U[用户] --> W[官方网站<br/>静态介绍与下载]
  U --> D[MaterialsX 桌面端<br/>项目 / Skills / MOOS / 钱包]
  D -->|认证、商品、订单、模型任务| G[Go 账户与计费网关]
  P[微信支付] -->|验签通知 / 查单 / 退款结果| G
  G <--> B[(MaterialsX PostgreSQL<br/>身份 / MX 账本 / 价格版本 / 审计)]
  A[独立计费 Web] -->|同源代理到私有管理 API| G
  O[/ops 模型采购与路由控制] --> G
  G -->|受控模型请求 / 请求 ID| L[独立 LiteLLM Proxy]
  L <--> LB[(LiteLLM 专用 PostgreSQL)]
  LA[LiteLLM Admin UI<br/>授权运维] --> L
  L -->|服务端 API Key| S[RootFlowAI 供应商]
  S -->|模型输出 / 用量 / 独立消费账单| L
  L -->|响应与用量| G
  S -.->|人工或受控导入账单证据| G
  G -->|研究响应 / 钱包与任务明细| D
```

实线是应用调用；虚线是供应商账单核对，不是用户请求路径。官网不参与支付或模型请求。计费 Web 和 LiteLLM 管理界面是运营系统，不是用户须另外打开的购买页面。`/ops` 管路由和供应商探针；计费 Web 管用户资金、退款、价目与对账；LiteLLM Admin UI 只管代理运行，不是 MX 余额或销售价的编辑器。

## 六个交付边界

| 单元 | 用户可见职责 | 服务端职责 / 数据边界 | 部署边界 |
| --- | --- | --- | --- |
| 官网 `website/` | 介绍研究能力、0.3 状态、价格机制与下载 | 静态文件；不存账号、支付凭据或上游 Key | 独立静态发布，可单独回滚 |
| 桌面 `apps/desktop/` | 本地项目、论文/实验文件、Skills、MOOS MCP、模型选择、MX 充值与明细 | 只读服务端商品和价格目录；提交商品 ID 与任务；本地模型走本机接口 | macOS/Windows 安装包与服务端分别发行 |
| Go 账户与计费网关 `services/control-plane/` | 认证后提供钱包、订单、可用模型、请求与回执 | 微信通知验签、幂等到账/退款、MX 账本、价格版本锁定、预留/结算/待核对、审计和管理 API | 独立进程和 MaterialsX 业务 PostgreSQL |
| 计费 Web `apps/billing-admin/` + `services/billing-admin/` | 具名员工角色界面：总览、用户、订单、用量、退款、价目、对账、报表、审计 | 同源 `/api` 代理固定 Go 私有接口；不直接读写数据库 | 独立主机名、构建产物、进程、健康检查与回滚 |
| LiteLLM `services/litellm/` | 无直接用户入口；Admin UI 只供授权运维 | 协议适配、模型别名、供应商路由及代理日志；供应商密钥仅服务端可读 | 独立 Python 进程、配置、专用 PostgreSQL、私网监听与回滚 |
| RootFlowAI 供应商 | 不向 MaterialsX 用户暴露登录 | 提供三条已采购路线和独立消费账单；每路独立密钥与精确模型 ID | 第三方服务；由 LiteLLM 私网出站调用 |

MOOS MCP 是另一条独立、只读的研究数据链路，不参与 MX 点收款或 LiteLLM 的模型采购；其连接状态在桌面「数据与 MCP」中展示。

## 用户从充值到任务的完整流程

1. **登录和展示**：桌面使用 MaterialsX 账户登录；Go 返回服务端准入的模型目录、四档 MX 商品、钱包余额和当前零售价格。余额大于零只是必要条件，模型路由还须独立准入。客户端不计算最终金额，也不凭本地配置开放模型。
2. **建单与支付**：用户选择 ¥10、¥50、¥100 或 ¥500。Go 固定订单金额与对应的 100、500、1000、5000 MX 点；客户端只送商品版本和幂等键。微信 Native 下单后，Go 验签、解密并复核金额、商户与交易状态，同一付款仅发一次点数。未知支付状态先查单。
3. **任务准入与锁价**：用户选择可用模型并提出研究问题。Go 校验账户、销售开关、模型能力、路由状态和钱包；在同一事务记录请求 ID、模型/路由版本及采购价、额度汇率、零售价快照，并预留可覆盖请求上界的 MX 点。
4. **模型调用**：Go 通过私网把受控请求发给 LiteLLM；LiteLLM 使用该模型的服务端 API Key 和供应商协议调用 RootFlowAI。输出回到桌面研究任务，项目、来源和工具回执继续留在研究工作台。已派发而终态未知的请求不盲目重发。
5. **计量和结算**：以普通输入、输出、缓存读取、缓存创建四类互不重叠的可信 Token 数计价。可信终态按请求开始时锁定的价目扣点并解除剩余预留；缺失或冲突的类别进入 `reconciliation_pending`，保留预留并等待证据，不把未知量填零或记免费。未派发的失败请求可释放预留。
6. **采购和利润核对**：记录按采购价与已锁定汇率算出的成本估计，再用 RootFlowAI 独立消费日志核实供应商实际扣费。计费管理端分开呈现现金实收/退款、未消费点数余额、已消费点数对应收入、采购估算/实际成本、差异与可计算毛利。供应商账单不会反向改写用户已锁定零售价。
7. **退款和审计**：首版仅支持整笔点数完全未使用且未预留的原路全额退款。申请先冻结该批点数；具名财务人员审批后，由 Worker 发起退款并以渠道最终成功为准。订单、支付、结算、对账及角色操作都有可追溯 ID 和幂等记录。

## MX 点与三模型计价

统一兑换关系：`¥1 = 10 MX 点`。内部以 `1 MX 点 = 1,000,000 子单位` 整数记账。RootFlowAI 站内额度按当前已核定业务口径 `1 额度 = ¥1` 估算采购成本；这是站内额度到人民币的结算假设，不是美元兑人民币汇率。官网所说“约官方价格五折”只把 2026-10-07 的官方美元参考价按估算 `1 USD ≈ ¥7` 折算后作历史对比，不承诺实时官方折扣。

下表为每百万对应类别 Token 的当前审核零售价快照，顺序为普通输入 / 输出 / 缓存读取 / 缓存创建。采购价为供应商站内额度；官网只展示零售价和机制，采购价与毛利留在内部账务系统。

| 模型与档位 | 采购价（额度） | 零售价（MX 点） | 当前准入 |
| --- | --- | --- | --- |
| `gpt-5.6-sol` 标准，输入上下文 <272k | 1.25 / 7.5 / 0.125 / 1.5625 | 175 / 1050 / 17.5 / 218.75 | 本机受限开放，已完成一笔独立账单核对 |
| `gpt-5.6-sol` 长上下文，输入上下文 ≥272k | 2.5 / 11.25 / 0.25 / 3.125 | 350 / 1575 / 35 / 437.5 | 同上；按整次请求长上下文档定价 |
| `claude-opus-5-5` | 2.4 / 12 / 0.12 / 3 | 140 / 700 / 7 / 175 | 本机受限开放，尚待同等级实付与供应商账单核对 |
| `claude-fable-5-1` | 6 / 30 / 0.15 / 7.5 | 350 / 1750 / 8.75 / 437.5 | 已审核价目，暂停新收费调用 |

`gpt-6-sol` 经供应商精确 ID 与协议复测失败，已从活跃路由、商品、价目和运行密钥移除；不得继续在官网呈现为可买模型。各类别互斥计数，缓存读取不能再算作普通输入。模型层毛利公式为 `已消费 MX 点 ÷ 10 − 供应商实际人民币成本`；模型层毛利率为该毛利除以已消费收入。支付手续费、税、基础设施与退款等未扣除，因此毛利不是净利润。未收到独立供应商账单前，只能显示估计成本和待核状态。

## 供应商 API Key 与发布控制

- 每条供应商路线使用独立 Key。私有 `runtime/litellm/secrets.env` 和生产环境的专属密钥管理服务只由 LiteLLM 服务账户读取；仓库、官网、桌面安装包、计费 Web、日志和导出均不含 Key 原文。`/ops` 可显示密钥引用或掩码与轮换时间，不回传密钥。
- 桌面只能调用 Go 的受控目录和网关。Go 使用受限的 LiteLLM 代理凭据；它不把供应商 Key 下发给桌面，也不接受客户端给出的任意 Base URL。
- 管理员先核实供应商真实模型 ID、协议、探针、计费倍率与账单，再发布不可变“路由 + 采购价 + 汇率 + 零售价”联合版本。部署 LiteLLM 并确认健康后，Go 才可激活对应价格；请求使用启动时锁定的版本。异常时回滚新路由，不重写旧账单。
- 计费 Web 管销售价审批与财务，`/ops` 管供应商和部署，LiteLLM Admin UI 管代理内部状态；任何一个管理界面都不能单独绕过 Go 的钱包与定价事务。

## 故障、隔离和发行状态

计费 Web 停止时，桌面已准入任务及 Go 支付回调仍可独立运行；LiteLLM 停止时，不再接受可收费模型调用，但历史账本仍可查询；Go 停止时，计费 Web 应明确报服务不可用，不能显示伪造余额。支付和供应商的未知结果均采用查询/对账恢复，不自动重复扣款或重发未知终态模型请求。三服务分别部署、监控、备份和回滚，网站的静态发布不触发任一资金服务升级。

截至 2026-10-07，**本机 0.3 开发预览**已验证四档真实充值可下单、指定账户的 ¥10 充值入账、一次 GPT 5.6 MX 扣点及 RootFlowAI 消费账单核对；此前一笔未使用订单的原路全额退款也已完成。Opus 尚需独立实付调用与成本核对，Fable 暂停，GPT-6 已移除。临时回调隧道和本机 loopback 配置不构成生产部署；公网 HTTPS、生产渠道对账、跨平台安装、完整故障演练和正式发布门槛仍待完成。
