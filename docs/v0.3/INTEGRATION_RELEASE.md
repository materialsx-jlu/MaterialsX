Go API/Worker、计费 Web 和 LiteLLM 在本机是独立进程。试点关闭、Go 重启后，`/ops` 和计费 Web 均重新登录成功，受保护总览均返回 200；未登录计费管理请求返回 401。此前独立数据库故障测试已验证 Go 停止时计费 Web 返回 503、自身健康继续 200，Go 恢复后查询可用。试点关闭后修正了 Go `/health/ready`：开发模式且支付/计费工作均关闭时只要求数据库可用；有支付、模型计费或待处理作业时要求 Worker 心跳；生产模式始终要求 Worker。默认服务恢复后 `/health/ready` 实测 200。生产 HTTPS、跨主机 Cookie/Origin/CSRF、备份恢复和独立升级回滚仍须在目标环境复验。

## 本机 MX 钱包与网关激活（覆盖上文旧的本机关闭状态）

同日后续开发已增加 [迁移 014](../../services/control-plane/migrations/014_mx_gateway_wallet.sql) 和独立 `mx-points` 任务模式。网关创建任务检查 MX 余额；调用前在一个数据库事务中提交请求、锁定路由/采购价/汇率/零售价和钱包预留；终态完整且四类 Token 互斥时原子扣点。未派发请求释放；供应商已派发但缓存写入等用量缺失时保留全额预留，等待对账，不将未知量记为 0。隔离 PostgreSQL 测试已覆盖成功结算、缺字段待对账及可信账单补证。供应商账单成本与 MX 扣点分开记录。

本机 `--mx-live` 使用 `wechat-mx-live`、私有回调源、LiteLLM 独立进程和新复制的不可变 `approved-v1` 价格层。2026-10-07 当前会话验证：Go `/health`、独立计费 Web、LiteLLM 均返回 200；回调隧道 `/live` 返回 204，未签名支付通知返回 400；认证后的四个充值商品均 `enabled=true`、`salesEnabled=true`，零售价目录为 `approved`。新 ¥10 微信订单已确认支付，钱包到账 100 MX 点。桌面订阅页移除了旧订阅积分与 M3 演示区，MX 任务明细改为可换行卡片；云服务中心亦移除了旧订阅入口。

GPT 5.6 已完成一笔真实 `MX 点到账 → 网关调用 → 终态待核对 → RootFlowAI 消费日志补证 → MX 最终扣点`：网关请求 `263b0f90-ea00-44ee-b49c-c3784bc64c2a` 对应供应商日志 `202610071405578842241928268d9d6vnyfGaA2`。供应商列示输入 4,392（含缓存读 3,840）、输出 5、缓存写入栏为空，计费公式无缓存写入项；实际成本额度 $0.001208，按本项目约定折合 ¥0.001208。网关零售价扣 0.16905 MX 点，即 ¥0.016905；本笔模型层毛利 ¥0.015697，毛利率约 92.85%，未扣微信手续费、税和服务器费用。原预留 28.6888 MX 点已解除，用户可用余额为 99.83095 MX 点。内部采购估算 ¥0.0012075 与供应商账单差 ¥0.0000005，恰为供应商账单六位小数向上取整；系统保留原始账单并将此标准取整判为已核验，超出取整差额仍记价格异常。

可信操作员通过 [本地核对脚本](../../scripts/reconcile-local-mx.mjs) 将独立账单的供应商请求 ID、四类 Token 和金额提交给 `identityctl --command reconcile-mx-supplier-bill`。该命令要求供应商的总输入、输出、缓存读取与网关终态一致，并把供应商账单、钱包扣点、网关结算状态写在同一事务中；重复提交同一证据是幂等的，改变证据会拒绝。缺少任何一类独立证据时仍维持预留，不以零填充。

Opus 仍需单独的实付 MX 调用与独立账单核对；Fable 保持关闭。上述本机开通不等于生产 HTTPS、多端安装包和公开发行验收，临时 ngrok 隧道失效后需更新私有回调配置并重启本机服务。
