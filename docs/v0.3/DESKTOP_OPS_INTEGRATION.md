# 0.3.6 桌面与 `/ops` 联动开发记录

2026-10-07：诊断接线已落地；指定账户 ¥10 MX 点真实收退款已验证，四模型正式销售未开放。

桌面「订阅与额度」以 MX 点数为主视图，从 Go 用户 API 读取四档商品、MX 钱包、固定零售价草案、订单、退款状态和本人计费请求；旧套餐与 paid-credit 保留在折叠区。MX 点和旧积分始终分栏。用户创建订单前由服务端商品状态和销售模式共同把关；测试模式明确标记合成订单。桌面 IPC 只传商品 ID、幂等键和退款原因，不接收供应商 Key、单价或任意后端 URL。客户端请求白名单现已明确允许 MX 商品/钱包/订单/退款的固定路径；此前这些路径会在桌面传输层被拒绝。账单用量和扣点为未知时显示“待核对”，不填零。

桌面设置从 `/v1/models` 获取模型目录，只能选择服务端已准入的模型。四个公开槽位的诊断模式可绑定到 `alpha-test` 任务与请求，不能伪装成 paid-credit 或 MX 点消费；Codex 与 Pi 原生调用使用所选模型 ID，而不再强制替换为旧 `materials-research`。`gpt-6-sol` 仍因供应商精确 ID 未证实而关闭。该目录目前未提供真实 MX 点收费调用准入。

`/ops` 通过管理员会话读取四路部署快照，显示槽位、LiteLLM 别名、密钥环境变量**名称**、路由版本和诊断开关，不返回 Key。将 `MATERIALSX_MX03_PROBE_REPORT_PATH` 配成 Go 服务可读的私有绝对路径后，Go 只读取 `probe-v03.mjs` 的脱敏报告摘要；报告缺失或无效则标记 `not_synchronized`，报告本身也不等于采购账单核验。跨主机部署时须由受控交付过程把报告复制到 Go 专用数据目录，不挂载 LiteLLM 的密钥目录。当前价格草案的候选编号与独立计费后台价格页一致，均为 `mx-v0.3-rootflow-svip-20261007-draft`；这还不是已激活的不可变联合发布记录。总览的云请求与销售暂停开关仍可使用。

尚未完成的 0.3.6 工作：补齐四路真实探针（目前 GPT-6 ID 未证实）；供应商扣费倍率暂按用户提供值记录为待账单核验的假设；建立带审批与审计的不可变“路由版本 + 采购价 + 汇率 + 零售价”联合发布记录；通过受控部署执行代理配置发布、健康复查和原配置回滚，并保证 Go 只在代理复查后激活对应版本。`manage.mjs` 目前提供独立代理的配置快照、校验与恢复 CLI，但 `/ops` 不会通过进程开关推断供应商健康，也未触发远程进程变更。已完成的指定账户 ¥10 真实收退款只验证钱包与支付闭环，四模型扣点调用继续关闭。

验证包括 TypeScript 类型检查、桌面/合同测试、Go 领域与 HTTP 测试；隔离 PostgreSQL 环境的 MX 用量归属测试确保只展示本人记录且未知扣费仍为 null。¥10 实付、到账、财务审批、原路退款和点数回退见 [0.3.7 联调记录](INTEGRATION_RELEASE.md)。GPT-6 直接调用返回 503，联合激活及生产回滚尚待验收。
