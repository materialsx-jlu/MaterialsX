# 0.3.4 MX 采购价、汇率与零售价开发记录

2026-10-07：三模型 MX 钱包事务接线已实现；本机四档真实充值已开放，生产公开部署仍未发行。

## 固定价格与版本

`docs/V0_3_ROOTFLOWAI_PRICING.json` 是本阶段固定导入源。导入器核对原文件 SHA-256、版本、三模型顺序、四个价格档、四种 Token 类别和精确十进制格式。草案版本保持不可变；显式 `approve-mx-price-snapshot` 命令复制为新的不可变 `approved-v1` 采购、汇率和零售版本，不改写草案。采购价表示 RootFlowAI 站内额度/百万 Token，当前汇率快照为 1 额度 = ¥1；零售价表示 MX 点/百万 Token，充值换算为 ¥1 = 10 MX 点。`gpt-6-sol` 不在活跃三模型中；独立供应商账单仍需逐笔复核。

部署时先执行 Go 数据库迁移，再由迁移所有者在私有环境导入固定文件：

```sh
cd services/control-plane
go run ./cmd/identityctl -command migrate
go run ./cmd/identityctl -command import-mx-price-snapshot < ../../docs/V0_3_ROOTFLOWAI_PRICING.json
```

该命令只接受与代码固定哈希完全一致的文件，重复导入幂等；改价需要新的审核快照和版本，不能改写已有行。受限运行角色只能读取价格版本，不能发布或修改。新表、视图见 `migrations/013_mx_pricing.sql`。

## 单次调用的账务闭环

内部 `ReservePriced` 在同一数据库事务里预留 MX 点并记录请求 ID、模型、路由版本、采购价/汇率/零售价版本和最大输入/输出 Token。预留上限按可达到的最贵上下文档和最贵输入类别计算。`SettlePriced` 必须收到互不重叠的普通输入、输出、缓存读取、缓存创建四类 Token 及可信证据引用，才按锁定的零售价结算。GPT 的输入上下文达到 272,000 Token 时整次请求使用长上下文档。缺字段、越界或不可信证据时全额保留预留，状态进入 `reconciliation_pending`；旧的无价格 `Settle`/`Release` 不能处理带价格请求。请求失败可通过内部 `ReleasePriced` 释放。

计算全程使用整数和定点数。1 MX 点 = 1,000,000 子单位；用户扣点按六位小数向上取整。采购成本估计存为人民币 `microfen`（1 元 = 100,000,000 microfen），按采购价和锁定汇率向上取整；它不来自 LiteLLM 的美元符号花费日志。`RecordSupplierBill` 可追加独立账单金额与证据引用，和估计值不一致时进入 `mx_cost_discrepancies` 视图；`mx_pricing_anomalies` 同时列出待核对用量。`mx_pricing_financials` 分开显示已消费点数对应收入、估计采购成本与账单成本及两种毛利，尚未收到供应商账单时实际毛利保持空值。供应商账单不会回写用户扣点。

已登录用户可用 `GET /v1/mx-points/prices` 读取仅含零售价的四模型价目表、档位、计费类别、相对官方价格比例和草案状态；不会暴露采购价、汇率或供应商密钥。未导入快照时该接口不可用。

## 当前接线边界

网关现在支持独立 `mx-points` 任务模式。创建任务检查钱包余额；请求入站、路由版本和价格版本锁定、MX 点预留在同一数据库事务中提交。终态在同一事务中按四类互斥 Token 结算；未派发的请求释放，已派发但缺少缓存创建等可靠用量的请求保持 `reconciliation_pending`，不会把未知量当零扣费。桌面平台模型目录只向有余额账户开放该模式。当前真实供应商探针尚未证明每条模型路线都返回缓存创建分类，因此用户付款后的首笔真实调用和供应商账单对账仍是验收事项。`/ops` 的旧积分定价与历史订单保持原样。

验证：PostgreSQL 独立测试库覆盖导入幂等、不可变触发器、长上下文边界、微额取整、四类 usage、缺失字段待核对、历史请求锁价、普通结算绕过拦截、供应商账单差异和受限角色写权限；`npm run mx03:verify` 核对固定文件 SHA-256 与四模型配置。
