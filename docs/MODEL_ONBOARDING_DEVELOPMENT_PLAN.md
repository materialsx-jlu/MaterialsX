# MaterialsX 云端模型新增与发布闭环

状态：核心链路已实现并在本机验证，2026-10-08；跨平台部署和正式供应商账单验收仍未完成。范围是通过 LiteLLM 调用并按 MX 点计费的聊天/推理模型；材料机器学习势仍由“材料模型目录”管理，不进入 Token 计费流程。

## 本轮实现与验证

- `8790 → 财务 → 定价与模型` 已加入“云端模型接入”：登记草案、修订、代理目录检查、普通/流式/工具真实探针、分档采购与零售报价、三种用量场景和最大预留预览、灰度/正式启用/停用。管理员的写操作经同源会话、CSRF、角色和审计；页面只保存密钥环境变量名。macOS 本机开发后台可一键生成私有 LiteLLM 配置、重启代理并更新网关测试密钥；其他部署环境仍需按私有清单完成代理发布。
- 注册表、不可变采购/汇率/零售版本、按模型档位定价与公开模型目录已经接通同一数据库。新模型只在灰度账户或正式启用后可见；停用即阻断新任务。旧三模型历史价格与账本保持原样。
- 用现有 `gpt-5.6-sol` 建立独立测试别名：LiteLLM 非流式、流式、工具调用均返回 200 与完整用量；灰度账户通过 MaterialsX 网关完成真实流式请求和 MX 点扣减。发现供应商输出用量超出请求上限时，现已保留实际供应商用量计算采购成本，并将用户输出扣点封顶于授权上限；先前待核对的测试预留按磁盘上的终止回执修复，未重新请求供应商。测试模型随后停用并从代理目录移除。
- 探针沿用一次请求、三种调用顺序执行，浏览器、计费 Web 代理和 Go 响应的超时已按最长约 135 秒的探针预算协调；超时仍进入待核对，不自动重放可能已计费的调用。
- 无独立供应商账单的灰度请求只保留成本估算；正式启用返回冲突，未开放收费销售。微信充值沿用现有 MX 钱包，新增模型没有单独创建支付渠道。
- 自动探针尚未证明供应商端取消、结构化输出、跨平台安装包部署。产品中相应能力必须保持“未验证”；正式发行前还需采购单价/账单复核、Linux/Windows 实机部署和打包验收。

## 改造前的固定假设（已在核心链路拆除）

- 计费中心“财务 → 定价与模型”只读取固定价格快照，没有写入入口。现有快照校验固定了三个模型 ID、档位数量、SHA-256 和版本。不能通过在页面追加一行来启用模型。
- LiteLLM 当前以配置文件运行，`STORE_MODEL_IN_DB=False`；`services/litellm/manage.mjs` 只渲染三个诊断别名并要求别名数正好为三。直接在 LiteLLM Admin UI 添加模型，不能成为 MaterialsX 的正式部署来源。
- MaterialsX Go 网关的 `mx03Routes`、探针结果、密钥可用模型列表和 `mx_priced_reservations.model_id` 数据库约束均限定现有模型。模型在 LiteLLM 可调用，不等于在 MaterialsX 可选择、可结算。
- `quote.go` 用全局 272000 Token 长上下文边界推断档位。新模型必须按自己的价格档位和边界计价，不能沿用此常量。

## 产品操作流程

“定价与模型”改为两个视图：“已上线模型”和“接入中的模型”。具有 `billing.pricing` 或 `billing.admin` 权限的员工可点击“新增模型”，按以下顺序推进：

1. **登记模型**：填写 MaterialsX 模型 ID、展示名、供应商、供应商模型 ID、LiteLLM 别名、服务地址、协议、模态和凭据引用。凭据只保存在服务端密钥库；表单和审计事件只保存引用，不回显密钥。ID 和别名须全局唯一。
2. **确认代理支持**：先按供应商选择 LiteLLM 原生适配器；对于真正兼容 OpenAI 的中转接口，可选择 `openai/<供应商模型 ID>` 和受控 `api_base`。若协议、流式工具调用或用量字段无法适配，标为“需要适配器”，不能上线。此步骤只建立非销售诊断路由。
3. **连接与能力探针**：检查供应商目录中的精确模型 ID、LiteLLM `/v1/models` 中的别名；分别验证非流式、流式、工具调用、取消、输出上限与用量字段。真实生成探针需显示预计费用并记录请求 ID、时间、脱敏回执和供应商账单关联；失败不会自动重放可能已计费的请求。
4. **建立价格草案**：录入采购来源、币种/汇率、普通输入、输出、缓存读取、缓存创建的单价，以及每个长上下文档位边界；录入零售 MX 点单价和生效时间。缺少缓存类别时必须明确“该类别不适用”的供应商证据，不能将未知视为零。系统展示最大预留点数、预计毛利和至少三种典型用量场景。
5. **复核与发布**：价格、汇率、路由、能力报告各有不可变版本和摘要。管理员核对回执后发布，先灰度给测试账户；通过端到端请求、扣点、供应商用量、账单与退款关联测试后再开放普通账户。发布操作产生审计记录和可回滚部署版本。
6. **持续监控**：检查成功率、首 Token 延迟、计费差异、零成本请求、供应商模型名变化和价格过期。异常时停止新请求，保留既有任务与历史账本；回滚路由不改写已结算价格版本。

状态机：`draft → proxy_ready → capability_verified → pricing_review → canary → active → disabled`，另有 `adapter_required` 和 `probe_unconfirmed` 异常分支。需先核对可能已计费的探针回执，再从异常分支修订草案；只有 `active` 可出现在普通用户模型选择器。`disabled` 保留历史价格和回执。

## 技术实现顺序

### 1. 统一模型注册与数据库

- 新增独立模型注册表和部署版本表，区分供应商原始 ID、LiteLLM 别名、MaterialsX 公共 ID；每次修改生成新版本。将价格版本按模型/档位扩展，保留现有三模型快照与历史账本，不修改已经签名的旧快照。
- 新迁移移除 `mx_priced_reservations.model_id` 的固定枚举约束，改为引用已登记模型 ID，并在请求记录中钉住模型部署版本。老数据必须无损迁移，且仅允许已发布模型进入付费请求。
- 把价格选择改为“按模型版本 + 输入上下文档位边界”；禁止用全局 272000 边界决定所有模型价格。预留、实际用量、供应商成本分别保留证据。

### 2. 服务端接入 API

- 在计费后台同源 API 增加模型草案的列表、创建、修订、探针、价格预览、灰度发布、正式启用、停用和审计接口。写操作使用现有会话、CSRF、具名角色、幂等键和期望版本；不能让浏览器直连 LiteLLM Master Key。
- 探针在后端使用凭据引用；所有供应商响应只保存脱敏摘要。显示“LiteLLM 代理可调用”“MaterialsX 网关可调用”“用量完整”“价格已批准”“已开放用户”五个独立状态，禁止一个绿色总状态掩盖未完成环节。
- 让网关的公共模型目录、任务路由、授权密钥和计费引擎消费同一份已发布注册表。启动时拒绝缺少价格或能力回执的付费路由。

### 3. LiteLLM 部署策略

MaterialsX 注册表作为唯一发布来源，生成私有 LiteLLM 配置或调用经核验的模型管理 API；首版继续用版本化配置文件与原子替换/重启，避免 LiteLLM UI 数据库与 MaterialsX 注册表同时写模型造成漂移。保留 `STORE_MODEL_IN_DB=False`，但移除“必须恰好三个别名”的旧诊断门槛，改为校验已批准部署清单。新路由先以测试密钥可见，正式授权名单随发布版本更新。供应商密钥仍只通过环境/密钥库引用进入 LiteLLM。

LiteLLM 的文档表明其 Admin UI 可添加模型并做 Test Connect，生产部署也可设 `STORE_MODEL_IN_DB=True` 管理模型；这是 LiteLLM 自身能力，不会自动更新 MaterialsX 的价格和网关。参见 [LiteLLM Quickstart](https://docs.litellm.ai/docs/proxy/docker_quick_start) 与 [Production Deployment](https://docs.litellm.ai/docs/proxy/deploy)。

### 4. 管理界面

- “新增模型”采用六步向导：基本信息 → 代理配置 → 探针 → 价格 → 复核 → 灰度/发布。每一步保存草案，可返回修改；显示明确阻断原因和下一步操作。
- 价格表展示“采购单价/币种/来源”和“用户 MX 点单价”两套数字，含版本、生效时间、上下文阈值与使用量类别。禁用模型和未核账单必须醒目标注。
- “模型消费”的筛选项从已登记模型 API 获取，去除前端写死的三个选项。普通计费查看角色不能看到完整密钥或修改价格。

## 必须通过的验收

1. 新增一个仅测试用途的模型草案，刷新和服务重启后仍可读取；普通用户看不到它。
2. LiteLLM 不支持该模型时明确停在“需要适配器”，不会允许标价或销售。
3. 对可用模型完成精确 ID、流式与工具、用量四类数据探针；同一请求不会因为探针超时自动重放。
4. 修改价格产生新版本；历史任务仍按其原版本结算；不同长上下文阈值算出正确价格与足额预留。
5. 灰度账号完成真实请求、扣点、回执核对与成本差异测试；正式开放后其他账号才可见。停用阻断新请求但保留旧账。
6. 本地、macOS/Linux/Windows 打包安装验证注册表迁移、LiteLLM 配置生成和界面状态一致；密钥不出现在浏览器、日志、导出文件或仓库。

首个真实接入验证复用了现有 `gpt-5.6-sol`，并使用独立测试别名，不等于批准新的商业售卖模型。正式接入其他模型仍需精确供应商 ID、服务端密钥引用、采购价格和独立账单证据，不能从模型名称推断。
