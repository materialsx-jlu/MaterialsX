## 目标与边界

用户只需安装应用并登录，桌面端只知道一个稳定的 `https://api.<domain>`。账号、模型、钱包、支付、研究数据均从这个 HTTPS origin 访问；官网独立静态部署，管理入口单独保护。服务端仍可拆成 Go、Node、LiteLLM、MOOS、Worker 和数据库进程，但其端口不直接提供给普通用户。LM Studio 等本地模型继续访问用户机器的 loopback，不走平台网关。

```text
桌面端 ──HTTPS──┐
微信支付回调 ───┼── api.<domain> 边缘网关 ── /v1/research/* ── 团队研究服务 ── MOOS MCP ── MOOS
                 └─────────────────────────── 其他路径 ────── Go 账户/网关/钱包 ── LiteLLM ── 供应商
官网 ── CDN/静态站点                                     └───── PostgreSQL / Worker
管理员 ── 受保护的 admin.<domain> ── 计费 Web ── Go 私有管理 API
```

公开路由只有官网、统一 API、必要的微信通知路径；`/ops`、计费 Web 和 LiteLLM 管理 UI 仅允许管理员经 VPN 或具身份校验的访问网关进入。LiteLLM 代理、数据库、MOOS 原始 API 和 MCP stdio 进程留在内网。普通桌面客户端不持有供应商、微信商户、LiteLLM Master Key 或数据库凭据。

## 配置合同：用户只配一次，服务器集中管理

### 客户端公开配置

新增一个受 Schema 校验的安装包配置文件，例如 `resources/materialsx-client.json`，只包含 `schemaVersion`、`apiOrigin`、`releaseChannel` 和可选的官网链接。正式包的 `apiOrigin` 必须是无用户名、无查询、无路径的 HTTPS origin；开发包可显式启用 loopback。桌面启动先读取打包配置，再连 `/v1/client-config`（新增）获取非敏感的功能可用性、模型目录修订号、推荐更新版本等动态信息。服务端配置响应必须有版本、ETag 和有限缓存期；断网时保留最后一份已校验配置并在 UI 标记“离线/可能过期”，不得因此把旧价格当作新订单价格。

正式环境的模型可见性、模型能力、价格和可用状态以服务端已发布记录为准；设置、云服务中心、订阅与额度消费同一组公共 API 和发布版本。账户余额、能否下单、具体价格由服务端实时确认；客户端缓存只能用于展示。桌面地址切换依靠稳定域名/DNS 和正常版本升级，不允许从任意网页或未校验响应改写 API origin。现有 `MATERIALSX_IDENTITY_URL` 保留为明确的开发/测试覆盖项，再在安装版中迁移或废弃。

### 服务端部署清单

在独立 `deploy/` 目录定义一份不含秘密的环境清单，按 `development`、`staging`、`production` 分开：

```yaml
schemaVersion: 1
environment: production
public:
  apiOrigin: https://api.example.invalid
  siteOrigin: https://www.example.invalid
  adminOrigin: https://admin.example.invalid
internal:
  identity: 127.0.0.1:8788
  team: 127.0.0.1:8793
  billingWeb: 127.0.0.1:8790
  litellmProxy: 127.0.0.1:4001
  litellmConsole: 127.0.0.1:4000
  moosApi: 127.0.0.1:8080
```

`example.invalid` 是占位域名，不可直接发布。由单一校验/渲染命令为 Go、团队服务、计费 Web、LiteLLM、反向代理和桌面构建产出所需的现有环境变量/配置。地址只在清单中维护一份；已生成文件附清单摘要和版本，不手改生成物。若团队服务与 MOOS 位于另一台主机，清单改为私网地址并启用服务间 TLS；现有 `MATERIALSX_TEAM_TRUSTED_LOOPBACK_PROXY=1` 只用于同机代理，不可用于跨主机流量。

密钥通过服务器密钥存储或权限为 `0600` 的受控运行文件注入，使用引用标识与地址清单关联，不出现于安装包、静态站点、反向代理访问日志或 Git。至少隔离身份主密钥、PostgreSQL、供应商 Key、LiteLLM Key、微信商户材料、后台代理令牌和 SMTP 凭据；记录轮换与撤销步骤。生产数据库继续执行现有 `verify-full` TLS、受限运行角色和独立迁移角色检查；LiteLLM 使用独立数据库。

## 分阶段开发

### OD.0 配置与依赖盘点

实现回执：[`deploy/README.md`](../deploy/README.md) 记录人工核对清单、访问方向和路由责任；`deploy/config-schema.mjs`、`deploy/routes.mjs` 与 `scripts/deployment-config.mjs` 提供严格清单校验、路由遮蔽检查和不含密钥的预览；`scripts/deployment-inventory.mjs` 扫描一手源码的环境变量名称及 URL origin。`npm run config:test`、`npm run config:check`、`npm run config:inventory`、`npm run check` 已通过。预览明确写出 `deploymentReady:false`，不声称可直接上线。

- 编写自动扫描与人工核对清单：桌面、Go、计费 Web、LiteLLM、团队服务、官网、微信、MOOS、邮件、论文检索、更新源的监听地址和出站地址；区分用户可配置的本地模型地址与平台地址。
- 确定一套公开路由表及所有者：`/v1/research/*` → 团队服务；其他用户 API 和认证 → Go；微信通知 → Go；`/ops` → Go 但须管理员边缘准入。记录每条路由的认证、请求大小、流式、超时与回调重试要求。
- 建立 `deploy/` Schema、模板和 `config:check`。检查 HTTPS、同源、端口冲突、生产开发开关、错误的回调域名、凭据明文和路由遮蔽；生成可脱敏的部署预览。
- 验收：在空白机器上仅凭示例清单能生成全部无密钥配置；错误清单在启动前失败；现有本机开发栈不受影响。

### OD.1 安装包和单一 API 入口

实现回执：桌面安装版从随包 `materialsx-client.json` 读取唯一 API origin，忽略开发环境变量；缺失或错误配置不会回退本机地址。预览包无部署清单时明确关闭平台连接；正式渠道必须使用经校验的生产清单。旧 8787 桌面订阅客户端/IPC 和启动时调用已移除，实际订阅与钱包继续使用 8788 平台 API。Go 提供公开、限时缓存的 `/v1/client-config`，包含目录修订、已发布版本与粗粒度功能状态；桌面保留同源已校验回执，离线标记过期，设置/云服务中心/订阅页面在目录修订变化时重新读取实时数据。`npm run check`、桌面构建、配置测试与 PostgreSQL 实库 ETag 测试通过。真实 HTTPS 域名尚未提供，macOS/Windows/Linux 安装后的公网连接验收仍待环境准备；此项不能据本机测试视作生产放行。

- 桌面引入打包配置加载器及配置合同；macOS、Windows、Linux 构建都携带同一发行渠道的正确 API origin。将登录、云服务中心、订阅、模型目录和团队研究连接统一交给平台客户端，不由各组件自行拼公网地址。
- 删除或隔离旧 `8787` 订阅客户端/IPC；若仍有历史视图需要数据，改从现有 8788 API 获取。启动和设置页明确区分“平台不可达”“未登录”“当前为离线本地模式”。
- 服务端提供版本化 `/v1/client-config`，只返回公开元数据；任何模型价格/权益的提交仍须服务端判定。目录更新用 ETag/修订号，应用内页面收到发布事件后一起刷新。
- 验收：无环境变量的三平台安装包均请求预期 API；错误域名不能静默回退 localhost；断网本地 LLM 仍可用，付费操作安全关闭；同一模型在设置、云服务中心和订阅页的可见性与价格版本一致。

### OD.2 HTTPS 边缘网关与身份服务

实现回执：`deploy/edge-nginx.mjs` 与 `scripts/deployment-edge.mjs` 从已校验清单生成双域名 Nginx 配置和默认拒绝的管理员准入文件；Go 与计费 Web 生产监听仅允许 loopback，Go 的 Host/Origin/可信代理检查及管理域名 `/ops` 已接通；`/health/live` 和分项 `/health/ready` 已分开。配置、身份和模型代理探针测试通过；真实公网 DNS、TLS、外部端口扫描、登录/撤销/流式/断流计费验收仍待服务器和域名，不视作生产放行。

- 把 UA.13 的反向代理模板扩展为可渲染的生产配置，固定 Host、Origin、转发头和可信代理范围；默认禁用路径探测/任意 upstream。`/v1/research/*` 转发保持 MCP HTTP 与长任务流式响应；模型响应关闭代理缓冲并设置合适的空闲超时，不能由代理自动重放已派发请求。
- 将 8788、8793、8790、4000、4001 和数据库限制到 loopback 或私网；公网仅 443。管理员路径与后台域名通过 VPN/身份网关准入，后端会话、CSRF、TOTP 和角色检查继续生效。
- 健康探针分 `live` 与 `ready`；`ready` 按账户库、Worker、模型代理和实际功能开关分别报告，不以一个进程存活证明收款或模型可用。
- 验收：从公网完成登录、设备撤销和流式模型调用；直接访问私有端口失败；错误 Host/Origin、伪造代理头被拒；请求中断后的原任务可核对、不重复收费。

### OD.3 MOOS 与科研数据跨网络访问

实现回执：`deploy/config-schema.mjs` 的 `researchData` 区分同机和私网双向 TLS；`deploy/moos-link.mjs` 与 `scripts/moos-link.mjs` 保留本机 MOOS 适配器和 8080 限制，只允许固定只读路由、证书身份和有界传输；团队投影拒绝非 JPEG 的原始二进制资源。`deploy/moos-link.test.mjs` 已覆盖非法路由、无证书/错误服务名及真实本机 MOOS 经加密桥接后按项目检索和越权拒绝。该回执使用本机合成身份与临时证书；异地安装版、真实服务器证书、设备撤销和公网端口扫描仍待上线环境，不标记生产验收通过。部署与轮换步骤见 [OD.3 MOOS 私网连接](../deploy/OD3_MOOS_LINK.md)。

- 团队服务在能访问 MOOS 的私网运行，MCP 继续本机 stdio 接入 MOOS API；普通桌面经同源 `/v1/research/*`、账户身份和项目 ACL 访问。不要直接把 MOOS 8080 换成公网 URL，因为当前适配器只允许 loopback。
- 明确项目授权、待复核记录标识、证据页码、读取范围和撤销行为；大文件与图像以受控文件/对象引用传送，避免把原始大 PDF 整个嵌入模型请求或访问日志。跨机器连接用私网加密通道与服务间身份，不信任客户端提供的研究角色头。
- 验收：安装版在异地网络检索一条授权 MOOS 配方，读取组分、步骤和证据；越权项目、禁用链接和撤销设备均不能读取；原始 MOOS API 不可从公网访问。

- 验收：停止任一后端能定位故障并维持安全状态；旧版本回滚不改写历史账本；安装包在 macOS/Windows/Linux 实机完成安装、登录、本地模式、云模型、研究数据、更新和卸载回归。

### OD.7 预发布联调与放量

实现记录：已接入只读公网拓扑探针、staging/生产隔离校验、逐阶段私有回执与运营暂停状态门禁，并将暂停/未配置原因发布到客户端能力目录；操作合同见 [OD.7 预发布联调与放量](../deploy/OD7_ROLLOUT.md)。真实 staging/生产部署、批准商户、小额实付、异机恢复和三平台安装验收尚未完成，不能标记正式放量通过。

## 实施顺序、可并行项与完成定义

依赖主线：`OD.0 → OD.1 + OD.2 → OD.3 + OD.4 → OD.5 → OD.6 → OD.7`。官网构建、日志/备份可与 OD.1–OD.4 并行；真实支付必须等公网入口和计费闭环稳定后进行。每阶段提交代码、Schema/迁移、最小必要测试、配置示例、部署/回滚命令和验收记录；同一目录或服务不得保留两套互相冲突的生产地址来源。

项目完成的判据不是“所有端口都有公网地址”，而是：新用户安装后无需手工配置平台接口即可登录并按权限使用；管理员能独立发布、核对和撤回模型；MOOS 数据有证据且受项目授权；真实订单和模型消费可逐笔对账；故障可定位、可恢复、不会重复扣费。此时各功能的用户入口仍只有统一 API，内部服务可独立扩容和升级。
