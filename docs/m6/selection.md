# M6.4：可解释选势、默认 Skills 与会话科学工具

2026-10-02 · MX-605 · © 2026 吉林大学 AI-DAOS 团队

M6.4 已接通本机科学任务与本地/平台 Pi 会话。两种核心势为 CHGNet 0.3.0 与 MACE-MP-0b3 medium；另外 14 项仍为候选目录，不自动下载或执行。默认 Skills 共 91 项，其中新增七项“原子模拟与机器学习势”。这属于开发版工程能力，未重新发行安装包。

## 使用

1. 打开“模型目录 → 机器学习势 · Checkpoints”，导入结构或选择内置 `si-diamond`、`nacl-rocksalt`、`si-triclinic`、`water`。也可选择此项目此前导入的结构。
2. 明确适用域与用途，再点“筛选兼容势与证据”。默认正式计算；当前没有独立 DFT 领域参考集，因此正式候选为空，显示 `DOMAIN_NOT_VALIDATED`。明确改为“探索试算”后，兼容的无机三维周期晶体才可执行。
3. 选择合格势，运行单点或 FIRE 优化。产物登记 `selection.json`，记录输入、候选/排除、权重和依赖身份、真实元素覆盖、实际选择与限制。读取或重启时检查登记摘要，修改文件后拒读。原文件不覆盖。
4. 本地模型：点击“填入本地模型请求”，或在输入框用 `@` 选择新 Skill。模型先筛选，引用候选真实证据，再执行/查询任务。可点开 Skill 查看中英介绍、复制双语例子或跳转势目录。
5. 平台模型：先选择/创建项目对话，再点击“授权范围并填入平台请求”。输入框上方显示结构、任务、适用域与用途，可清除。发送时原生确认框列出本轮结构摘要和本机执行范围；接受后才创建平台请求。退出账户或重启会清除范围，历史结果不授予新结构/任务权限。

平台科学工具仅接受本轮结构 ID、任务和自身创建的任务 ID。无坐标/完整原子力数组/本机路径的摘要可外发；原子数、元素计数、PBC、显式电荷/自旋、来源 SHA、选势证据及标量结果会发送给所选平台模型。原生确认回执保存在应用私有 `atomistic/consents/`。用户问题、已批准文本附件和本对话平台历史仍按原 M5 确认范围发送；这些额外文本可能含用户自己填写的坐标或路径，科学摘要过滤不替代附件审核。

平台 LLM 请求继续使用原网关、预算、原生 Responses 流式输出和真实用量结算。上游结果或积分结算未确认时，停止后续本机工具与模型请求。CPU 科学计算本身不扣云积分；本轮最多两项本机计算，用于受限单点/两势比较。取消会停止该轮自己创建的任务，不能取消其它任务。

## 默认任务 Skills

| Skill | 当前能力 |
| --- | --- |
| `materials-atomic-structure-inspect` | 检查项目结构/内置样本，解释周期边界、部分占据及阻断项 |
| `materials-mlip-selection` | 硬性筛选、候选证据、排除理由、正式计算拦截 |
| `materials-mlip-singlepoint` | 合格核心势 CPU 单点与真实结果/登记产物 |
| `materials-mlip-relaxation` | FIRE；固定晶胞默认；变胞按明确约束与外压执行 |
| `materials-mlip-md` | 已内置，仅方案与前置检查；执行器待 M6.5，不生成轨迹 |
| `materials-mlip-comparison` | 同一不可变结构、两个不同合格势的真实单点力差 RMS/最大值 |
| `materials-atomic-3d-view` | 打开本机 3D；分子可预览，预览不等于分子计算 |

两势比较禁止未对齐能量基准的总能量比较或平均；模型一致不代表准确。优化报告区分实际收敛、步数上限、取消及失败；单点计算不能写成已收敛。力向量定义与压力/应力符号沿用 [M6.3](relaxation.md)。

## 选择合同与边界

- M6.0 注册表、任务名称规格、质量策略及 release-lock 不修改。`skills/atomistic-m64.json` 单独记录启用与执行状态；真实安装覆盖层来自受控本机运行时。
- 首次筛选在隔离子进程读取固定权重，核验实际 SHA/大小和依赖锁后提取实际元素列表；最多 60 秒、4096 MiB、有限协议/日志。内存值是加载完成后的观测 RSS，非按任务规模预测的峰值。后续缓存只复用同权重/锁的元素回执，每次仍重验权重 SHA。已有科学任务运行时不再加载第二个模型。
- 硬门槛包括实际运行时、许可、权重身份、元素、PBC/占据/解析阻断、已确认无机域、输出/head/电荷/自旋、原子数、加载内存余量和步数。未知/分子/高分子/表面/界面不可进入当前核心计算；MD 由 M6.5 开放受限固定晶胞 NVE/NVT，见 [动力学](dynamics.md)。
- 独立误差、训练重叠与体系规模资源预测仍未知。通过兼容检查的探索候选并列，以固定 ID 顺序显示；此顺序不是精度排名。生产模式始终要求独立参考，当前阻断。
- LLM 提案只含 assessment ID、已合格 potential ID 和该候选的证据 ID。拒绝额外参数、虚构引用、非候选及跨项目/陈旧评估；开始前再次核验注册表、结构、权重、运行时与兼容性。
- 预算默认 256 原子 / 600 秒 / 4096 MiB / 64 MiB / 4 线程；真实计算 watchdog 继续执行内存、输出与超时限制。加载观测值无法保证大体系在此预算内完成。
- 本地旧单点/优化 IPC 保留为明确选择势的探索兼容入口，仍执行硬门槛并登记选择记录；不能通过增加 `mode` 等参数绕过严格 schema。Agent 的两项专用运行工具现在也必须提交评估 ID 和证据。

所有计算保持 `needs_review`。不能把硬性兼容、数值一致性、合成样本或运行成功解释成 DFT 精度/热力学稳定性验证。Windows、正式安装包与真实供应商多步科学推理仍须分别验收。

## 工程复验

```bash
npm run check
npm test
npm run control-plane:test
npm run m64:contracts:check
npm run skills:accept:materialsx
npm run m6:selection:test
npm run m6:ui:selection
# 原生确认 + PKCE + PostgreSQL/网关 + 真实 CPU（隔离测试库）
npm run m6:cloud:selection
```

真实 CPU 验收要求已构建两套隔离运行时，见 [M6.1](runtime.md)。平台验收使用合成 Responses 数据，但经过真实 Pi SDK、Go 网关原生请求验证及本机真实计算，不调用供应商或支付。补充云端桌面闭环使用新建的 loopback PostgreSQL 隔离实例（或显式 test 库）、真实 PKCE 登录/网关/用量记录，验证拒绝不发起任务、接受后完成真实 CPU 任务、确认回执与退出撤销。需要 PostgreSQL 16 工具，可设置 `MATERIALSX_POSTGRES_BIN`；临时服务/库在验收后清理。桌面验收使用独立 userData 和团队合成结构。证据见 [M6.4 验收](selection-acceptance.md)。
