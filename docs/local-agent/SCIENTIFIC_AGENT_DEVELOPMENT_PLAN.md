## 1. 产品目标与范围

MaterialsX 面向材料研究生、科研人员和研发工程师，帮助他们理解研究问题、组织材料数据与证据、执行分析、检查科学适用性，并依据真实结果选择下一步。长期目标是形成可持续积累、可审核和可复现的材料研究工作台。

通用文件、代码、终端与任务恢复沿用 LA/Codex 底座；材料判断与工作流依托 Skills、领域工具、科学规则和实际数据。强模型是推理能力的一部分，不能代替数据质量、领域验证或真实实验。

LA 与 RA 关系：LA.0–LA.20 解决可靠执行、性能、基础检索/流程；RA 扩展研究数据、项目记忆、科学质量和反馈。RA 不重建另一套 Agent 引擎、M5 账本、M6 科学 worker 或 MOOS 数据库。编号是交付标识，不要求按数字逐个完成才能运行最小闭环。

M7 统一多尺度方法论和首个材料选型继续暂缓。RA 支持明确条件下的候选、实验设计和适用方法连接，不把“性能→分子结构”作为已解决的一一映射，不要求研发统一微观到宏观预测引擎。

## 2. 三个首批价值场景

| 场景 | 真实输入 | 最小交付 | 完成边界 |
| --- | --- | --- | --- |
| 材料证据表 | MOOS 实验/论文/专利记录，或授权论文 | 可编辑条件化数据表、证据跳转、缺项/冲突说明、导出 | 只读摘要不冒充全文，缺证据不补造 |
| 实验分析 | 用户原始曲线/表格或 MOOS 合法数据资产 | 单位/条件/QC、图表、统计、脚本、报告 | 保留原始数据；无重复试验不造误差条 |
| 结构计算 | 用户结构或 MOOS 中真实可取得结构资产 | 资格检查、适用选势、真实运行、结果与 3D、方法说明 | 模拟声明不等于结构/权重可取得，缺输入时停止于准备 |

一个入口调用不同专项 Skill，结果保存为项目产物。目录数量、下载量、模型说得流畅均不作为这三个场景的完成标准。

## 3. 目标架构与数据优先级

```text
研究目标 + 项目实测输入 + 用户约束/授权
                   ↓
ResearchProjectStore：样品、条件、数据、证据、假设与决策
                   ↓
Codex 优先 / Pi 兼容 + 材料流程 Skills + LA 任务监督
                   ↓
DataSourceRouter：优先 MOOS MCP，覆盖不足再查外部来源
                   ↓
EvidenceService + DatasetBuilder + MethodRouter
                   ↓
受管分析执行器 / M6 科学后端 / 后续远程计算
                   ↓
技术完成检查 + ScientificQualityValidator
                   ↓
可编辑表格 / 图表 / 原文证据 / 实际结构 3D / 报告
                   ↓
用户确认的数据与真实实验反馈 → 新版本 → 后续研究决策
```

材料数据获取：用户指定的项目实测/文件优先作为输入；新增实验、配方、工艺、模拟、图片、性能数据优先从 MOOS MCP 获取。连接未就绪、字段缺失、条件不满足与无匹配分别记录，再依照授权补外部来源或待用户输入。

MOOS 服务拥有入库、复核、索引和资产权限；MaterialsX 拥有研究目标、分析版本、派生产物、方法选择和决策。私人记录不自动进入公共平台，不默认把全库发送给云模型。数据源授权与 M5 模型订阅分开管理；Token/计算费用和数据读取回执关联但不重复扣费。

详细服务、工具和接入合同见 [MOOS MCP 计划](MOOS_MCP_SERVICE_PLAN.md)。arXiv 仍为默认外部预印本入口，Crossref 等负责后续身份/覆盖补充；来源没有匹配不等于科学上不存在相关研究。

## 4. 核心研究对象与所有权

| 对象 | 关键字段与约束 |
| --- | --- |
| ResearchProject / ResearchCampaign | 目标、材料体系、指标/条件、阶段、预算、权限、未解决问题 |
| Sample / Batch / Specimen | 材料身份、组成基准、批次、试样几何、取向、状态、父子关系；同名材料不直接合并 |
| Recipe / Process | 含量及基准、实际步骤与参数、设备、处理历史、与样品/来源关系 |
| Observation | 性能量、值/单位、温度/应变率等条件、原始数据、重复数、不确定性、reported/calculated 等类型 |
| Evidence / Asset | 来源版本、页表图、原文、合法资产/SHA、权限、抽取复核状态 |
| Method / AnalysisRun | 固定代码/模型/环境/参数、适用域、输入快照、运行回执、产物、技术与科学检查 |
| Hypothesis / Candidate | 支持/反对证据、替代解释、预测、否定条件、待验证状态 |
| ExperimentPlan / Outcome | 变量、对照、随机化/重复、实际测量、失败原因、操作者与偏离计划 |
| Decision / Correction | 选择理由、当时证据与约束、人工改动、版本、受影响结果 |

复用 RPSME/XYZ 作为交换和投影来源，在连接边界显式适配；不强行用一个 ontology 覆盖所有材料。保留原生字段，无法映射的内容进入带版本扩展和缺项报告。项目内 UUID 与 MOOS ID 分开，数据引用含 connectionId/sourceId/experimentId/generation/entityType/entityId。

基于源快照/SHA 与依赖关系标记分析失效。更改样品面积、工艺温度或原始 CSV 时，只重算受影响的分析；旧报告保留为历史。不自动将最新结论覆盖审计轨迹。

## 5. 可运行方法、Skills 与方法包

Skill 定义何时使用、输入需求、流程和完成条件；MCP/执行器提供真实调用；Method Registry 记录支持范围和验证。用户自建 Skill 可以执行授权任务，不能自动获得“已验证方法”标记。

完整 MethodPackage 包含论文/数据许可、代码 commit、环境锁、模型/checkpoint/hash、输入输出 schema、单位、例子、参考数据与容差、适用范围、运行资源、失败边界和双语说明。参考结果复现是技术资格的一部分，独立材料体系验证另列。

默认研究 Skill 应能执行：搜索/读取 MOOS → 检查条件与质量 → 构建小型分析数据集 → 使用适当真实方法 → 校验 → 保存结果。候选、实验和反馈专项模块复用 LA.20，不以每一个势复制独立全流程提示词。

公开研究对这种架构有参考价值：Paper2Agent 封装论文方法并用参考输出校验工具；Kosmos 用结构化状态维持长任务；Co-Scientist 将假设批评与实验验证结合。它们的特定案例不证明 MaterialsX 已具备相同能力或任意材料体系可自动闭环。[Paper2Agent](https://www.nature.com/articles/s41586-026-11044-y)、[Kosmos](https://arxiv.org/abs/2511.02824)、[Co-Scientist](https://www.nature.com/articles/s41586-026-10644-y)

## 6. 科学判断与可比性

至少分开记录 taskState、technicalStatus、evidenceStatus、scientificStatus、experimentalValidationStatus。退出码 0、生成文件、结论可信和实验成立不能互相替代。原状态不能被报告措辞升级。

ScientificQualityValidator 检查：

- 数值、量纲和组成基准；原单位/归一单位转换可复查。
- 样品、批次、工艺、测试标准/条件和重复测量；缺条件不算满足筛选。
- 模型的元素、物相、温度/压力、任务和训练/验证范围；超范围保留风险或 unsupported，不强行计算。
- 模型比较的物理口径一致；不同 DFT 参考/能量零点的绝对能量不能直接当作材料优劣排名。
- 统计分析的数据分组、样本独立性、缺失值和重复测量；训练/测试按论文/批次等分组防泄漏。
- 拟合/预测需要基线、验证切分、误差和适用域；小数据不能凭 LLM 产生校准后的预测区间。
- 结论与事实/证据的支持关系、反例、替代解释；相关性不升级为因果。

科学置信度来自证据类型、测量和验证方法，不使用 LLM 自报“95%可信”作为概率。多个 Agent/模型一致可作为复核线索，不替代独立实验。

## 7. 分阶段开发

以下研发日是工程规划候选值，包含阶段说明与针对性测试；不含新增材料数据采集、独立精度研究、设备/商户采购及长期实验等待。LA 复用和 MOOS 工作分别记账，RA.0 后删去重叠工作重新估算，不直接将 LA/RA 总量相加。

| 阶段 | 交付 | 主要依赖 | 候选研发日 |
| --- | --- | --- | --- |
| RA.0 | MOOS 能力/数据调查、六类合同、金标准与 MCP 版本冻结 | 无；LA.0 可同时开展 | 3–5 |
| RA.1 | MOOS 只读 MCP server、八工具、资源和错误回执 | RA.0；SDK/权限合同 | 5–8 |
| RA.2 | MaterialsX MOOS 优先接入、缓存/增量、证据/图片卡片 | RA.1 + LA.1/LA.12 或 LA.15.A 最小 MCP 桥接 | 4–7 |
| RA.3 | 研究项目状态、样品/批次/条件、版本快照与工作台 | RA.0 + LA.5/LA.13；与 RA.2 集成 | 5–8 |
| RA.4 | 证据质量、条件可比性、冲突/撤回、科学检查 | RA.2/RA.3 + LA.6 | 6–10 |
| RA.5 | 实验原始数据分析包、可编辑 QC/图表/脚本 | RA.3/RA.4 + LA.11/LA.17 | 8–15 |
| RA.6 | 跨方法科学路由与条件化基准 | RA.4；LA.7/LA.20 与已有 M6 | 6–10 |
| RA.7 | 假设、实验计划、真实反馈、下一轮实验推荐 | RA.4/RA.5/RA.6；足够合法数据 | 10–18 |
| RA.8 | 经验证的论文方法包与社区贡献/更新 | LA.8/LA.12/LA.19 + RA.4/RA.6 | 8–15 |
| RA.9 | 跨天研究/远程计算与恢复 | LA.5/LA.13 + RA.3/RA.6 | 5–9 |

### RA.0：调查和基准

- [ ] 实测 MOOS 服务地址/开关、契约、权限、索引新鲜度与六类字段覆盖；报告计数时间与范围。
- [ ] 区分已入库记录/文件草稿，审核状态/科学验证、媒体元数据/像素、模拟声明/可复算输入。
- [ ] 冻结最小八工具和类型化引用；历史 generation 不可读、缺字段、性能分页等列入缺口。
- [ ] 建立合成/授权的金标准、来源优先与错误样例；私人数据只在本机验收。

验收：六类数据逐项映射，无新增模型生成费用和源数据修改；真实合同与脱敏 fixtures 对应；协议/运行时和权限路径明确。

### RA.1–RA.2：优先数据源闭环

实施与测试以 [MOOS MCP 规范](MOOS_MCP_SERVICE_PLAN.md) 为准。先上线同机只读，完整远程身份门槛在 RA.10；不封装已有采购、审核、索引或模拟副作用为普通读取工具。

验收：MOOS MCP 查询与分页→读取详情/证据/合法图片→保存选定数据快照→真实分析→中文/英文报告；断线/拒绝/无数据/不完整数据正确区分。界面标签“MOOS”对应真实工具回执。

### RA.3：持续研究状态

- [ ] 项目 manifest、样品/批次/试样关系与数据引用持久化；持久层复用现有存储能力。
- [ ] 依赖图、分析版本、人工纠错、阶段恢复与未解决问题；上下文只装载当前必要摘要。
- [ ] 增加研究工作台，复用已有左项目/中对话/右证据布局，按任务展示表、图、结构与决策。

验收：关闭再开继续同一研究；跨项目不串数据；改一个输入只标记相应下游结果；旧版本可追踪；没有实测结果的实验仍 waiting_for_input/needs_input。

### RA.4：证据和科学检查

- [ ] 引用和数值回链；字段 missing/unknown、原文与推断分开。
- [ ] 单位/含量基准、条件比较、批次与重复测量识别；不可比较时输出原因。
- [ ] 支持/反对证据、来源撤回、误配图片、版本变化造成的结果失效；纠错不修改上游事实。

验收：故障集无伪造值/引用/实验；不能比较的数据不进入聚合；来源被撤回仍能保留审计但停止作为当前推荐依据。

### RA.5：实验数据分析

首批强制完成应力—应变 CSV/XLSX；XRD、DSC/TGA 从实际可用原始格式中选下一项，先冻结数值算法和仪器导出支持矩阵。论文图像数字化为 digitized 数据，保留标定/误差/人工核对，不能冒充仪器原始数据。

- [ ] 单位/几何/试样/温度等条件检查，可编辑拟合区间和异常点原因；原始数据不可覆盖。
- [ ] 经测试的算法生成图表、重复样统计和脚本；参数和环境锁保存。
- [ ] 缺少面积、应变来源或测试条件时，生成缺项报告，不制造模量等派生物理量。

验收：与人工参考数值/图表在预先固定容差内一致；更改拟合区间可复算；无重复数据不制造误差条；项目在新环境恢复脚本结果。

### RA.6：方法选择

- [ ] 按研究目标与数据条件选择文献比较、统计/拟合、数据模型、已有 MLIP/计算等可用方法。
- [ ] 方法包记录支持范围、证据/验证数据、资源与缺口；候选依据先确定性过滤，再由模型解释。
- [ ] 多方法结果按一致口径比较；超适用域、数据泄漏和不合理跨尺度推断有检查。
- [ ] 自定义分析可使用通用执行工具，但保持未领域验证身份，不冒用 M6 合格方法回执。

验收：人工标注的适用/不适用/缺输入任务正确分流；M6 原有资格检查不退化；没有支持宏观求解器时输出待准备而非虚构全场预测。

### RA.7：实验反馈与下一步

先做 DOE、约束检查与真实结果归档；具备足够数据和验证条件后加入贝叶斯优化/主动学习。下一轮推荐同时考虑性能目标、成本、可加工性和信息价值，保留探索与利用策略及预算来源。

- [ ] 假设结构化保存支持/反对证据、替代解释、预期观察、否定条件与区分实验。
- [ ] 计划包含变量、对照、重复、随机化/分组、测量与验收；用户反馈偏离计划也记录。
- [ ] 真实结果含失败与不可测；用户录入和已授权设备读入有明确 origin，不由模型生成完成记录。
- [ ] 小数据先用基线和可解释 DOE；不确定性需具体校准/验证，不凭模型自述概率排序。

验收：合成可控优化问题与已有授权回放数据比较随机/DOE 基线；训练和评价分开；真实材料效果需要后续实验验证，不能用回放宣称研发成功。设备自动操控另设项目与许可门槛。

### RA.8：论文方法包

- [ ] 发现论文对应官方代码/数据、审核许可/权重分发，锁 commit/env；受限隔离环境复现参考输出。
- [ ] 封装真实工具/MCP，再生成双语 Skill、例子、资源清单和支持范围。
- [ ] 状态 discovered→candidate→reference_reproduced→domain_validated；每次升级独立验证，可回退/撤回。
- [ ] 社区提交方法包需参考案例、容差和许可；不只交提示词。自动发现不自动成为默认可信工具。

验收：两个合法有代码的材料方法案例，与参考输出比较；一个失败/许可不明案例不能进入默认包；更新后引用和回归结果仍可复查。

### RA.9：跨天任务与计算

先支持用户已有受控 SSH/Slurm 环境或本地长任务，保存实际 scheduler/job ID、输入 hash 和环境。恢复先查询真实状态，不重复提交或扣费；排队、计算、模型和下载耗时分开。研究 campaign 可包含多个 LA 任务，允许关闭模型会话等待计算，不能无限续跑。

验收：断线/桌面重启/集群排队/取消/超预算/节点失败下恢复；超预算保存进度并按有效授权续跑；脚本生成不代表远程执行完成。

### RA.10：团队和远程服务

从项目级读者/编辑/审核角色开始，与 MOOS 授权建立明确映射。M5 登录不自动赋予 MOOS 管理权。跨项目、资源访问、数据外发和模型目标的权限由服务端执行；敏感配方/IP可只用本地模型或授权的最小字段。

验收：越权/撤销/分享/缓存访问/审计/远程 TLS 和 Origin 检查；审核只能形成合法版本，不能用同一 Agent 扮演独立复核人。

### RA.11：产品和科研验收

每批 release 发布技术矩阵、数据/方法覆盖、独立精度范围、已知限制和可重复样例。先做 macOS 验收再 Windows 实机，不能用 CI 编译代替跨平台运行。产品测试与独立科学验证分开。

## 8. 质量指标

| 指标 | 首个正式研究预览目标/记录口径 |
| --- | --- |
| 引用可定位率 | 固定授权金标准中重要事实 100% 有可访问引用或明确缺证据；不是声称所有事实均正确 |
| 事实与数值正确率 | 至少 60 个金标准字段/结论，≥95%；关键数值/单位错误和越界案例单独列，不能用平均值掩盖 |
| 可比性/权限/假完成检查 | 固定边界与故障集 100% 正确阻止，不推广为全场景零错误 |
| 三场景任务完成 | 每场景至少 10 个固定案例、独立运行三次；可执行任务≥90%，拒绝/不支持另列 |
| 可复现性 | 固定环境/输入下全部参考案例满足预定容差；随机算法记录种子和统计容差 |
| MOOS 优先策略 | 合同用例中源选择与获取回执 100% 一致，失败回退有原因；响应不伪装成 MOOS |
| 产品收益 | 在授权试用中记录人工修改数、到可用产物耗时、返工率与重复使用；先测基线，不预设节省百分比 |
| 下一轮推荐 | 与基线比较目标改善/信息价值/费用；科学效果以真实实验独立验证 |

测试集需有未用于调提示/实现的保留案例，按论文/样品族/批次分组；专家核查不能全部由生成模型自评。任何“超越通用 Codex”描述仅在同条件、具体材料任务与明确指标通过后使用。

## 9. 用户体验和例子

所有新增页面、卡片和抽屉沿用 Skills/模型目录样式与全局配色，支持中英文、长名称、多列证据与窄窗/全屏。例子可以复制到输入框；产品标题不用 RA/LA 编号，阶段号留在开发文档。展示数据覆盖、执行状态、依据、局限和下一步，不用“已自主发现”替代待验证结果。

示例一（首批目标）：

> 优先从 MOOS 查找碳纤维增强热塑性材料的配方、加工条件和拉伸性能，按基体、纤维含量基准、取向和测试温度整理。仅比较条件足够一致的记录，给出数据表、图片/原文证据、缺项和中文报告。

示例二（实验分析目标）：

> 分析项目中的拉伸 CSV 和试样信息。先核对单位和试样尺寸，保存拟合区间、重复样统计、图表及脚本。用 MOOS 相近条件的数据作参考，区分本次实测与论文报告。

示例三（后续反馈目标）：

> 根据本项目已完成的实验和可调整工艺，提出下一轮 6 组实验。明确成本上限、对照组、选择理由和会推翻当前假设的观察；缺少预测依据时用 DOE，并等待真实结果更新。

English example:

> Search MOOS first for recipes, processing conditions and tensile measurements for carbon-fiber-reinforced thermoplastics. Compare only records with compatible composition bases and test conditions. Save an evidence-linked table, missing-data notes and a reproducible report.

例子为交付目标，不承诺当前 MOOS 一定存在足够匹配数据。

## 10. 优先级与首个可交付版本

1. RA.0 与 LA.0 建立源数据/执行基准，验证最小 Codex 和材料工具共存。
2. RA.1 只读 MCP → RA.2.A 最小接入 + RA.3.A 项目快照 → LA.20.A 材料入口；LA.1/LA.6 最小合同与完成检查同时满足。
3. 获取 MOOS 实验/配方/工艺/性能与合法图证据，交付第一份真实条件化分析表和报告；这时允许发布功能明确的内部预览，不声称 RA 全部完成。
4. LA.19 外部发现/全文与 RA.4 科学检查、RA.5 首批数据分析、RA.6 方法路由共同扩展三个场景；正式预览通过相应 RA.11 子集和 LA.18。
5. RA.7–RA.10 分别通过数据、方法、计算和权限门槛后推进。每项独立发布，不让团队后台/设备自动化阻塞最小价值。

RA.2.A/RA.3.A 是同阶段最小子集，不新增编号。新阶段交付模板：目标/非目标、代码与合同、迁移兼容、权限/预算、金标准/边界测试、真实运行回执、双语说明、产品限制、回退方式。计划勾选必须有证据，不因文档完整而标为实现。
