## 1. 执行规则

- 每个任务交付可审阅代码、适当验证、操作说明、已知限制和下一步；不只提交 UI 演示。
- 每个任务有一个主负责人，跨层功能按纵向切片交付。
- 下表工量 S=1–3 工程日、M=4–7 工程日、L=8–15 工程日，是粗估；外部账号、领域评审和失败返工另计，M0 后重估。
- 只有用户明确要求开始开发后执行实现；本轮交付是计划。
- 默认不提前建立全套空目录、微服务或全部技能占位文件。
- 权限、收费、原始数据保护和科学正确性属于功能验收，不作为上线后的补丁项。

- 企业部署：SSO、内网模型、离线依赖镜像、离线授权、可审计更新。
- 高分子/复合材料深度：更多力学模型、表征流程、工艺窗口、主动学习与实验结果回灌。
- Linux/macOS x64 桌面、完整英文内容、可选同步与多设备。

## 8. 首次开发会话应完成什么

建议执行顺序：MX-001 的样例契约 → MX-002 的 Pi 最小 SDK 验证 → MX-003 的桌面/运行环境验证 → MX-005 的计算包验证 → 记录 ADR。对不依赖用户材料的验证，使用固定公开/合成样例先推进。

第一次实现交付至少包含：

1. 清楚的启动与验证命令。
2. 已锁定的 Pi/运行环境版本和必要许可证文件。
3. 一个实际工具调用、一次取消、一次会话恢复的证据。
4. 当前系统已经验证的结果，以及 Windows/求解器仍待验证的项。
5. M0 工期重估和下一工作包，不把后续所有模块一次性写成占位实现。
