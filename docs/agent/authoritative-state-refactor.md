# 动态能力、状态纠错与回答核对

日期：2026-10-06。归属：统一计划 UA.1/UA.3/UA.4/UA.5/UA.14。状态：共同宿主工程已实现；科研语义与完整模型资格继续按 UA.14 验收。本文件是实现附件，排期和阶段状态以 [统一计划](../UNIFIED_AGENT_DEVELOPMENT_PLAN.md) 为准。

## 问题与实现边界

“模型说没有权限，但应用实际上支持安装”涉及宿主事实、历史状态和答复核对。单纯换提示词或模型不能解决全部问题。共同宿主拥有真实能力和回执；Pi/Codex 继续使用各自原生工具执行循环。此次没有新增 Agent、安装工具执行器或计费账本。

已注册、已配置、已授权、已安装和已验证运行分别记录。例如 Skill 可以已安装但停用，也可以已启用但缺依赖。MOOS 配置存在时连接仍可能失败。势有本地安装元数据也不能直接证明适合当前材料。任务权限和来源/计量规则继续由现有监督器及业务服务检查。

## 数据合同与唯一来源

`packages/contracts/src/capability-awareness.ts` 定义能力快照、来源事实、修订记录及回答核对。`TaskExecution` 增加可选 `awareness` / `answerAssessment`，保存到原 SQLite 日志，沿用版本冲突检查。旧 v1 记录可被新代码读取；旧程序的严格 Schema 不保证可以读取新增字段，因此已有新记录后不要直接降级应用，迁移与发行门禁仍需保留。

| 来源 | 新事实 | 明确不证明的内容 |
| --- | --- | --- |
| 实际方法注册、任务授权、计划与步骤范围 | 当前注册/授权；最近调用与回执引用 | 不证明依赖就绪或步骤依赖已完成；实际派发仍须原门禁 |
| 共享 Skill 安装合同 | 对话安装命令和宿主处理能力 | 能力问答不构成安装授权；不证明任意远程来源可下载 |
| 内置指令文件状态、用户与已安装 Skill 索引 | 实际安装/启用状态 | 不证明 Python/npm 依赖或脚本运行资格 |
| 原受管势的安装记录 | 该运行目录内的安装状态 | 不代表目录中所有资源已安装，也不证明推理正确 |
| 原 MOOS/论文服务实例 | 是否已配置适配器 | 不证明连通性、数据权限或每条记录完整性 |
| 成功的 environment/skill_capabilities 固定结构化回执 | 环境状态、实际扩展启用状态及回执来源 | 任意网页、论文、错误文字和模型声明不能更新权限事实 |

轻量内置 Skill 状态读取复用原目录配置，检查指令文件是否存在；不在每次请求读取完整翻译、例子和 Skill 正文。扩展的原完整性检查保留。宿主事实不含凭据；平台云任务不注入本机私有 Skill/势目录。本地模型路径保留原本机隔离规则。

## 版本与纠错

`TaskSupervisor` 是唯一日志和版本入口。规范化事实生成 SHA-256，事实相同时不增加能力版本；变化后记录新版本及被替代来源。成功回执刷新有限的类型化事实。模型请求末端加入当前状态，原生指令、旧历史和真实回执保留。当前快照优先于旧回复，未知不等于不可用。

完整快照最多 512 项，保存于宿主。模型上下文只传最多 16 项相关事实，并明确标记是局部视图；可用 `task_control {action:"capabilities",query:"skill:frontend-design"}` 获取匹配事实。查询仍有原权限/截止时间检查，不安装任何资源。目录增加超过边界需要分页合同扩展，不能静默丢弃事实。

恢复的 Codex 历史可能包含本轮撤销的命名空间工具。适配层只保留有配对回执的历史调用，别名不加入当前工具声明或回传派发映射；未配对历史显式失败。模型新调用仍须通过当前 Schema、权限和宿主准入。没有重写历史证据或重新执行旧工具。

## 回答核对与科学验收

`task_control {action:"validate_answer",answer:"…",claims:[…]}` 支持两类精确声明：

```json
{
  "action": "validate_answer",
  "answer": "单点能量为 -3.75 eV，结果待科学复核。",
  "claims": [
    {"kind":"receipt","receiptId":"实际本任务成功回执 ID","pointer":"/energy/value","value":-3.75},
    {"kind":"receipt","receiptId":"实际本任务成功回执 ID","pointer":"/energy/unit","value":"eV"}
  ]
}
```

例子只是合同形状，不是已完成计算。实际回执字段位置由原工具决定。JSON 指针基于原对象或单个 JSON 文本回执的解析值；禁止原型路径，不能使用外任务、失败或旧计划的回执。能力声明必须携带当前快照版本、能力 ID、维度和精确值。数字、单位、工况、来源页码应作为分别可核对的标量声明。

回答哈希与声明一起持久化。工具新提交/回执、计划修订及真实状态核对会使旧评估失效。最终返回前重新核对当前回答。系统还检测有限的明确矛盾，例如否认已安装 Skill、把停用 Skill 说成启用、虚构 skill_installer 权限要求、未知操作未结束却说全部成功。

- `blocked`：声明与当前证据冲突，不能按成功交付。本地路径在原会话里最多有限纠正；已完成操作不重提，不扩大授权/预算。
- `claims_verified`：提交的精确声明匹配证据。**不是整段自然语言的蕴含证明**，也不代表科学结论已验证。
- `needs_review`：未提交可核对声明，或只有自由文本。保留已有科学复核与真实文件验收。

此次没有引入另一模型“打分即通过”的循环。旧 UA.4/UA.7 的原始数据、来源版本、真实产物、数值/单位/适用条件检查继续执行。全面自然语言验证、材料因果论证、来源覆盖与领域专家验收尚未完成；不能把此重构称为科研语义全闭环或 Codex 智能等价。

现有执行记录面板显示能力/事实版本、回答核对状态和冲突，并明确提示“事实核对不代表科学结论已验证”。沿用全局主题，没有另加能力管理页面。
