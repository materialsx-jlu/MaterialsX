## 使用方式

打开 **研究数据与交付 → 科学检查与方法**，先在“材料数据”选择来源。

1. “检查选定数据”生成真实 JSON、双语 Markdown 报告，核对原字段、单位、条件、证据、重复与不确定性。报告的“可继续研究”只表示没有当前已知硬阻断，科学结论仍待复核。
2. 在“用来源观测进行分析”选择统计、拟合或验证，添加真实来源观测。拟合需成对 X/Y；验证需提前指定 train / validation / test。
3. 先检查可用性；只有通过硬条件的方法才出现运行按钮。填写选择理由后运行，生成有哈希的 JSON 与易读结果表。原单位/基准不自动转换。
4. 已确认更正、版本更新、撤回或权限撤销时，登记原因和可选替代版本。旧记录保留；受影响产物标 stale。选择新版本、修订同一研究计划，再执行获授权的受影响步骤；系统不会自动重跑。

聊天示例：

> 使用 @materials-research-workbench，先检查选定来源的字段、证据、测试条件和重复数据，再汇总相同单位和含量基准下的强度原值。缺独立重复时不计算标准误，生成真实 JSON 和报告。

> 对选定的含量 X 与强度 Y 做固定线性拟合，先检查成对观测和方法范围，再记录选择理由。报告残差和训练范围，不把斜率直接称为模量。需要预测评测时，提前按来源分组划分训练/验证/测试，并报告训练集均值基线和外推点。

自动执行仍要求模型正确返回工具参数和真实 ID。工具及固定算法的工程通过不证明模型能正确理解所有研究问题。

## 当前支持的数值范围

- 统计：相同属性、原单位、基准和测试条件的有限数值。均值、原值范围只描述选定行，不作为合并文献效应或总体估计。只有来源明确声明 replicate_kind=independent、具有独立 specimen_id / replicate_id、无汇总身份和重复 ID 时计算样本 SD/SEM；不提供置信区间。
- 拟合：至少三个成对数值、非退化 X、对应来源与条件、相同原单位。保留训练范围、斜率原单位、残差及训练 R²；不自动称为模量、因果或材料本构。
- 验证：训练至少三个、验证至少一个、测试至少两个来源组；先保存划分，再仅用训练集拟合。MOOS 同源论文/专利的多个实验不能跨 train/validation/test；投影中的任意 study_id 不能覆盖此身份。重复源观测、缺读证据、混单位/条件、预测值充当真实参考目标、缺能量口径时拒绝。
- 基线：仅用训练集目标均值，分别计算验证/测试 MAE/RMSE；保留逐项预测并标记训练范围外的点。源分组是必要条件，不自动证明独立参考数据、训练集未重叠或领域泛化。
- 原子试算：只路由现 M6 合格任务。真实权重、元素、结构、PBC、物理范围、环境和生产模式门槛仍由原组件检查。模型间一致不代表准确，模型总能量不做未知基准对齐或拟合偏置。

方法接口只支持上述任务和输入。外部 PDE/FEM 求解器、材料本构拟合、任意脚本、原始 CSV/XLSX 处理、拟合区间编辑、复杂图表与独立科学评测不因“可运行”取得本阶段资格。原始实验处理继续归 UA.8，其他科研方法须按范围新增并独立验收。

## 字段与来源回链

research_quality 可提供 claims，包含结论文本、来源类型和 refs：snapshotId、section、rowId、field、evidenceIds；数量结论还包含 quantity.value / unit。宿主从实际快照查找字段与已读证据，数量必须精确匹配至少一个所引用的原值/原单位。合法 ID 回链不证明整句文字、普遍化结论或因果解释正确，因此保留 CLAIM_SEMANTICS 待复核，不宣称科学通过。

本地导入 JSON 的格式继续是 {title, data}，data 中各节为数组。新增对真实 readEvidence[].id 的唯一性检查，并按其实际内容生成应用持有的哈希回执。导入者的证据内容、独立重复声明和来源类型仍属未审核输入，不自动成为 MOOS 或已验证事实。已登记但未真正读取的 evidence ID 不能支持结论或数值分析。

“不同来源在相同已记录条件下报告不同数值”作为待复核分歧，不自动宣布某篇论文错误；缺条件可能掩盖真实差异。未知单位、质量/体积/摩尔/phr 基准、不确定性定义保持未知，不造误差条、排名或单位修正。

## 验收证据

- 全量单元/协议测试：289 项，288 通过、1 项既有跳过、0 失败；覆盖跨项目拒绝、真实字段与数量、不改原单位、缺证据、重复与分歧、来源版本/权限、恢复历史、哈希篡改、符号链接、分组泄漏及硬排除。
- 真正的 MCP SDK 客户端调用共享三工具：科学报告、方法列表/评估、真实统计与文件；使用 Pi 的同一宿主定义和共同 TaskSupervisor，拒绝无授权或被排除方法。没有用脚本模型冒充真实 LLM 理解。
- 数值独立参考：Python 隔离标准库 statistics.linear_regression / mean / stdev，12 组合成数据、84 个不同数值字段、三次独立运行共 252 次核对。绝对容差 1e-10，最大绝对误差约 7.11e-15。这是算法数值验证，不是材料性能或科研事实的专家验证。
- 真实 M6：已有硅晶体样本、真实 CHGNet 0.3.0 权重 SHA d14ab7c0f093efe64b60a7bcd540bca10e74fb7f46c86108a079af60524659d1，经新方法目录委托原 M6 资格检查后，以原作业入口完成 8 原子 CPU 单点；总能量 -42.4974365234375 eV，真实结构/结果/验证报告哈希保留。该值仅证明文件链和模型计算，未与独立 DFT 比较，正式生产模式仍被拒绝。
- Electron：真实本地 JSON 导入和证据哈希、IPC、方法配置/运行、报告预览、中英文、820/1600 宽度和全局主题、来源更正影响通过。UI 验收数据是团队合成样本，不是实验测量。
- 类型检查、构建、单文件 600 行限制通过；当前自有源文件最大 586 行。原 3Dmol eval 与大包构建警告继续保留。
- 本轮没有调用付费供应商、下载新模型或修改发行版本。原主模型 gpt-oss-20b 的多步工具和语义限制不因数值后端通过而消失；Windows/专家审查仍未通过本轮资格。

原始验收回执在被 gitignore 排除的 runtime/agent/ua-7。真实结构探针和桌面探针均使用临时状态/项目目录，结束删除；不修改现有科研项目或账户。

## 清理与保留边界

原 research-delivery 中科学规则已拆到 delivery-science，保留公开兼容入口并复用同一合同；文件完成与领域质量各有职责。抽出原 M6 物理需求检查复用，删除分散实现；训练均值复用同一数值函数，没有再造 Agent、模拟 worker、下载器、MCP 客户端或数据库。工作台 Skill 版本更新到 UA.7.0，不新增重复 Skill。

来源更正/撤回目前来自 MOOS 已知版本/权限回执和用户核实后登记，不是全网自动撤稿监控。arXiv 文本/元数据、外部引用还需先通过现 RPSME/项目输入形成可核对的研究快照；任意读过的网页或截图不会自动变成科学事实。直接图像结论与全网更新监控继续按 UA.10/UA.11/UA.12 推进。

当前约束、数值方法和引用可用性依赖完整输入，未知科学条件仍可能存在。自然语言语义、材料适用性、跨方法因果或实际实验验证必须独立验收；productionApproved 始终 false。本轮没有改 M5 计费/平台外发授权，云端/远程 MOOS 继续按 UA.13。

方法选择默认采用与现有执行引擎同一模型；没有“成功率”或准确性排名，没有强行更换模型。无合格候选时交付真实限制，不能把工程检查包装成科研可靠性认证。

方法参考：拟合与残差定义参照 [NIST least squares](https://itl.nist.gov/div898/handbook/pmd/section4/pmd431.htm)；来源分组及训练/测试隔离参照 [scikit-learn cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html) 与 [data leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html)。这些是方法设计参考，本阶段没有新增 scikit-learn 依赖。
