# AP.4：针对原因的恢复

日期：2026-10-06。对应 UA.3 / UA.5 / UA.6，复用原执行引擎、TaskSupervisor、工具注册表、授权、journal 与 M5 请求账本。

## 实现

共同错误合同增加 `recovery`：失败类别、拒绝/已执行/在途/未知阶段、下一步动作、原工具与回执 ID。参数错误携带实际注册 Schema 和最多八个字段位置、期望类型；不回显非法参数值，不删除业务字段，不制造来源或作业 ID。旧持久记录无需迁移；旧适配器错误仅在边界兼容模块解释，核心恢复决策使用类型而非错误措辞。

| 故障 | 原循环中的处理 | 保持的边界 |
| --- | --- | --- |
| 参数或响应格式 | 尚未执行的调用提供准确字段要求，在同一引擎会话纠正 | 完整终态、Schema 与原授权通过后才执行 |
| 连接/响应流中断 | 区分模型服务/网关传输故障，核对原请求 | 不误报为本地服务故障，不直接进入格式修复或付费重放 |
| 脚本失败 | 返回实际 stderr、退出码和原回执；读取源码，授权内修改，再运行并读回产物 | 同样失败的命令没有成功修改/受管修复回执时禁止重放 |
| 环境缺失 | 已知非零退出或受管适配器报告；提示原 environment_check / environment_repair | 原锁定依赖、沙箱、独立环境和失败回滚；不任意安装 |
| 来源不足或能力不可用 | 补本轮批准来源，查询当前能力与真实 Schema；无法补充则说明缺口 | 目录收录不等于安装、调用成功不等于科学有效 |
| 作业未完成 | 根据原 pendingJobs 的真实 ID 查询或取消 | 不提交第二个计算 |
| 写入或付费结果未知 | 原任务/请求/账本先核对 | 不重放，不释放未知预留，不增加付费请求 |
| 权限、预算、物理范围 | 明确停止，保留实际文件和来源证据 | 不扩大 grant、期限或科学支持范围 |
| 交付未完成或回答冲突 | 用原监督器检查实际待办和产物，纠正与证据冲突的声明 | 模型声称完成不能代替文件、来源与真实终态 |

脚本修复仍由引擎选择原工具执行。环境修复仍由已有受管模块执行；没有另建 Agent、脚本自动补丁器或安装器。无有效终态的原生请求继续保持未知；格式错误并不意味着可以免费重试。

Codex 原单操作屏障保留，并在初始引擎说明和实际原生工具描述中明确“每响应至多一个原生操作”；不等到拒绝后才提示。失败脚本即使因版本修订标记 stale，输入指纹未变且没有真实修改回执，仍禁止原样重放。

每段没有真实产物进展时最多两次响应纠正，全任务最多八次。只有宿主核验完成步骤的文件路径、SHA-256、字节数出现新证据，才开启下一段；读操作、模型声明、版本变化或旧步骤失效不重置。失败工具执行另限初次执行加两次纠错、全任务最多八次失败；历史失败不会因重规划变成 stale 而消失。纠正预算写入同一 journal，重启、恢复或引擎交接不能绕过；原时间、模型请求和积分预算继续约束。

拒绝的 MCP 参数和外层响应修复使用同一持久计数。已经成功的修改保留原回执缓存；未知操作和在途作业未核对前不会进入响应修复。被拒绝的调用没有执行记录。技术验收失败保留此前已完成的文件，不能自动删产物或把失败响应改写成成功。

本地请求状态 failed 不代表平台采购/积分结算已完成。付费失败请求须经原 M5 `refreshSnapshot` 确认 settled/released/not_billed，且有可靠终态或确认未发出，才能标记 `reconciledAt`；否则同对话新任务仍被阻止。查询只更新原请求 ID，不增加模型调用、不释放待核对预留；结算确认本身也不授权模型重试。

运行记录增加可折叠的双语恢复记录，展示原因、纠正次数、原回执、退出码和作业 ID，采用全局主题。恢复预算耗尽时恢复/交接按钮禁用，后端同样拦截；核对原回执仍可用。终止消息区分脚本、参数、科学范围、预算和未知结果，不统一归为“模型调用失败”。
