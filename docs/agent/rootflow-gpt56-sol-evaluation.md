# RootFlowAI gpt-5.6-sol 实测报告

日期：2026-10-06。环境：MaterialsX 当前开发源码、macOS ARM64、Pi 0.99.1、独立 Codex App Server 0.160.0、真实 RootFlowAI Responses/SSE、隔离 PostgreSQL 账户服务。

## 结论

这套接入能完成普通材料设计咨询、读取批准的文件、进行简单质量核算，并表现出修改代码的能力。但当前计划驱动的科研执行仍未闭环；更换为 gpt-5.6-sol 不能自动消除 MaterialsX 的意图路由、计划执行、协议适配、运行环境和交付问题。

短问题“如何设计水性制冷涂料”在实际桌面运行链路中由两个引擎分别完成。下面的压力测试及对照是不同路径，不能混成一个成功率，也不能据此量化它相对 gpt-oss-20b 或本会话 Codex 的智能水平。

## 故障与下一步

1. **咨询意图误判。** 当前 advisoryQuestion 对“实测”等词直接匹配，连“不虚构实测性能”也会退出咨询路径。需识别否定与约束，让缺失参数限制具体配方，而非阻止一般建议。
2. **计划与工具调用不一致。** Codex 压力测试多次因当前步骤依赖不匹配被拒绝，尚未执行实际业务工具。需要按真实候选和步骤回执纠错，不能通过放松权限或跳过验收来制造成功。
3. **Pi 后续轮次错误不透明。** 复现中 task_control.begin 已返回，下一次 SDK 报 Connection error；仅前三次请求有已完成回执。尚未确认是请求序列化、本机准入还是连接环节，应先记录脱敏的失败阶段和 cause，不能把它断定为模型推理不足或上游已重复扣费。
4. **供应商输出上限契约。** 本轮请求上限为 3072，实际回执出现 5178 和 3852 输出 Token。现有网关据此拒绝完成；Pi 随后显示“流用量与账本不一致”，掩盖更早的失败。应核验供应商如何执行 max_output_tokens 和统计推理用量，并区分输出越界、终态失败、未知用量与真实数值不一致。保留预算检查。
5. **云端纠错不完整。** 当前若干同引擎修复能力只在本地模式启用，云端不能自动沿用。应只对未执行的参数错误、已确认回执的计划问题做有界修复；回执未知的请求不得重复提交。
6. **运行环境事实。** 原生测试中的系统 Python 被 xcrun 阻塞。应统一提供且探测实际解释器，向引擎给出受管 Python 路径；在依赖不可运行时准确说明阻塞，不能把备用计算或写出正确 JSON 冒充原脚本成功。此处是源码测试环境，未覆盖安装包的完整环境引导。
7. **耗时和上下文。** 同类内容出现明显耗时差异；原生修复多次模型请求累积大量上下文。后续需分解排队、模型生成、工具运行和验收耗时，减少无关工具/历史，同时保留权限、状态和必要证据。

## 测试边界、数据和费用

- 固定材料数据是明确标注的 synthetic-test-data；100 g 湿质量、50 g 固体质量，放大 250 g 时应为 125 g 固体。它不是已验证配方。
- 每轮上限：16 请求、每次 3072 输出 Token、300 秒。结果是这一配置下的观察；没有证明其他预算设置或供应商线路的结果。
- 使用测试自有数据库和账户；没有操作生产钱包、支付、订阅，也没有导出 MOOS 私有配方、论文或用户研究文件。云端 MOOS 能力仍受现有数据授权与工具接入限制，模型更换不会自动打开。
- 已确认账本用量（包括失败但有用量的请求）：输入 517,515 Token、输出 38,726 Token。部分请求回执未知，另有两次极短的直接协议探针没有完整用量，故这些数字不代表全部采购用量。
- 供应商 API 发生真实消耗；MaterialsX 隔离账户采用 alpha-test，不代表供应商免费。未获取实际采购费率/账单，不报告或推算人民币实付金额。
- 极短直接探针的一次元数据解析错误和一次 HTTP 异常保留在 runtime 中，未用于评价科研能力。
- 初版基础固含断言漏识别 `50 wt%` / LaTeX 百分号，原生修复测试漏采集 `receipt` 事件。保留初版报告并说明人工复核；仅补跑修复，不将修复测试本身的缺陷归因于模型。
- 本轮只增加测试脚本与报告；没有替换执行引擎或修改应用业务代码，也不代表已发布安装包。
