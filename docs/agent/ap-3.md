# AP.3：中英文能力与工具发现

日期：2026-10-06。对应统一计划 UA.1 / UA.5 / UA.7，继承 AP.1 / AP.2 的任务监督、权限和真实回执。

## 实现

现有 Codex `hostRouter` 和 Pi 工具激活共用本地词项/同义表达排序。补充现有工具的双语用途、输入/输出及短例子；描述性注释不注册工具，也不存放另一份 Schema。没有增加向量服务、模型下载、分类模型或新的 Agent 循环。

`find_tools` 接收中文/英文用途或准确工具名。默认最多八项概览；`includeSchema:true` 返回原注册表中的准确参数，自然查询最多三份 Schema，准确名字只返回该工具。未授权工具只解释状态，不暴露其 Schema、不执行。没找到、未安装、未配置、未授权、调用已验证、运行尚未验证分开表示；验证仅指当前回执范围，不证明其他输入或科学精度。

初始最多六项相关能力，加上 Skill 入口、实际存在的已选附件读取器及最多三项当前计划方法；后续方法仍按需发现。Codex 后续用原 `invoke_material_tool` 分发，Pi 沿用下一次请求激活原工具的机制；原参数校验、步骤依赖、授权、预算、取消和 journal 不变。常驻能力投影最多六项简要事实，按名称查询最多十六项完整事实。目录增加不会把全部 Schema 或全部 Skill 说明加入每轮请求；现有能力事实合同仍有 512 项注册上限，完整势/Skill 目录用现有搜索分页访问。

Skills 与机器学习势目录共用排序，展示双语说明和例子。按需读取 Skill，每次最多 200 行，返回 SHA-256、实际行范围和是否部分读取。常见的 1–200 行请求在短文件处读到末尾，仍拒绝超过 200 行、反向范围和越过末尾的起始行。显式所选说明固定快照；自然选择的说明在当前 reader 首次读取时固定，下一任务的新 reader 会核对新版本。附带资源继续走现有 `skill_resource`，依赖另行检查。删除旧整句 includes 发现和独立初始关键词选择；保留旧调用者的小型兼容视图。

势目录先进行原元素、周期性、任务类型和受力能力过滤，再排序。准确点名的 checkpoint 被排除时不能悄悄换成其他势；家族名仍可列出相关权重。实际运行继续检查安装、平台、元素、电荷/自旋、长程物理及科学适用性。语义匹配仅生成候选。

## 类型明确的引用

输入 `@` 可选择 Skill、附件和当前项目已有的配方来源、论文、结构；兼容 `@pymatgen`、`$Skill`、`/skill:Skill`。也支持：

```text
@file:"Si sample.txt" 检查这个已选文本。
@paper:"arxiv:2601.12345v2" 阅读已注册论文的指定页码。
@recipe:"<本项目已选来源 snapshotId>" 核对原始用量与证据。
@structure:"<已导入结构 ID>" 检查是否满足本轮分析条件。
```

后端绑定已批准对象的真实 ID、项目、版本与哈希，作为原计划输入版本和原监督器的说明，不改写用户目标。文件沿用同一附件入口，本地与平台模式都可使用；只接收项目内、每个最多 32 KiB 的 UTF-8 文本快照，凭据和越界链接拒绝。重名附件需选择唯一 ID。Skill 必须实际安装、启用且可读；明确点名不存在的说明会提示原因，不自动猜一个替代品。

普通引号、行内代码、代码块、邮箱中的 `@` 不绑定。类型明确的引号可容纳文件名中的空格。单轮最多十六项引用、最多八项显式 Skill。跨项目、不在附件清单、未选入研究范围、已撤回或变更的来源拒绝。论文元数据与已读文本页分开；图片未审阅不能宣称已读。结构摘要不增加计算授权；没有原科学范围时仍显示未授权。MOOS 云端外发维持关闭，引用不会绕开独立授权。

输入框按需展开 ID、版本和读取范围。文件显示已冻结 SHA；Skill/结构在发送前仅展示“发送时固定版本”，不会把未完成的绑定伪称为已核对版本。界面使用全局主题与现有列表样式；窄窗口受应用原最小宽度限制。
