# AP.1：任务理解、探索与计划展开

日期：2026-10-06 · 状态：开发实现及本阶段回归完成，尚未更新安装包。

MaterialsX 使用当前选定引擎的原会话决定回答、读取证据或执行。默认仍为独立分发的 Codex App Server，平台路由 `materials-research` 对应 RootFlowAI `gpt-5.6-sol`。没有新增分类模型请求、第二个 Agent 循环或研究状态库。Pi 保留显式选择和既有兼容路径；本阶段真实云测试只覆盖 Codex。

## 行为与实现

- **简单任务直接处理。** 主运行入口创建探索态合同，不再因“设计”“分析”、数字、文件名或未知关键词强制先调用解释模型。数字目标可以用于咨询，不自动变成计算指令；询问如何生成文件不等于要求写文件。“能安装 Skill 吗”依据当前能力回答，“安装 Skill …”继续通过已有宿主安装入口执行。
- **先读取，再展开必要计划。** `task_control action=plan` 返回现有合同与实际注册、授权的方法；模型在原会话提交 proposal。材料计算、统计后端、下一轮实验设计、管线提交和子任务在正式计划确认前由宿主挡住。文件修复等有限任务可直接执行，其原生权限和范围检查不变。
- **计划沿用同一任务。** 探索转计划保留已成功的只读回执、任务/输入版本、原始请求、权限、预算、截止时间和验收产物。执行过可能写入或终态未知的操作后，不允许重新解释目标；后续修改不能放宽既有限制。读取回执不能冒充计算结果。
- **缺条件只阻断相关计算。** 缺密度仍可读取配方、计算有真实依据的质量固含，不能编造 PVC；原生能量/受力的未知输出 `value=null` 可以保留单位，不要求用户先给出数值目标。需要实际计算的输入仍严格校验。
- **交付覆盖用户要求。** 明确请求的命名文件进入同一验收合同，计划不能删掉；有限文件任务需要真实成功写操作和实际文件，不接受文字声明或旧文件加读取回执。未完成时复用原会话的有限恢复，保留成功操作，不重放写入。
- **来源配方与建议分开。** 现有 MOOS 续接入口读取本轮冻结配方。请求三个建议时，必须有三个不同的真实建议回执；改名或只换验证项目不算新方案。同名修订以最新版本交付，原回执仍保留。原始用量、单位、证据页码与建议用量分别显示，建议保持未验证状态。现有聊天建议入口只支持其 Schema 声明的数量/工艺选项，超出范围不悄悄缩减。
- **能力状态由宿主提供。** 云端也接收公开的 `host:skill.install` 事实，说明用户命令、安装边界及网络/来源限制。该投影不包含本机 Skill/势库存、私有 MOOS 或服务配置。已有事实足够时直接回答；简单回答由现有最终宿主校验检查，不强制再调用 `validate_answer`。复杂精确声明仍可显式核验，叙述及科学有效性不被自动认证。

主要文件：`packages/agent/src/task-understanding.ts`、`research-planning.ts`、`requested-artifacts.ts`、`task-supervisor.ts`、`model-recovery.ts`；桌面沿用 `agent-runtime.ts`、`application-capabilities.ts`、`research-recipe-*`。`execution-control.ts` 公开同一 plan 动作。云端 Skill/文件工具提示已统一到实际 Schema 的 `id` 字段。

删去未知请求默认强制计划、咨询任务一律关闭工具等旧门槛；共享可能写入的工具判断，删除重复实现。原本仍有消费者的显式计划/Pi 兼容路径保留。所有自有代码仍满足单文件不超过 600 行，本次监督文件 511 行、桌面运行文件 572 行。

## 验证记录

`npm run check` 通过核心/桌面/后台类型检查及自有代码大小检查。`npm test` 共 **486 项：485 通过、0 失败、1 跳过**。跳过的是独立真实 PostgreSQL 身份服务的系统浏览器回调、凭据库重启与设备退出测试，环境未配置；不是本阶段云测试所用的隔离 PostgreSQL。

旧五项路由预期失败已逐项审查，补充了中英文咨询/否定/混合意图、缺条件允许安全读取、计算执行前准入、同任务转计划、约束不可放宽、实际产物和重复建议等保护测试。未通过修改断言取消权限或交付检查。

真实测试复用 `scripts/agent/rootflow-evaluation.ts`，经过桌面运行入口、MaterialsX 独立 Codex、原 M5 网关和隔离 PostgreSQL。只使用合成涂料数据及公开硅结构；真实供应商调用有实际终态和 Token 回执。生产钱包改动、支付均为零，没有外发私有 MOOS 数据。采购费用未知，不根据 Token 回执编造人民币金额。

失败原始答案、文件、校验、调用及 before/after 指纹保留在忽略目录 `runtime/agent/ap-1/`，不会自动提交或打包。构建/UI 原始日志在 `runtime/agent/`。最终桌面构建及隔离 UI 核验覆盖实际加载身份、默认云端/Codex、六个页面、零模型/支付调用；文档更新后重建并重新核验身份。
