# AP.5：跨轮研究上下文与交付核对

日期：2026-10-06。对应 UA.1 / UA.4 / UA.7 / UA.11。工程实现完成；真实供应商验收与科研专家复核单列，不承诺任意任务都能自动完成。

## 实现

上下文是原 TaskExecution 的可选 `workingContext` 字段，仍保存于 WorkspaceStore 的 AgentJournal。没有增加数据库、执行循环、付费请求或自动 LLM 评审。Codex 为默认引擎；Pi 仅保留原兼容接口。

- 自然追问“上述配方 / 这个结构 / 这篇论文 / 这个文件 / 继续”按同项目、同对话、同账户、同团队授权范围查找真实记录。显式对象优先；存在多个单一对象时列出 ID 并要求选择，不猜一个去计算。不相关问题不主动注入历史。代码块、普通引号内的引用提示不触发继承。
- 原项目绑定、来源快照、实际工具回执和已验收产物形成清单：ID、版本、SHA-256、读取范围、工具省略情况、原任务 ID、来源/产物变更通知，以及 local-only / approved-cloud 范围。搜索/选择元数据不能计作已读证据。
- 批准的文本附件保存为原日志中的不可变内容对象（不是执行回执），本地追问和重启后可恢复，用原 read_material_file 按行读取。恢复核对原账户、对话、项目授权、内容对象指纹和文本 SHA。云模式不自动恢复外发选择；仍要求本轮明确选中的输入，历史原回执查询不开放云外发。
- `currentWork` 从原计划与当前步骤生成：当前目标、有效约束、输入、事实、缺失、假设、已完成步骤、阻断与下一步。状态、计划、压缩和恢复共用同一份清单。没有用模型摘要制造回执，也没有把旧任务完成计作当前步骤完成。
- 清单按模型窗口投影元数据，省略记录有计数、原清单指纹和历史请求哈希。大证据通过原工具继续分页/分段读；当前用户约束、权限、工具 Schema 和当前调用配对仍保留。超出窗口时明确停止，不截掉硬约束。修正旧压缩检查点累积/重复附状态的问题，原引擎仍保有完整历史。
- task_control 原 receipt 动作增加可选 sourceTaskId，只能查清单列出的历史成功回执；按原存储读回，64 KiB 超限提示改用原来源工具分段读。无当前 read 权限、来源失效或跨范围请求拒绝。历史回执不参与当前完成验收，不能用于重新执行旧副作用。
- 每次原监督器持久化、请求摘要和最终检查重新核对来源变更/撤回及历史产物。变更保留旧版本并提示影响，不悄悄换成新来源。失效/歧义上下文阻止计算与写入，保留只读检查。原科学后台依旧负责来源权限和领域约束。

## 交付核对

原 AnswerAssessment 保留当前能力版本/标量回执事实核对，增加 measurement 声明：同一真实成功回执的 valuePointer、unitPointer、sourcePointer 必须分别对应所报数值、单位、来源；不进行隐式单位换算。任意自由文字的科学解释仍不能据此标为已验证。

实际 Markdown 文件链接检查项目边界、文件存在和已验收内容指纹；代码示例中的链接不作为交付声明。结束时再次核对所有原步骤验收文件，防止“验收后又删除/改写文件”。已有配方后台继续要求实际读取来源、distinct 建议回执以及原始单位，不能用文字声称代替真实建议记录。

`deliveryAssessment` 分别保存技术 complete / partial / incomplete 和科学 needs_review。必需文件缺失、步骤/在途回执不完整仍阻止成功；needs_review 不会掩盖技术错误。执行记录使用全局配色展示缺失产物、读取范围/遗漏、版本、授权范围和关联任务；能力与科学状态分开。

## 限制与回退

引用提示覆盖常见双语表达，并非任意代词的语义识别器；疑义应明确选择对象。旧任务无已存的工作清单时可使用原配方绑定/已核实回执，旧内存附件无法倒推全文，需要重新选择。核心不会自动认证自然语言里的每个科学数字或全网引用；精确声明和原领域后台做确定性核对，复杂科学解释需要专家审阅。

撤回/修订不会自动替换或重算；必须选择新的真实输入，复用原计划修订、回执核对和预算。历史查询不会扩大旧授权。长上下文不能容纳必要指令/当前证据时仍会明确报预算不足。

新增字段可选，旧日志兼容。回退需先停止活跃任务并保存原数据库与当前完整构建；不能将已改变来源/文件的旧日志标成功或重放未知任务。本阶段不替换已安装应用、签名、打包或发布；AP.6 仍负责重复供应商批次及安装包闭环。
