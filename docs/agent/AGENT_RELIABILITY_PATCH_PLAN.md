# MaterialsX Agent 任务理解与执行可靠性补丁计划

版本：1.2 · 日期：2026-10-06 · 版权：© 2026 吉林大学 AI-DAOS 团队。

本次修订吸收工具调用、行动与观察循环、语义选择和显式引用建议，明确协议、上下文和完成条件。保留现有执行架构；不依据通用 Agent 示例推断 Codex 的内部实现，也不以过时的模型推荐代替本项目实测。

本计划是 [统一开发计划](../UNIFIED_AGENT_DEVELOPMENT_PLAN.md) 的修补清单，沿用 UA.1、UA.3、UA.4、UA.5、UA.6、UA.14 的主实现，不新建执行引擎、工具循环、计费服务或研究状态库。后续可以按 AP.0–AP.6 逐项实施；每项通过自身验收后才进入下一项。

## 1. 目标、范围与当前证据

目标：用户用自然语言提出材料问题，系统正确决定直接回答、查资料、使用 Skill、执行代码或调用材料后端；遇到可修复错误能够在授权与预算内继续，最终交付真实结果。科学候选、技术完成、科学适用和实验验证分别展示。

当前已有原生 Codex 工具循环、研究目标合同、版本化能力事实、任务监督、有限恢复、M5 请求/积分账本、MOOS MCP、材料计算与产物验收。本次完善这些能力的衔接，不宣称它们都不存在。

AP.1 已移除主入口的未知请求强制计划，按原会话探索并保留合同。当前主要剩余缺口：模型仍管理部分内部步骤/版本/回执；工具发现依赖字面子串；恢复依赖错误字符串；跨轮引用仍需更可靠地绑定真实对象；缺少同条件重复实测与安装包一致性验收。

[前次真实测试](codex-rootflow-chain-closure.md) 五类任务分别复测成功，但不是同一批次 5/5，不是长期成功率。失败批次、供应商耗时波动、未知终态必须保留。接入 Codex App Server 或使用同名模型，均不证明与 Codex 桌面产品能力一致，也不证明中转实际模型身份。

## 2. 默认模型与运行边界

- 默认执行引擎：MaterialsX 独立分发的 Codex App Server；本轮主线只测试 Codex。
- 默认模型来源：联网平台模型；M5 公共路由 `materials-research`，服务端映射 RootFlowAI `gpt-5.6-sol`，Responses/SSE。公共路由 ID 和上游模型 ID 不混用。
- 新安装默认上述组合；旧配置首次升级一次性切换上述组合并保存旧设置。之后用户手动选择本地模型/Pi 时，重启保留，不每次覆盖。
- 本地端点、协议、上下文/输出选项、任务积分上限保留；运行中的任务继续使用自己的冻结连接和价格版本，不因全局设置改变。
- 启动选择模型不触发生成请求、扣费、上传文件或自动外发 MOOS 数据。不把“已选平台模型”显示成“已连接/已授权”。
- 未登录、网关未配置、无额度、网络不可用时提供准确状态和下一步；不悄悄切换模型、引擎或收费账户。
- 供应商密钥仅由服务端/本机私有受限配置持有，不进入桌面默认值、文档、日志或发布包。不恢复产品 BYOK 路线。

## 3. 共用工作合同

在已有合同中增补必要字段，以任务 ID、项目 ID、来源版本和真实回执关联，不另外保存竞争状态。

| 合同视图 | 必须表达 | 所属原实现 |
| --- | --- | --- |
| 任务理解 | 主目标、问题类型、请求产物、所指输入、缺失条件、假设及理由；可含多个意图 | UA.1 研究目标与计划 |
| 下一步 | 直接回答/查资料/执行/需要补充/受阻，选择理由；每轮允许依据新证据修订 | UA.1 / UA.3 原会话 |
| 能力 | 注册、配置、安装、授权、实际就绪、来源和版本分别表达 | UA.1 / UA.5 现有能力事实 |
| 执行状态 | 原生操作、实际退出码、运行中 job、回执、文件哈希、预算和未知请求 | UA.3 监督与日志 |
| 恢复建议 | 结构化错误类别、是否有副作用、可重试性、所需证据和允许的修复动作 | UA.3 / UA.6 |
| 交付 | 请求产物覆盖、证据引用、已知限制、技术终态和科学复核状态 | UA.4 / UA.7 / UA.14 |

语义决策由模型依据用户目标与上下文作出；权限、费用、科学参数、工具 Schema、真实文件与副作用判断由宿主执行确定性校验。模型不能通过修改计划扩大授权或改写验收标准。

### 3.1 一个执行循环，明确协议与责任

以下是 MaterialsX 的目标设计。已有能力继续复用，未实现的显式引用和上下文细节按后续阶段验收。

~~~text
用户自然语言 / @Skill / 文件与数据引用
    ↓
MaterialsX：解析引用，组装相关上下文与当前能力事实
    ↓
选定引擎：默认 Codex App Server
    ├─ 直接回答
    ├─ 授权内探索 → 根据观察继续决策
    └─ 复杂研究 → 建立或修订同一研究目标与执行计划
    ↓
原生工具调用 → 宿主校验权限、参数、依赖与预算 → 原工具执行
    ↓
真实输出与结构化回执 → 更新同一任务状态 → 返回原引擎
    ↓
原引擎继续 / 请求必要信息 / 提交交付 → 宿主验收或保留未完成状态
~~~

1. **工具调用是协议事件。** 函数工具采用声明的 JSON Schema；原生自由文本工具按其自身输入协议处理。宿主匹配工具名、调用 ID、参数和结果，不从“思考：我要运行……”或 Markdown 命令块中提取命令执行。UI 的“正在运行”必须来自真实执行事件。
2. **观察进入原会话。** 保留工具调用与结果的对应关系、失败信息、截断标记及协议要求的模型状态。流式参数未完整接收前不执行；未知工具或不合法参数先返回可修正的错误。模型修正仍经相同校验，不能借修正忽略业务约束。
3. **行动与观察循环复用引擎。** ReAct 是理解这种行为的概念，不要求输出私有思考过程；用户看见必要的行动说明、实际进度、证据与结论。MaterialsX 监督该循环，不再实现另一套 LLM while-loop。
4. **模型结束不等于任务完成。** 纯咨询可以直接交付；执行任务只有必需产物、回执和约束均满足才完成。无工具调用但缺产物，应在原会话内有限恢复或报告未完成。需用户补充、运行中、结果未知和失败均有独立状态。
5. **不叠加框架。** 当前不引入 LangGraph/AutoGen 再编排 Codex 或 Pi。未来可评估 LlamaIndex 等作为检索适配组件，但必须有明确收益，复用原来源 ID、权限和上下文合同，不能形成第二份会话、计划或完成状态。

上述工具协议依据 [OpenAI Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)；保持简单架构和重视工具接口的方向参考 [Anthropic 的 Agent 工程建议](https://www.anthropic.com/engineering/building-effective-agents)。本项目的阶段安排、权限和验收要求是 MaterialsX 的工程选择，不是这些资料对其可靠性的保证。

### 3.2 显式引用与自然语言选择

当前已有 @Skill；下表中文件、数据和结构的输入引用是待实施要求，不能提前展示为已支持。

| 输入方式 | 应表达的意图 | 处理与边界 |
| --- | --- | --- |
| @已安装 Skill | 优先依据指定方法处理任务 | 绑定实际安装版本；加载说明，附带资源按需读取；引用本身不授予执行权限 |
| @文件或附件 | 指定任务输入或证据 | 选择器绑定受权路径/文件句柄、类型和版本；限定范围读取，不默认塞入整个文件 |
| 配方、文献、结构引用 | 指定研究对象 | 绑定真实对象 ID、版本、来源和项目；不能把搜索快照 ID 代替记录 ID |
| 普通自然语言 | 模型依据目标选择回答、探索或方法 | 使用相关历史与就绪能力；关键词和语义检索提供候选，不能作为最终任务判定或授权 |
| “能安装吗”与“安装这个 Skill” | 能力咨询与实际操作不同 | 前者依据能力事实回答，后者进入既有安装流程；引用名称或讲解命令不等于要求执行 |

- 引用解析生成类型明确的上下文项，不只用正则匹配后直接读文件。含空格路径、多个引用、代码块/引号中的 @、不存在的资源和跨项目引用都有明确处理；无法确定的引用不得悄悄换成另一个对象。
- @Skill 固定本次使用的安装版本与来源；未安装时显示准确状态。仅在用户有安装意图及相应授权时安装，不因提及名称就下载。Skill 说明是方法指导，不可覆盖宿主权限、预算和用户要求。
- 文件先识别类型与大小，再选择文字分段、PDF 预处理或受支持的图像输入。上下文记录读取范围、截断与遗漏；大文件通过检索和定向读取补足。秘密文件、越界路径、符号链接和云端外发沿用既有保护，不增加无条件读取入口。
- 上传/读取与外发是不同授权。选择平台模型不会自动把本地文件或 MOOS 内容发送出去；只在原外发授权范围内装配请求。
- 自然语言选择由当前引擎在原会话内完成，不强制先调一个分类模型。若未来引入向量排序，只用于发现候选工具/Skill/数据；低置信度可探索或询问，多意图不能被一个类别吞掉。
- 自然语言与 @ 对同一能力共用一个执行入口、权限判断和回执。@ 可以缩小候选范围，不能保证模型理解正确，仍需语义验收。

### 3.3 上下文按需加载

复用 UA 的上下文、来源和能力事实，按“概览 → 选定说明 → 需要的资源/证据”逐步加载。Skill 的渐进加载方向参考 [Agent Skills 文档](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)，具体限制由 MaterialsX 的模型窗口和测量决定。

上下文清单至少记录：用户当前目标与有效约束、相关历史摘要、选定引用及版本、证据范围、能力就绪状态、已完成动作与阻断、预算余量、读取/截断状态。工具 Schema 是调用规范，Skill 是方法指导，MOOS/论文是证据来源，三者不互相替代。

仅列当前授权项目的必要目录和关联文件，不默认扫描整个磁盘。当前打开文件只在已有附件/应用上下文权限内使用，不隐式监控屏幕。压缩历史时保留用户限制、真实回执和未完成事项；摘要不把假设升级成事实。外部文件、网页与检索结果中的指令视为来源内容，不能改变权限或系统行为。

## 4. 实施阶段

### AP.0：默认配置与可复现基线

归属 UA.0 / UA.5 / UA.14。状态：默认配置、基线采集与开发构建身份检查已实施；一次真实诊断批次已有记录。AP.0 时的 AP.1 回归失败保留为历史证据，已由后续阶段修复；重复稳定性和发行验收未完成。见 [AP.0 实施与基线](startup-cloud-default.md)。

工作：

1. 共用模型默认值；一次性迁移旧配置，事务写入备份、设置和迁移标记。缺 engine 的设置保存也默认 Codex。
2. UI 明示 RootFlowAI / gpt-5.6-sol；区分选择、账号连接、额度、网关就绪和任务授权。
3. 复用 UA.14 指纹和评测脚本，冻结当前源码、引擎、协议、供应商路由、工具权限、样例和预算。确认开发进程/安装包是否实际载入相同构建。
4. 分别测首次反馈、首个内容、计划解释、模型等待、工具执行、恢复、验收与总耗时；不能把供应商等待全部算为宿主开销。

验收：新安装与旧本地配置均选云端/Codex；旧配置有备份；用户后续本地选择重启保留；写失败整体回滚；启动不发生成请求。基线原始失败保留，实际构建身份可追溯。

### AP.1：理解任务，先探索再展开复杂计划

归属 UA.1 / UA.3。状态：开发实现和阶段回归完成，见 [AP.1 实施记录](ap-1.md)。安装包及重复稳定性资格仍归 AP.6。

复用 `research-planning.ts`、`research-intent.ts` 及现有目标解释，不再增加独立意图分类 Agent。

- 以当前消息、相关历史、明确授权、实际输入和能力事实决定下一步，避免单独一句话关键词作为最终判据。
- 使用第 3 节的共用合同，在原会话中表达目标、引用、缺失条件和下一步；不增加独立分类请求或强制输出私有思考。能直接完成的任务不承担完整研究计划的管理成本。
- 纯咨询直接回答；查找/读文件先检索读取；复杂依赖、长时计算或高成本任务才展开正式计划。未知请求可先做授权内的只读探索，不能因此授予额外权限。
- 探索态与确认后的执行计划明确区分；从探索展开计划时可细化方法和依赖，但必须保留原目标、约束、已完成动作和请求产物。高成本计算及多步研究依赖宿主准入，不能只靠提示词要求模型自律。
- 将“能不能安装”与“请安装”、“如何设计”与“执行优化”、“禁止执行”与“执行”区分；一个请求可包含查资料和产出建议。
- 只追问真正影响下一步的缺失条件；输出指标单位不能因 value=null 把探索性任务直接挡住，定量计算仍须真实有效输入。
- 解释与执行沿用同一任务/模型/预算，纯咨询目标为一次模型请求；不强制所有任务预先经历一次分类请求再一次执行请求。
- 接入已有 @Skill 和真实数据引用，先验证其与普通表达走同一入口。文件引用只确定合同和复用现有附件能力；新增完整选择器与检索排序归 AP.3/AP.5，避免 AP.1 再造解析或搜索服务。

验收：能力询问、安装指令、设计咨询、检索、计算、否定条件和混合意图的中英文改写均得到正确动作；咨询不会意外计算；明确执行不会仅给建议；计划修改不改变用户要求。“读取配方并提出三个方案”须保留两个意图和三个交付要求；只生成一个方案不能通过。移除旧关键词分流后，要验证原本被它保护的权限和产物门禁仍然有效。

### AP.2：宿主负责内部状态，模型负责研究行动

归属 UA.3 / UA.4。状态：开发实现及阶段回归完成；见 [AP.2 实施记录](ap-2.md)。同条件重复资格和安装包验收仍归 AP.6。

复用 `TaskSupervisor`、`execution-control.ts`、原生回执、已有 `verifyBackendSteps`。

- 由宿主管理计划 revision、受信 ID 映射、回执关联和已完成步骤；减少模型反复查询状态、复制控制候选和拼 JSON 指针。单一后端支持 `plan method=<实际注册名>`，宿主保留原合同并绑定固定产物；依赖式研究保留 proposal。
- 根据实际调用和当前步骤确定绑定；存在多个候选或依赖不明时返回明确选择，不能猜测归属。业务 targetId/jobId 仍以真实结果为准，不将任意 snapshotId 当成 candidateId。
- 仅有成功工具返回还不够：领域方法、退出码、运行中任务、必需文件、版本和哈希均满足时才自动登记技术完成。自由研究步骤不能仅凭“模型说完成”自动结束。
- 同一原生工具只执行一次；合法读写和探索无需额外 begin/complete 往返，但执行仍经授权、依赖与预算检查。
- 在原适配器落实完整调用事件、参数校验、调用/结果对应、退出码与截断信息；无效参数不运行工具。原生协议要求的状态必须正确传递，不将说明文字当作工具事件。
- 将完成、需补充、运行中、部分交付、失败、结果未知映射到既有任务状态。模型提交最终回复但执行要求未满足时不得标成功，也不能无限恢复或把真实失败吞掉。
- 不按两套逻辑维护完成状态；迁移涉及的旧显式控制调用，必要兼容登记消费者和删除条件。

验收：同一任务减少行政控制请求；重复回执不重复运行/扣费；非零退出、缺文件、错版本和运行中 job 不可完成；多候选不会误绑定；乱序/重复工具结果、流式参数不完整、自然语言伪调用均不能触发错误执行；既有恢复及会话继续通过。

### AP.3：中英文能力与工具发现

归属 UA.1 / UA.5 / UA.7。状态：开发实现及阶段回归完成；见 [AP.3 实施记录](ap-3.md)。同条件重复资格及安装包验收仍归 AP.6。

复用 `host-tool-router.ts`、共同能力目录、Skills/材料势目录，不建立第二个工具注册中心。

- 为现有能力提供中英文用途、输入/输出、同义表达和短例子；实现词项/同义词排序，必要时增加可替换语义排序。首版不要求联网向量服务或另下载大模型。
- 精确工具名优先；自然语言查询返回相关已授权工具及准确 Schema、限制和就绪状态，替换整句 includes 搜索。
- 初始给出少量相关工具与统一发现入口；按需获取参数，避免把全目录塞入每轮上下文。
- Skills 先提供相关用途概览，再读取所选版本的说明和附带资源；工具名称、Schema 和真实能力状态保持同步。不能把完整 Skills 内容或全部 Schema 当作常驻提示词。
- 增补第 3.2 节的类型明确引用选择与双语提示，兼容已有 @Skill；显示已绑定资源、版本、未安装/不可读状态和读取范围。复用已有文件附件入口，不创建第二套文件授权。
- “没找到”“已收录但未安装”“未配置”“未授权”“已验证可用”分别表达。未授权工具只能解释能力状态，不能借发现接口执行。
- 材料势选择保留元素、周期性、电荷/自旋、长程物理、任务类型、已安装状态和科学适用检查；语义相似不能绕过准入。

验收：用“查论文”“找水性涂料配方”“修 Python”“计算结构能量”等双语自然表达可找到正确能力；精确名不退化；错误能力不误用；目录规模增大时请求上下文不线性膨胀。@ 与普通表达对相同目标执行一致；引用不能提升权限；安装后的能力事实在下一轮可用，不能继续回答“不能安装”。

### AP.4：针对原因的恢复

归属 UA.3 / UA.5 / UA.6。状态：工程实现、故障注入与桌面回归完成；真实 RootFlowAI 端到端验收未通过（超时/传输失败/网关 HTTP 503），保留失败并等待服务恢复后复验。见 [AP.4 实施记录](ap-4.md)。不能据此宣称模型稳定成功或发布资格已通过。

复用 `model-recovery.ts`、共同错误合同、环境修复和 M5 原任务/请求账本，将核心恢复从错误字符串匹配迁入结构化分类。

| 失败类别 | 下一步 | 禁止行为 |
| --- | --- | --- |
| 参数/Schema 错误，尚未执行 | 提供字段位置、期望类型与最小合法调用，纠正后调用 | 随意丢弃业务字段或补虚构 ID |
| 已知脚本失败 | 读取真实 stderr/源码，授权内修改，再运行必要检查 | 只重复原命令、声称已修复 |
| 依赖/环境缺失 | 检查独立受管环境，依据锁定依赖和授权修复 | 借用用户 Codex/Python、无限安装 |
| 来源或能力不足 | 查当前事实、补批准数据或调整方法 | 伪造配方、密度、页码和科学结果 |
| 原 job 运行中 | 查询原 ID 并支持取消/继续 | 重复提交计算 |
| 付费请求/写操作结果未知 | 查询、恢复或对账原操作 | 自动重放或释放未知预留 |
| 权限/预算/不支持物理范围 | 清晰说明阻断及可选下一步 | 自动扩大权限、预算或科学适用范围 |

保持有限无进展修复上限、时间和预算；只读查询、计划 revision 变化不重置修复计数。终止时保留已完成产物和可恢复状态，展示具体原因，不把所有错误写成“模型调用失败”。

验收：注入每类失败并核对实际修复或正确停止；不制造重复副作用；正确退出码和未知账本状态保留；修复成功有真实运行与文件证据。

### AP.5：跨轮研究上下文与交付核对

归属 UA.1 / UA.4 / UA.7 / UA.11。状态：工程实现、三轮原生协议与桌面验收完成；真实供应商首轮 HTTP 503、账本待核对，连续研究任务验收未通过。实现、两批失败与限制见 [ap-5.md](ap-5.md)。

- 复用现有研究项目、来源快照、知识状态和任务日志，绑定“上述配方/这个结构/继续”的对象 ID、版本、证据和产物。引用不明确时先查看相关对象，确实有歧义再补充询问。
- 形成精简当前工作上下文：目标、有效约束、输入引用、已确认结论、缺失/假设、已完成动作、阻断项、下一步。按任务相关性读取，不反复附全目录和所有历史。
- 上下文清单绑定来源哈希/版本、页码或读取范围、遗漏与外发范围。按相关性和模型窗口分配证据预算；截断不能隐藏关键限制，大文件允许在原循环中继续检索/分段读取。
- 计划、压缩摘要与恢复共用这份清单，保留原调用关联和已完成动作；不凭摘要重建虚构回执。不相关历史不自动带入新项目。
- 新工具回执更新旧能力结论；事实和旧模型文字冲突时以受信来源/最新宿主状态为准。
- 最终核对用户所求产物和关键声明：路径真实、数值/单位/来源正确、能力否认与状态一致。确定性检查优先；复杂科学解释按需评审，不要求所有回答多一次 LLM 审核。
- 区分技术完成与科学待复核；任务失败、部分交付、成功有限制分别展示。不能用 needs_review 掩盖缺失产物，也不能把它一概当工具失败。

验收：三轮以上连续任务可引用实际上一轮输入并修改要求；重启后可恢复；不跨项目泄露；旧证据被修订后提示影响；能给出三个有来源/假设标签的候选配方，不凭空宣称已验证性能。

| --- | --- |

## 5. 验收指标与门禁

以下是拟定的工程预览目标，未达到前不能标“稳定”，也不代表科研精度或 Codex 全面同等能力。

| 指标 | 目标与统计口径 |
| --- | --- |
| 意图/下一步识别 | 保留集正确率至少 95%，按语言、场景分列；复杂缺条件任务正确询问/探索也可合格 |
| 支持范围内完成 | 至少 90%，连续三完整批次；每类单列，不用咨询量掩盖执行失败 |
| 必须阻断案例 | 所有权限/未知副作用/科学硬限制案例正确阻断；任何违规均挡发行 |
| 可恢复故障 | 每一支持故障类型至少三次重复注入，恢复或正确停止并有真实回执 |
| 纯咨询 | 不做无关工具调用；正常路径一次生成请求，不强制分类/计划/评审三次往返 |
| 性能 | 报 p50/p95 首次内容、总耗时、请求数与宿主分段时间；相同条件下宿主总耗时中位增量目标不超过原生基线 20%，不承诺固定秒数 |
| 预算/费用 | 原任务内计量，无额外影子请求；测试报告含实际用量与积分，采购费率未知时不推算人民币成本 |
| 交付/状态 | 所有关键产物读回核验；失败不标成功，技术完成不标实验已验证 |
| 版本一致性 | 测试源代码、构建和实际启动应用身份可核对，签名/跨平台/专家资格单列 |

指标解释遵循统计样本和不确定性：报告案例数、全部结果与波动，不从小样本推导“任何任务都能解决”。同一固定模型尚未达到门槛时，优先定位上下文、工具或宿主限制；确有模型能力证据后再评估路由调整。

## 6. 每阶段交付与实施顺序

顺序：AP.0 → AP.1 → AP.2 → AP.3 → AP.4 → AP.5 → AP.6。AP.0 的基线在后续阶段持续复用；AP.5 所需已有真实对象引用可在 AP.1 直接使用，不等待新状态库。

每项交付：涉及的合同/代码/界面、明确删除的冗余及调用证据、必要工程测试、真实任务结果、失败与限制、当前构建身份、回退方法。功能改善有数据再标完成，不按文件数量或单元测试数量认定 Agent 智能。

现有技术检查使用 `npm run check`、相关工程测试及开发构建；真实云测试沿用 `scripts/agent/rootflow-evaluation.ts` 和原网关/账本，需有效账户及调用授权。默认配置修改本身不需要真实付费生成。
