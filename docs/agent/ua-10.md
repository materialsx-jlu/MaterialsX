# UA.10 方法包：使用、发布与验收

日期：2026-10-06。状态：首批方法包工程预览。两项固定数值方法已完成真实参考复现；材料领域、专家/模型选择质量、Windows 和正式发布资格仍需分别验证。

## 使用

打开「研究数据与交付 → 方法包」。页面使用 Skills 相同的卡片、详情抽屉和全局主题，支持中文/英文名称、介绍和使用示例；示例可直接填入对话。详情可查看适用范围、资源、来源、四类许可、代码/依赖/数据合同哈希、参考数据、容差和实算回执。

点击「运行参考案例」会在本机使用已有数值模块实算，保存回执；不会下载新环境、模型权重或安装论文仓库代码。实际科研分析仍通过 `research_methods` → `research_method_run`，复用原任务权限、冻结输入、监督循环、研究数据库、真实文件写入及证据检查。

例子：先在「材料数据」选择有证据、属性/原单位/条件一致的观测，再输入：

> @materials-method-packages 对已选成对观测进行线性拟合，报告斜率、残差和输入范围，不作范围外预测，生成 JSON 和报告。

缺少 X/Y 配对、独立试样、单位或条件时，现有方法门禁会阻止计算或保留相应限制。示例不是已完成分析的声明。

## 方法合同与资格

`methods/catalog.json` 保存内置版本，合同在 `packages/contracts/src/method-packages.ts`。每个包保存双语范围/限制、论文/代码/数据/文档链接和版本、论文/代码/数据/权重分别的许可决定、现有工具 ID、代码与依赖锁、输入输出 JSON Schema、运行资源、参考输入哈希/认证值/容差，以及双语 Skill 指引与示例。

候选、参考复现通过、领域验证分别处理：

- **候选**：描述未完成审核/签名/适配，或兼容包尚未实算参考。内置兼容包可运行参考；不兼容外部包始终不可执行。
- **参考复现通过**：使用应用锁定的真实输入/认证值和已有执行模块，在记录的 Node/平台/架构下实算通过。导入者提供的 `passed`、声称的证书、模型文本或用户 Skill 不构成回执。数据文件的认证值还会与 manifest 预期逐项核对。
- **领域验证**：首批均 `domainValidated=false`、`productionApproved=false`。没有提供将包一键标记为领域合格的入口；科研结果继续 `needs_review`，需要真实材料数据、专家审查和独立验证后扩展资格流程。

任务开始把方法包 ID/版本/SHA 加入现有 `approvedInputs`。筛选记录引用该冻结版本；升级不会给旧任务偷换版本。运行前检查源文件、实际执行文件、依赖锁、JSON 合同、参考文件、发布历史与撤回状态；首次执行或环境变化时实算参考。JSON 同时携带方法 pin、完整参考回执和 assessment；报告列出版本与回执。来源或方法撤回令旧分析显示失效，最终验收阻止将失效结果宣称完成；历史文件和回执保留。

旧 UA.7 历史结果没有方法包 pin，不追授参考资格；旧未执行 assessment 需重新筛选。Node/平台/架构变化需重新参考复现。参考案例验证 CPU Float64 算法，不代表全部硬件/软件组合已通过。

## 许可和独立安装

首批没有复制论文正文、上游科学代码或权重；数值代码为团队已有实现，沿用项目 AGPL-3.0。两份 NIST 员工数据保留下载原字节和完整 non-SRD 数据声明于 `methods/references/NOTICE.txt`；使用依据与署名见 [NIST 数据许可说明](https://www.nist.gov/open/copyright-fair-use-and-licensing-statements-srd-data-software-and-technical-series-publications)。法律/数据发布审查仍按第三方清单进行，不把其他 NIST SRD 或外部作者数据泛化为同一许可。

`methods/`、参考数据/声明、JSON 合同和 `package-lock.json` 已纳入安装包资源配置。已有运行时、工具和科学模块直接复用，不依赖用户电脑安装 Codex，也不复制一套 Python/模型环境。构建后按原字节复制 canonical `.mjs` 到 dist，避免 TypeScript 重排格式导致运行与复算资产 SHA 不同；Git 固定 `.mjs`/锁文件 LF，`.dat` 禁止文本转换。此轮未生成或替换正式安装包。

## 社区审核、升级、签名和撤回

「导入方法包或发布文件」只读取选定 JSON（512 KiB 上限）。候选导入与本机审核使用同一 SQLite；模型仅有只读 `method_package_search`，不能写审核、安装代码或提升资格。本机审核记录审核人、依据、时间和精确包哈希，不等于作者资格或科学验收。

发布使用已有 M6 信任公钥与共用 canonical JSON / SHA256 / Ed25519 原语，另设严格 `materialsx-methods-v1` 类型通道，防止跨目录重放。两条通道的审核状态和签名都不会授予任意代码执行能力。社区包必须同时满足本机批准、可信签名发布、许可完成以及与应用内审定适配/Schema/参考/依赖完全匹配，之后才能实算参考。

发布回执保存序号、前一发布 SHA、精确 manifest、逐包审核、完整撤回清单、有效期和密钥轮换。拒绝篡改、未知密钥、降序/历史替换、无审核或错包审核、过期/未来发布、撤回删除、替换相同密钥 ID。回滚必须以更高序号指向已知旧发布并保留所有撤回。重复导入只在完整 envelope 相同时幂等；验签/保存失败不会修改数据库。历史撤回在离线和重启后继续生效；安装过的签名历史不会因离线时过期而被删除，新导入仍检查有效期。

维护者可准备符合 `methodReleasePayload` 的文件，然后用**仓库外的私钥文件**签名：

```bash
npx tsx scripts/agent/sign-method-release.ts \
  --input /absolute/path/reviewed-method-release.json \
  --key /absolute/private/path/publisher.pem \
  --key-id materialsx-catalog-2026-bootstrap \
  --output /absolute/path/signed-method-release.json
```

`previous` 是实际上一发布 SHA（首次 null），每个发布 entry 都需要精确 pin 的批准审核。私钥、身份和发布内容需由团队管理；测试使用临时 Ed25519 密钥，未修改生产信任公钥或生成生产签名。代码/依赖/数值参考的变更需要开发者更新审定适配、包版本与 manifest，不能靠社区元数据覆盖代码。重建 manifest 脚本只用于有审核的开发变更，不在启动或下载时自动运行。

新的方法线索可通过既有 `paper_search`/官方来源阅读取得，再整理成候选描述。当前没有通用方法自动爬取/自动下载执行器、远端社区运营站、收费作者体系或一键领域认证；M6 的新势发现仍沿原流程。签名升级/撤回的首版传输是手动 JSON 导入，没有设置未经审核的公网更新源。
