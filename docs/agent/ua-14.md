# UA.14 完整验收与发行

日期：2026-10-06。状态：验收工具与发行门禁已实现；正式发行未通过。当前工程预览不代表整个 UA 计划或所有模型、平台、科研场景已经合格。

删除原 `scripts/m4-release-readiness.ts`：仅凭文件存在和环境布尔值不能授予正式发行资格。旧 `m4:readiness`、`m4:release-gate` 命令分别转到 `ua14:report`、`ua14:release-gate`；兼容的命令名保留给现有 `verify` 调用者，不保留旧发行判定实现。桌面 `createReleaseReadiness` 保留为本机健康诊断，不能替代 UA.14 门禁。M6 的专项门禁只描述计算组件，不能代替整个产品发行资格。

已有 `localResponsesInvoker` 仍有真实调用者，而且统一委托原本地传输，保留兼容入口；未删除有效功能或清理用户工作区的历史改动。

## 固定案例与比较口径

`fixtures/agent/ua14-cases.ts` 冻结 60 个自有合成工程案例，每个均有中文、英文两个请求；不是将两种语言计为两个案例。六类各十个：文件精确修改、原值统计、线性拟合、来源数据交付、单位不兼容、缺失必需数据。数据批次、文件初态、数值、单位、来源和证据随案例固定，数值绝对容差 `1e-10`。三组完整对照需要 **360 个结果单元**。

六个任务族的合成变体用于检验工程执行与数值实现，不足以代表六十种独立的真实材料问题。UA.0 的 30 个需求理解案例继续用于复杂目标与计划合同；其历史通过记录不能自动充当新代码的资格。真实文献、势计算、实验、DOE、长期任务、多人团队的领域保留集须另外审核。

主体为 MaterialsX Pi、MaterialsX Codex、参考 Codex App Server。参考组是**未修改的开源 App Server + 相同材料工具/授权/监督**，直接运行原引擎入口，评估产品编排的额外行为；不代表商业 Codex 桌面产品或 OpenAI 闭源服务。

同一案例比较必须固定模型 ID/加载配置修订、权重身份、协议、上下文与输出预算、权限和时限、源码与锁文件、机器、原输入、初始工作区。每次使用新工作区/引擎目录；本地提供者按同一暖缓存策略顺序调用，不清理用户 LM Studio 缓存。三组调用顺序固定，尚未进行随机交叉顺序和多轮统计，不能据一次样本宣称性能优于参考产品。

CLI 当前限定本地回环模型，不隐式付费、下载模型或调用真实 MOOS、私人论文。平台模型需要受原 M5 预算保护的独立评测入口与采购费率证据；本轮不以本地试跑替代平台资格。

```bash
# 常规检查，不触发真实模型生成、支付或下载
npm run ua14:verify

# 显式开启本地真实生成；建议先选案例诊断
npm run ua14:benchmark -- --live --cases UA14-001,UA14-011 --locales zh,en --subjects pi,codex,reference-codex --output runtime/agent/ua-14/diagnostic

# 完整固定批次：60 × 双语 × 三主体，可能需要数小时
npm run ua14:benchmark -- --live --cases all --protocol chat-completions --model openai/gpt-oss-20b --output runtime/agent/ua-14/benchmark

# 汇总当前证据，缺项如实列为未通过
npm run ua14:report
# 正式发行：未通过时返回非零退出码
npm run ua14:release-gate -- --artifact /private/MaterialsX-installer --trust /private/release-trust.json --evidence /private/approved-evidence
```

输出目录仅用于私有工程记录，不提交到公开仓库。原模型文本不能代替真实文件；数值从原科学运行记录验收，单位冲突必须有质量报告，缺输入不得伪造分析。文件写入按字节比较，产物检查路径归属与哈希。每个单元保存真实 journal 与 finalText 哈希。完整 usage 缺失时 Token 为 `null/unknown`；不得将估算输入上界当作真实计费 Token。`recoveries` 目前表示失败/未知请求数，不表示已成功恢复的次数；详细恢复需检查原 journal。

模型加载配置在批次前冻结，每个单元前后重新核对；源码/套件变化也阻止沿用旧报告。不能挑成功单元拼成完整批次；不把不同模型、机器或协议差异归因于引擎。

### 权重身份

本地 API 的模型名或加载配置哈希不是权重内容哈希。没有经过核验的权重清单时可诊断，但正式对照阻塞。`--weights-manifest` 指定本机私有清单，文件放在对应权重目录内，以相对路径列出所有必要权重文件及 SHA-256，并说明量化与运行时版本；检查不下载、复制或加载权重。还需操作者确认该清单确实对应提供者当前加载的模型，API 本身不能证明其内存权重内容。

```json
{
  "modelId": "openai/gpt-oss-20b",
  "quantization": "MXFP4",
  "runtimeVersion": "填写实际 LM Studio/MLX 版本",
  "files": [{"path":"填写真实权重文件名","sha256":"填写真实 SHA-256"}]
}
```

## 科学报告与可信审批

`technical-report.md` 与 `scientific-report.md` 分开生成。现有 UA.7–UA.10 的独立数值参考复用原算法，不能认证材料规律、论文事实或模型适用范围。

正式发行需要授权的真实保留集、至少 60 个金标准字段、事实/数值/单位/引用、适用性边界、复现与独立专家检查。真实资料和图片许可未确认时不能进入公共样例包。专家审核必须有报告、报告哈希、已核对的发行包哈希和审批记录。

批准证据采用现有 Ed25519 元数据签名协议 `signMetadata`，不引入第二套签名算法；合同为 `releaseEvidencePayload`、`signedReleaseEvidence`。每份证据绑定当前源码/套件/锁文件/版本、具体安装包哈希、报告哈希、审核人、类别、平台和有效期（最多 30 天）。外部可信公钥配置必须由发布负责人确认，不能相信证据自身携带的公钥；撤销、错人、错类别、过期、修改内容或旧源码全部拒绝。签名只能证明批准来源，不能替代审核人验证科学事实和报告内容。

证据类别与必需检查见 `qualification/gate.ts` 的 `releaseChecks`：科学、macOS/Windows 安装、正式签名/公证、许可、M5/M6/旧项目迁移与更新回退、授权离线样例。没有可信配置不创建示例审批或假签名去通过发行。

## 包内容、安装与回退

正式生产 ASAR 排除开发 scripts/tests/fixtures/spikes、测试 JS 和 smoke 程序；保留实际 worker、科学后端与 Skill 脚本。`afterPack` 对生产应用实际字节做私有文件/秘密模式/开发源码检查，不能只依赖 package.json 声明。Skill 执行脚本是产品资产，不能误当临时开发脚本删除。第三方运行时/权重由既有独立内容哈希与许可清单覆盖，不声称文字秘密扫描覆盖所有二进制或任意密钥格式。

`ua14:migration` 从当前 Git 基线 M0 核心 SQLite schema 构建隔离旧项目，验证原项目/会话/消息、现有 M5 任务指针、重新启动、完整备份恢复和 M6 文件字节不变。只在临时数据库演练，未触碰用户数据库或重算权益/账本。真实服务端 M5 权益、签名安装器更新失败回退、跨平台迁移仍需实机批准证据。

`ua14:package:smoke` 复用已有打包测试，在隔离目录启动实际 Electron 工程包，PATH 不含系统 Codex/Node，验证包内 App Server、终端、patch、MCP。测试包未签名，模型响应受控；它不是全新物理机器的完整产品安装器验收。未重打多 GiB 的全部势安装包。
