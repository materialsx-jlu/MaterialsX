# Codex 本地性能优化与 PostgreSQL 复测

日期：2026-10-06。本机 LM Studio 0.4.25+1，模型固定为 `openai/gpt-oss-20b`，Codex App Server 0.160.0。复用原引擎、TaskSupervisor、材料工具和模型连接；未调用付费模型，未更新公开安装包。

## 改动

- 将逐轮变化的宿主状态放在最新工具证据之后，保留原生指令、用户条件、工具定义和已闭合历史的稳定前缀。当前证据、权限、预算和工具调用/回执配对不截断。
- 本地原生请求只展示已有监督和回执适配的工具；未适配的原生目录查询、交互提问、内置 goal 等工具不再误导模型。材料工具仍可经原 `find_tools` / `invoke_material_tool` 发现和调用。历史命名空间别名保持一致，现有授权检查照常执行。
- 该统计任务的工具定义由 18 个 / 18,667 字节降到 9 个 / 11,064 字节，定义体积减少约 41%。这不是全模型目录的数量变化。
- 科研工具已经返回所需 JSON、报告和实际结果时，模型简短回答并提供文件链接，避免重新生成整份报告或重复读取未变来源。用户明确要求在聊天中展开文件内容时仍可显示。
- 仅在实际提供原生组合工具时引导使用组合代码；通常直接调用本轮已声明工具，避免要求模型调用不存在的包装器。
- gpt-oss 的 Chat Completions 适配保留 `developer` 角色，其他模型保留原 `system` 兼容映射；不把工具间的最新宿主指令改为新系统设置。[OpenAI Harmony 文档](https://github.com/openai/harmony) 描述了该模型原生的角色与工具格式。
- 隔离验收支持 `--repeat 1–5`，记录每次成功或失败、逐请求耗时、首个受检流片段延迟、输入保守上界和供应商实际用量；不把字节上界当作 Token，也不把未知用量补成零。诊断只记录工具名、定义体积和回执长度，不默认输出完整研究内容。

## 性能证据

使用实际桌面运行入口、实际原生引擎与共享科研工具。输入为三份合成测试来源，原值 3 / 5 / 7 MPa；成功必须完成来源质量检查、方法评估、实际计算，生成均值 5 MPa 的 JSON / 报告并核对文件哈希。科学状态仍为 `needs_review`。

| 版本 | 实测 | 说明 |
| --- | --- | --- |
| 先前实现 | 成功约 227 秒 / 8 请求 | 历史报告 `numeric-historical-227s.json`；非本轮相同随机 ID 的配对基线 |
| 本轮改动前 | 56 秒失败 | 提前声称完成，实际没有分析文件；不作为速度提升 |
| 只调整状态位置 | 128 秒成功 / 5 请求 | 包含一次约 49 秒格式错误；单次结果不代表稳定资格 |
| 工具精简，仍改写为 system | 3 次中 1 次成功：92 秒 / 6 请求 | 另两次约 79 / 81 秒协议失败，不纳入成功耗时统计 |
| 最终版本，保留 developer 角色 | 3 次中 1 次成功：105 秒 / 6 请求 | 另两次约 83 / 78 秒，分别为协议标记与 task_control 参数错误；仍未获得稳定执行资格 |

最终成功样例较先前 227 秒少约 54%，但这是成功样例间的观察，不是稳定加速保证；连续成功率仅 1 / 3。保留 developer 角色没有解决本机全部工具解析错误，不将角色调整当作已证明的根因修复。全部中间结果和失败记录保留；总报告为 `runtime/agent/closure/codex-local-performance.json`，最终三个原始案例为 `numeric-perf-developer-role-repeat.json`。

LM Studio 已完成请求中返回的 `cached_tokens` 为 0。稳定前缀提供缓存复用条件，但目前没有缓存命中的证明，不能将耗时变化直接归因于 KV 缓存。请求次数、实际输出长度、格式纠错和后端负载都会影响总耗时。

## PostgreSQL 验收

- 本机通用 PostgreSQL 位于 `127.0.0.1:5432`，用户提供的身份可连接；没有现成 MaterialsX 身份库。
- MaterialsX 已有开发账户库位于 `127.0.0.1:55452/materialsx_local_dev`，使用独立运行角色，本轮未修改其账户、凭据或业务数据。
- 在 5432 上创建独立 `materialsx_ua_identity_test_20261006`，通过原迁移、原 Go 身份服务和随机合成账户执行客户端测试；测试后停止临时服务并删除该库。子测试数据库由 Go 测试自己创建和清理。
- 原先跳过的真实身份链现在通过：浏览器授权页/PKCE 回调、刷新凭据恢复、设备撤销、旧会话失效。客户端 8 / 8；Go 身份服务 15 / 15，零跳过；Go 全服务 `-race` 回归通过。
- 运行全套 Node 测试时传入真实隔离身份服务，共 330 项全部通过、零跳过。正常无 fixture 的 `npm test` 仍按原规则跳过该真实服务测试；这与本轮已有真实复测证据不同。
- `check`、600 行限制、完整构建、原生双引擎监督/终端/补丁/MCP 回归及独立数值校核通过。证据：`runtime/agent/closure/identity-postgresql-retest.json`。

## 复测

```bash
npm run ua:closure:workflows -- --numeric-only --codex-only --repeat 3
```

数据库测试先在本机环境变量设置 `MATERIALSX_IDENTITY_TEST_DATABASE_URL`，指向专门测试库（名字必须包含 `test`），不要指向已有账户库。DSN 不写入仓库或公开日志。

```bash
npm run m5:identity:live -- --all
npm run m5:identity:test
```

`--all` 沿用原身份 fixture 启动器运行完整 Node 测试，没有增加第二套账户服务。所有临时支付和云生成均关闭。上述复测未验收真实付费供应商、跨平台安装包或科研准确性，也不替代复杂论文导出与研究计划链的模型资格验收。
