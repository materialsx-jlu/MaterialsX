# UA.11 长期研究任务与本地计算

日期：2026-10-06。状态：macOS 本地计算工程预览。此阶段落实计划中的“受控 SSH/Slurm 或本地长任务”的本地路线；SSH/Slurm 和其他平台执行资格仍待接入与实测。

## 如何使用

打开「研究数据与交付 → 长期计算」。页面沿用 Skills 卡片、详情抽屉和全局配色，支持中英文、任务查询、运行日志和真实结果预览。

1. 点击「添加 NIST 参考示例」。程序将内置参考脚本、已有 OLS 数值模块、Norris 数据及许可说明复制到项目 `campaign-demo/`，生成已批准的示例配置。这一步不提交计算。示例最多计算 120 秒，总等待期限 48 小时；实际参考计算约 2 秒。
2. 点击配置卡片的「填入对话」。在该项目开始任务，Agent 使用 `campaign_job inputs` 获取冻结配置，然后以真实配置 ID 和研究理由提交。也可添加自己的配置：选择项目内审核过的自包含 `.mjs/.js` 脚本，列出依赖/输入、输出文件名、参数及时间、堆、产物上限，并明确批准退出后计算和暂停模型。
3. 提交后，模型会话暂停，任务显示「等待计算完成」。应用退出后独立进程继续运行；电脑必须保持开机，休眠会影响进度。页面可见时，只读查询已提交任务，不调用模型或提交新计算。
4. 打开详情，查询实际状态及日志。成功退出并核实所有必需产物的哈希后，显示实际输出、`job-summary.json`、`job-report.md` 和标准输出/错误日志。任务失败可查看真实运行日志；“请求取消”只有收到 worker 的取消回执后才成为已取消。
5. 计算完成后，在原对话「执行记录」中先「核对任务回执」，再「恢复原引擎」。恢复沿用原研究目标、计划、账户、连接、权限、已用请求和剩余模型执行时间。需切换引擎时，先在原引擎恢复并完成计算步骤验收。

新任务只冻结每个配置名称的最新版本。历史配置及哈希随原任务保存，不能通过修改当前配置替换旧任务输入。示例是数值回归与执行恢复测试，不是材料研究结论。

## 执行与证据合同

- `CampaignResearch` 是原 ResearchService 的本地计算提供者，使用原 SQLite/ResearchStore、UA.3 TaskSupervisor/日志、共享工具权限和产物写入器；没有第二套 Agent、自动重试或计费循环。Pi 工具和 Codex Host MCP 调用同一 `campaign_job`。
- 用户批准的配置不可变；冻结脚本/输入的确切字节、配置 ID/哈希、参数、最大计算时间和总等待期限。提交需要当前任务的真实在途工具 attempt，local 账户及 read/patch/terminal/science 权限；模型不能创建配置或扩大权限。
- 在应用私有 `long-jobs/<jobId>/` 暂存输入，记录 job ID、nonce、packet SHA256、worker 代码及实际运行时可执行文件哈希，**先持久化身份，再派发一次**。macOS 沙箱禁止网络，只给计算工作区及私有 HOME 写权限；环境不继承 API 密钥。系统公开运行库仍有只读权限，沙箱不是不受信任任意代码的平台。
- 独立 worker 保存实际 worker/计算 PID、Node/平台/架构、开始/结束时间、退出码、错误及输出哈希。取消只写给原 worker 的带 nonce 请求；不向恢复记录中的任意 PID 发信号。worker 只管理自身派生的进程组。
- 原任务/步骤/配置已经有作业时只查询原 ID。派发缺失、worker 消失、身份/packet/终态回执或文件变化保持 `unknown`，不自动重提。电脑重启不能恢复已经死亡的进程，也不会把保存的脚本自动再跑一遍。
- 成功状态要求退出码 0、全部指定文件、大小上限、冻结输入与真实哈希均通过；重复收取产物仅允许与磁盘现存字节完全一致。部分发布后的恢复不会覆盖变更文件。科研验收保持 `needs_review`。
- 模型会话的执行时间和受批准的计算等待时间分开。只有本提供者的真实待运行作业且没有未知模型/工具回执时，才能进入等待。等待不增加请求次数、积分额度或授权；首次 campaign 的总期限不随后续配置扩大。普通 UA.3 任务过期规则保持原样。
- 显示模型请求、排队、计算、下载和研究等待时长。该提供者无网络下载，下载时间为 0；研究等待与计算可能重叠，不应相加作为总时长。平台积分扣费为 0，本地电费/资源成本未计量，外部实际费用为 null。

## 当前范围与限制

| 项目 | 当前支持 |
| --- | --- |
| 运行时 | macOS 的应用独立 Node/Electron Node 运行时；不依赖另一台电脑安装 Codex |
| 脚本 | 用户已审核的自包含 Node 脚本及显式列出的本地依赖/输入；不提供 Python/第三方安装或远程执行适配 |
| 上限 | 全局最多 2 个在途或未核清的本地作业；每 campaign 最多 32 个；最长计算/总期限 7 天；单输入/输出 8 MiB，输入总量 24 MiB，输出总量 1–16 MiB，每路日志 512 KiB |
| 内存 | Node 堆限制 64–4096 MiB；不是 OS RSS/子进程内存硬限额 |
| 费用 | 离线计算不调用 RootFlowAI/M5 推理网关，不重复扣费；前序模型请求按原服务记录，本阶段未开放平台付费等待/恢复 |
| 恢复 | 应用关闭后进程可继续；重启先查询，完成后人工恢复原引擎；不后台自动唤醒模型 |
| 远程 | SSH/Slurm、真实 scheduler receipt、GPU/Python 环境、费用计量尚未接入；生成远程脚本不算执行完成 |
| 科学资格 | NIST 四字段参考复现及技术回执通过不代表材料领域、专家或真实 LLM 任务理解通过 |

私有工作副本和项目产物会占用磁盘，本阶段不提供自动删除运行输入或研究产物；后续空间管理需依据作业终态、引用和审计记录扩展。

## 验证

```bash
npm run ua11:verify
npm run build
```

测试包含真实独立沙箱进程、提交父进程真实退出后由新进程收取原任务、应用数据服务关闭/重启、NIST Norris 四认证字段、哈希核实及重复收取、Pi/真实 Host MCP 共享调用、输入变化/越权/软链接/输出遗漏/日志超限、计算超时/取消、进程容量和伪造回执防护。另用受控时钟模拟两天等待及期限到期，检查原请求数、剩余活动时间和授权不重置；这不等于实际连续运行 48 小时的稳定性测试。

实际 Electron 验收使用应用自身 Node 运行时进行后台参考计算、保留等待任务后重新打开数据服务、只读查询与结果预览、最新配置/历史保留、示例复制、中英、dark/light 全局主题、820/1600 宽度。证据位于本机忽略目录 `runtime/agent/ua-11/ui.json` 和 `campaign.png`。

本轮不包含真实 SSH/Slurm、重启操作系统后的进程恢复、付费等待、Windows/Linux 执行或真实 LLM 科学语义资格；未更新正式安装包。

本轮结果：`npm run ua11:verify` 与全量构建通过；373 项测试通过、1 项真实 PostgreSQL 身份服务未启用而跳过；16/16 默认团队 Skills 通过。所有自有代码 ≤600 行，最大 586 行。既有 3Dmol eval/大包体积构建提示继续保留，未新增正式分发资格。
