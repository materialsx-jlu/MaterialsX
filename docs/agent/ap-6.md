# AP.6：重复实测与安装包验收

日期：2026-10-06。归属 UA.14，复用原评测、M5、Codex App Server、工具、日志与发行门禁。工程入口已实现，是否取得稳定性/发行资格以当前指纹的实际报告为准；没有报告、供应商失败或结果未知均不能标通过。

## 变更

- 原 RootFlowAI 评测提取共用案例和产物核对函数；新增最小原生 Codex 对照入口，仍使用同一 M5 网关、原 TaskSupervisor/SQLite、项目工具和权限。删除原评测中重复的产物检查，旧入口保留兼容。没有新建模型循环、Agent、余额账本或研究数据库。
- UA.14 增补 UA14-061–070 共 20 个双语测试单元，两个主体共 40 格：能力询问、设计咨询、工具发现、显式/隐式 Skill、脚本修复、三个建议、引用中的命令与缺来源追问。三个双语对子声明为保留集，调参使用情况进入批次证据；用于修复后不能仍自称保留集。已有 UA14-001–060 和真实论文专家审核仍是独立要求。
- 指纹同时涵盖原案例与新增范围。批次编号、起止时间、输入、路由、协议、工具参数合同、实际权限、预算、机器、源码与构建均记录。每批还实际调用原 AP.5 三轮连续任务入口（包括修改要求与重启），保持原失败停止规则。必须三次完整批次，不能跨批次挑成功项拼接；中断/未运行保持缺失，失败在分母中。
- 每批以实际原生请求 ID 对应网关回执，区分未知终态、usage=null 与已完成。保存首内容、p50/p95、请求数、网关请求区间、工具区间、接受/恢复阶段和协调残差。请求时间包含网关/网络/供应商，不声称是纯模型耗时；残差不是隔离的宿主 CPU 开销。只有同条件成功对才比较，不从不同权限/模型或失败值推算提升，也不按未知采购费率推算人民币成本。
- UA.14 发行报告增加 AP.6 门禁：当前真实批次、完整双语、未污染保留集、意图/完成/边界、真实终态、同条件及观察到的协调增量；核验磁盘日志、报告和冻结前后指纹。新增 Linux 独立签收平台要求，不能由 macOS/Windows 证据代替。
- 原预览配置把补丁计划与阶段限制文档纳入分发。源码导出可指定独立输出目录，不覆盖以前的发行资产。自有源文件继续由原 600 行检查约束；没有将测试脚本放进产品 ASAR。
- 增加可选 `MATERIALSX_PROFILE_PATH`，只在明确设置绝对目录时使用独立本机配置；默认路径不变。相对路径、根目录、符号链接拒绝。用于便携配置和安装验收，不增加工具权限、自动登录或模型调用。

## 验收入口与证据

```bash
npm run check
npm test
npm run ua14:verify
npm run ap6:engineering   # 三次原生协议/原回归/网关故障检查，无外部模型调用
npm run ap6:live          # 三次真实完整双语对照，使用已授权的本机私有配置
npm run ap6:installed -- /absolute/path/MaterialsX.app
npm run ua14:report
```

报告保留在 `runtime/agent/ap-6/`，包括每一批日志和原回执。工程注入调用真实独立 Codex 与 MCP，但使用脚本化供应商，不能计入模型科研能力或真实云成功率。真实测试只用公开硅/合成配方；不会外发私有 MOOS、修改生产钱包或进行支付。未知的原请求不自动重放。

macOS 验收将当前产品包复制到临时 Applications 目录，启动该包的实际二进制，使用新 profile、新 HOME 和排除系统 Codex 的 PATH。仅此测试进程开放本机检查端口，退出即关闭；产品没有新增检查服务。核对加载的主程序指纹、桌面界面、SQLite、默认 Codex/平台模型、默认 Skills、独立 PDF/原子运行时、包内 Codex 版本、实际 ASAR 内容和预览限制。使用后删除临时安装与配置，不替换用户 `/Applications/MaterialsX.app`。

本机安装启动不等于完整付费云任务、长期研究稳定性或实验验证。macOS 的临时清洁安装验收不能替代用户旧配置升级、Windows/Linux 实机隔离、正式签名/公证与科研专家签收；未获得证据的项目保持未通过。预览包按原权利清单附许可和限制，待核实的样例权利不自动升级为已审核。

## 结果边界与回退

AP.4/AP.5 已有的 HTTP 503、超时、未知请求与待核对账本保留，不因新增评测删除。本阶段代码、测试工具和打包准备可以交付；只有当前真实三批、安装、签名及专家要求全部满足，才允许正式发行。详情以当前运行结果为准，不作 Codex 商业产品能力等同承诺。

初次 AP.6 实测发现检查器把“无需模型安装工具/本轮未授权安装”误判为“不支持 Skill 安装”，且最小对照在没有项目工具时显式传入空工具桥，造成其只读工具目录与产品不同。已修正评测入口和肯定/否定断言，并补回归；旧批次完整保留为无效历史，不计入同条件资格。回答语言遵循题目明确要求，不能仅凭测试单元的语言字段判断回答语言。修正后必须重新冻结构建和重跑整批。

连续追问实测还暴露了来源附件与数据库配方对象的类型差异：第一轮真实读取附件，第二轮仍被“上述配方”缺对象阻断。复用原工作上下文进行修复：仅当本轮唯一文件再次获准，且同账户/项目/会话的历史链含相同 ID、哈希和成功真实读取回执时，绑定原附件来源。附件仍标为 file，当前任务仍需真实读取，不生成 MOOS 配方 ID，不继承历史工具成功或云外发授权。不同账户、未读附件、撤销本轮选择或改动来源均继续阻断；已补重启与反例回归。

显式 Skill 实测还发现单步骤文件合同提前接受产物，随后读回文件被错误视为没有就绪步骤。原监督器允许尚未结束的单步骤直接文件任务继续使用原文件工具核验或纠错，绑定同一步骤并复用原回执、权限、版本和截止时间。相同已完成写操作仍返回缓存；已结束任务、多步骤依赖图及已完成科学后端不开放此入口。产物仍在最终交付前读回校验；旧实测保留，不拼接到修复后的完整批次。

批次时间上限按测试单元数 × 原 300 秒任务上限加启动余量计算，隔离评测账户有效期覆盖同一批次；不改变单任务权限、16 次请求或 500 积分上限。不用任意短的总批次超时提前裁掉后续案例，未知请求仍不重放。旧单批/AP.5 入口保留原账户有效期。

只读云咨询实测发现空项目工具桥回退到默认搜索权限，先向模型展示 find_tools，后被实际 read 授权拒绝，造成额外往返。产品及原生对照的空桥现在也始终携带真实授权，只向有 search 权限的任务展示搜索入口；已选文件仍可按 read 权限读取。修复不增加权限，补齐空桥和已选附件回归。

连续任务评测明确 scaled.json 根对象的总固体质量字段，保留原数值/来源校验，不按文字声明替代 JSON 字段。产物在隔离配置清理前按受控目录读取并存档实际字节及哈希；失败产物也保留，不制作占位文件。AP.6 成对结果复用监督器的真实文件证明填充 UA.14 artifact 表。

保留 `task_control` 显式调用、旧 RootFlow 单批命令、原任务和模型协议兼容；它们仍有实际消费者，不能为“清理”删除。删除的是已提取并共用的重复案例/核对实现，没有清空运行历史。回退前停止活跃任务，保存原 SQLite、未知请求和当前完整构建；不得通过回退把失败标成功或释放未知付费预留。

超时实测发现取消 RPC 与子进程退出发生竞争，未等待的取消 Promise 可能使宿主退出，导致整批缺失。后台取消入口现在处理拒绝；Codex 中断失败仍保留原未知请求，并关闭子进程，释放代理始终执行，不重放请求或标工具成功。回归使用实际标准输入输出子进程在中断时退出，验证请求已取消和代理释放。崩溃历史保留为未完成批次，不能与后续成功项拼接。

原保留集的引用命令实测暴露宿主把内联代码中的输出文件误设为交付义务，两组模型正确不执行仍被要求生成文件。现在复用同一输出合同提取器区分引用命令与字面文件名，普通输出路径及实际 Skill 调用保留；引用的 RPSME Skill 也不强加论文交付。原始用户消息和权限不改动。UA14-069 中英文保守标为已用于修补，继续出现在全部批次，但源码记录和批次门禁都阻止它们冒充未见保留集。需另行冻结未用于修补的验收数据后才能取得该项资格，即使后续全部通过也不自动恢复保留集资格。
