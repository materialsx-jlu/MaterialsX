# AP.2：宿主状态管理与真实执行验收

日期：2026-10-06。状态：开发实现及阶段回归完成；未替换本机安装程序或发布安装包。

MaterialsX 继续使用所选引擎的原会话与工具执行循环。默认独立 Codex App Server + RootFlowAI `gpt-5.6-sol`；Pi 保留兼容入口。宿主管理计划版本、步骤归属、回执、进程与文件验收，没有新增分类模型、调度 Agent、执行循环、数据库或计费账本。

## 本次行为

- 单一后端可调用 `task_control {"action":"plan","method":"materials_science"}`。宿主复用当前原始请求、目标、优先级、认知状态、约束、输入版本、授权、预算与截止范围，再绑定注册方法及其必需产物。不会为了简化计划删除用户命名文件、补造事实或增加权限。存在依赖的多步骤研究仍可提交原 proposal 合同。
- 唯一就绪步骤由宿主绑定实际调用；多个匹配步骤没有明确选择时，返回真实候选，不默认取第一个。`begin` 只用于消除歧义。业务候选、结构、计算、工作流和终端会话 ID 保持真实身份，不互相替代。
- 固定后端和有明确合同的读取、文件步骤，在原工具执行后由宿主检查主要方法、当前版本回执、任务终态及真实文件，再登记技术完成。前置读取不能冒充主要计算。科学计算强制包含结果 JSON、报告与 3D 结构；只有数值声明或计算仍在运行不能完成。自由研究仍需明确验收，叙述和科学有效性不被自动认证。
- 在途计算返回最多八条源于本轮真实回执的查询提示，继续查询原任务，阻止重复提交。自动分析工作流的 ID 与其子计算 ID 分开；不能拿子计算 ID 调用 `auto_get`。提示只帮助原模型选择下一步，不自行执行或轮询。
- `exec_command` / `write_stdin` 保存实际退出码、真实会话 ID、截断标记和原始输出长度。未返回退出码或会话的原生命令保留未知状态。非零退出保持失败；stdout 中看似退出码或任务状态的文字不能代替原生封装回执。空输入的会话轮询仍需原权限和会话所有权。
- 文件验收记录相对路径、SHA-256、字节数及计划版本，并复核已完成文件是否改变。验证期间发生修改、跨出项目、超过读取上限、计划被修订或任务被取消，均不能用旧结果完成步骤。旧日志可读取；没有旧文件哈希时，首次重新核对只建立当前基线，不能证明历史字节未变。
- 相同调用 ID 与输入使用原回执；改用同一 ID 表示不同输入、矛盾终态、未知写操作均不重放。原 M5 请求配额、账本和未知请求核对规则保留；本次没有新增收费重试路径。
- 流式参数及 finalized item 等待可靠终态后才放行。缺字段、无效 Schema、重复或冲突调用 ID、终态漏掉调用、失败/未完成终态、自然语言伪调用，不能进入实际执行。当前一次模型响应只接受一个原生操作；宿主工具继续经原 MCP 分发，不能通过 opaque composer 绕过窄步骤权限。

## 代码与兼容

主要入口仍是 `TaskSupervisor`、`CodexEngine`、`HostMcp`、`hostRouter` 和既有 Pi/平台适配器。抽出 `step-completion.ts`，删除监督器内重复的固定后端完成判断；共享原生 Schema 校验。`pending-job-guidance.ts` 只生成受信回执视图，`selectedMethodPlan` 只绑定已有合同。

`task-execution-v1` 增补可选 `nativeReceipt` 与步骤 `artifacts`，不建立竞争状态。完成检查在原工具之后和下一次请求之前进行；恢复、取消、计划 revision、预算仍使用原 journal。

| 保留接口/消费者 | 当前用途 | 后续处理条件 |
| --- | --- | --- |
| `task_control begin` | 多个真实就绪步骤的明确选择；旧模型调用兼容 | 歧义仍需显式选择，不能直接删去 |
| `task_control complete` | 自由研究明确验收；旧显式控制任务/回放 | 固定合同已自动完成；自由验收没有替代合同前保留 |
| `expectedRevision`、`receiptIds` | 旧客户端、测试和明确并发/证据核对 | begin/complete/replan 可省略，由宿主绑定；传入则仍严格校验 |
| `plan proposal` 与原解释入口 | 依赖式多步骤研究、非交互 Pi/脚本兼容 | 不能用单后端捷径替代复杂计划或删去原验收 |
| 原 Pi、平台工具事件适配器 | 同一监督与产物检查，保留现有选择 | 本阶段只做离线兼容回归，不声称 Pi 真实模型链路已验收 |
| 既有 SQLite 计划/恢复日志 | 旧任务重启、核对与继续 | 无批量清库、无自动改写旧科研证据；按原版本与权限恢复 |

所有自有代码通过 600 行限制；监督器约 520 行，桌面运行入口 572 行。没有清理范围外的历史代码、用户数据、环境或模型缓存。

## 验证与实际观测

最终 `npm run check` 通过核心、桌面、后台类型检查及 600 行检查；`npm test` 共 **502 项：501 通过、0 失败、1 跳过**。跳过的是未配置独立真实 PostgreSQL 身份服务的系统浏览器回调、凭据库重启与设备退出测试，不是本阶段云测试使用的隔离 PostgreSQL。桌面构建和隔离 UI 核验覆盖实际加载身份、默认云端/Codex、六个页面；模型调用和支付均为零。保护测试覆盖：唯一/歧义绑定、依赖、真正主要回执、在途任务、防重放、截断与非零退出、未知终态、已验收文件变化、并发修订/取消、缺文件有限续接，以及重复/乱序/不完整协议事件。原 SQLite 重启、CAS、会话恢复及预算回归保留。

真实测试使用已有 `scripts/agent/rootflow-evaluation.ts`，经过桌面运行入口、独立 Codex、原 M5 网关和隔离 PostgreSQL。仅使用合成涂料数据与公开硅结构，生产钱包写入和支付为零；没有外发私有 MOOS 数据。采购费用未知，不从 Token 回执推算人民币成本。

| 冻结批次 | 结果 | 实际观测 |
| --- | --- | --- |
| `live-batch-1` | 3/4 | 建议、指定 Skill 质量衡算、真实脚本修复通过；分别 1/4/8 次请求，内部 status/begin/complete/receipt 调用 0/0/1 次 |
| 同批次势计算 | 失败保留 | 15 次请求、约 264 秒；计划漏掉固定产物，反复计划与查询耗尽上下文。实际计算曾启动，但没有完整终态和交付，不标成功 |
| `science-batch-2` | 1/1 | 修正后 8 次请求、约 99.4 秒；一个 plan、一个额外 begin，无 status/receipt/complete 往返；一次真实 CHGNet 单点、查询终态、数值与文件核验通过 |

两个批次内部源码均未改变，构建均与该批源码匹配。不能拼接成同一构建的 4/4 或长期成功率。指定 Skill 本次约 58 秒，而脚本修复约 85 秒；供应商等待与任务差异仍明显，不能宣称所有任务提速或达到 Codex 桌面水平。模型仍可能多调用一次不必要的 begin。

新增 `scripts/agent/ap2-native-session.ts` 通过真正的独立 Codex 启动 Python、等待原会话、核对退出码与真实文件哈希。采用脚本化供应商响应，外部模型调用为零，约 2.3 秒；这是执行协议测试，不是模型理解能力测试。早期测试 fixture 的非法授权值和 opaque 参数写法失败日志保留，没有放宽运行权限来让它通过。

势计算之后还补齐了工作流/子计算 ID 不互换和两种原生截断标记的离线保护；最终文档更新后重建并核对开发应用身份。上述真实批次不是最终安装包资格。

原始日志、完整回执、输出及批次前后指纹位于忽略目录 `runtime/agent/ap-2/`，不会自动公开或打包。真实计算说明后端确实执行；不证明 DFT 精度、势适用于所有体系、实验真实性或科研专家审核通过。
