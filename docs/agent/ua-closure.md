# UA.1–UA.7 本地 Agent 闭环修复

日期：2026-10-05 至 2026-10-06。执行模型固定为 LM Studio 已加载的 `openai/gpt-oss-20b`，窗口 131072；不更换模型、不调用收费供应商。仍使用 Pi 0.99.1 / 随 MaterialsX 分发的 Codex App Server 0.160.0、同一研究计划和 TaskSupervisor、同一 SQLite 与原材料工具。

## 已修复的原因

1. **模型响应损坏后立即终止。** 对本地格式错误增加每个未推进阶段最多两次同引擎、同会话纠正；只有宿主核实完成了新步骤，下一阶段才重新获得纠正次数。单纯读取、版本变化或模型声明不重置次数，原 32 次请求/任务期限仍是总上限。纠正时带上实际回执和当前状态，不重放已成功的修改。不修补猜测的 paperId、工具名或参数。费用/执行结果未知、在途计算、权限不足、取消、超时和非格式错误不走这条恢复路径。
2. **工具发现无法真正激活工具。** Pi SDK 的 `tools` 是永久注册白名单；此前把按需展示列表当作注册列表。现注册完整现有工具，逐轮按任务与权限设置活动列表；`find_tools` 可以启用已注册的工具。会话换领域或权限变更时重新应用展示范围，沿用原 SDK 历史。
3. **采样与协议检查影响工具 JSON。** 本地请求显式设置温度、采样范围及惩罚参数，gpt-oss 使用低推理强度、`repeat_penalty=1`；实际是否应用由 LM Studio 后端决定，不把发送参数当作供应商行为证明。兼容探针识别具名 SSE 事件、注释和 CRLF。探针版本升级为 `ua5-wire-v2`，旧记录不作为新版本的资格依据。
4. **计划字段和引用错误。** 使用无执行工具的 JSON 解释请求，给出完整数据示例和明确的步骤编号、指标全部七字段。仅当用户和提案均未排列指标时，遗漏的 priority 使用 0（未排序）；明确排序缺字段或错误类型仍拒绝，不自行决定第一、第二优先级。宿主修复无歧义的序列化结构，将明确的步骤输入绑定为依赖、已注册方法绑定为原授权内的最小权限、固定后端产物绑定为已发布角色；不编造目标、来源、阈值或路径。自引用和循环依赖继续拒绝；错误引用的具体 ID 会反馈给唯一一次合同修复。识别明确的数字词及温度单位别名，保留 SI 大小写区别。失败仍不执行工具。
5. **有效产物被当作缺失文件。** RPSME 的逻辑角色从同任务、同计划版本、同一步骤的真实抽取回执解析；同时检查原 PDF、项目副本和三个产物的哈希/大小。固定统计报告的已知角色也只从同一步骤的实际后端记录解析；有歧义需要明确路径，不用文本宣称代替文件。
6. **统计任务被引导去生成对照表。** 研究提示、工具展示和验收共用任务判断。只要求数字分析和 JSON/中文报告时，固定分析工具的真实产物即可验收；明确要求 CSV/SVG、材料对照或来源已变化时仍保留对应门槛。
7. **计划和工具前置关系脱节。** 固定计算步骤内允许原后端的方法评估和来源读取，仍受原步骤/任务授权、依赖、预算和回执检查。前置工具成功不能代替主要计算完成。质量、固定分析和 RPSME 使用已发布的产物合同，由宿主在真实主要回执、文件归属、内容哈希均通过后完成技术步骤；科学结论仍需复核。不自动验收任意解释、来源读取、脚本或缺失文件。步骤切换提供真实 ID 的完整控制候选和精简回执；遗漏 expectedRevision 时准确指出必填字段及当前版本，不再错误提示“计划已修订”；模型提前结束时在本阶段剩余纠正次数内继续验收，与格式纠正共享上限。
8. **原生 MCP 依赖错误中断整个会话。** 注册的 HostMcp 工具在原分发器执行前校验，拒绝以普通工具错误返回给唯一的原生循环纠正；原生命令/补丁仍做流阶段预授权，未知工具和任意程序不获放宽。
9. **结果复述改错数值。** 对话交付追加固定分析工具的实际数值、选定原值、来源引用和产物链接，不由模型重建计算数字。
10. **本地原生状态序列化。** 私有 reasoning 保留在原生引擎历史中，不作为本地 Responses 端点的可移植状态或用户证据回传；普通消息、工具调用和匹配回执全部保留。组合工具通过真实 wire 名称与 JSON input 字段表达，不从泄漏协议文本猜测或执行命令。
11. **失败的原生请求残留为 running。** 上游解析失败或流被取消时关闭观察回执，未知用量保留 unknown；不据此释放或重试收费请求。
12. **真实 PDF 被误判为 MOOS 对照任务。** 原输入路径包含 `/Code/MOOS/`，通用交付识别曾把目录名当作任务要求，导致已有三个抽取文件仍被判缺失。现在按实际任务识别，屏蔽授权 PDF 路径；RPSME 不要求额外对照表，明确要求 CSV/SVG 或工作台交付时仍验收。最终抽取回答读取已核实归属和哈希的中文摘要，避免模型另写不符原文的交付摘要。缺失或改写的抽取文件仍不能完成。

13. **论文版本身份在工具间丢失。** 下载、分页读取和导出参数曾接受裸 arXiv 编号、URL 或缺版本 ID，随后只有笼统的未注册错误。现要求使用检索/身份工具回执的完整 `arxiv:` 与 `vN` 身份；未注册错误只列出当前项目至多八个真实 ID。不会自动换论文、补猜版本、访问其他项目或重放导出。原生 wire 的静态映射提示置于历史之前，保留最新真实工具回执/宿主状态在消息末尾；该顺序修正本身没有解决所有负例。真实格式纠正和论文身份拒绝分别记录。

14. **方法评估后缺少具体执行指引。** 宿主上下文现在列出来自本任务、当前计划版本成功评估回执的固定方法执行候选，包含真实 assessmentId、methodId 和完整必填参数；模型仍需按原目标选择，由原工具执行。只给出来源版本/哈希仍有效且未计算的候选，排除其他任务、未观察到的评估、已完成分析、来源撤回/无权限、在途或未知操作。候选不扩大权限，不执行计算、不批准科学结论。工具 Schema 和说明区分“评估”与“实际运行”，避免把 assessment 当作计算完成。

15. **默认并行执行与有依赖步骤不匹配。** 受监督的 Pi 会话使用原 SDK 的 sequential 调度，确保同一模型响应中的工具按顺序取得真实回执；不新增执行循环。即使供应商忽略 `parallel_tool_calls=false`，多工具响应仍串行执行，真实 SDK 测试验证前置回执先完成。计划提示优先表达主要计算步骤，数据读取/方法评估仍通过已授权原工具作为前置调用，不为每次准备读取添加独立步骤。未经核实的任意读取仍不自动完成。
16. **简单平均任务没有启用统计工具。** “平均数 / average”现在与统计任务共用按需能力判断；此前只会删除多余交付工具，没有启用分析工具。仍按实际已注册能力与权限过滤，无安装或授权扩张。
17. **参数是 JSON，但不符合实际工具合同。** 流适配层按本轮真实声明的工具 Schema 校验完整参数，在整个响应通过之前不放行工具终态。一个调用无效时，同一响应中的其他调用也不提前执行；错误只给字段和要求，不输出被拒绝的参数值。仅本地、没有未知操作的原会话可按既有两次上限纠正；不是自动改写参数。
18. **把方法评估要求成文件交付。** `research_methods` 返回登记的评估回执，不生成分析 JSON 文件。解释合同拒绝这种不可能的文件要求；独立评估步骤仅凭同任务、同计划版本、同一步骤的真实评估回执及匹配的来源版本/哈希完成。方法列表、外来任务、旧版本回执不算完成；实际分析仍需原计算工具和真实文件。
19. **已经选定的数据仍要求模型反复抄写 UUID。** Pi 和 Codex 共用同一工具接口：质量检查省略 snapshotIds 时使用任务冻结的明确选择；固定方法运行省略 ID 时只绑定本任务真实评估回执的唯一未运行候选。来源失效、多个候选、未知或其他在途操作均拒绝绑定，明确提供的错误 ID 不替换。底层科学 API 继续要求显式 ID，实际分析保留解析出的评估身份和源哈希。上下文显示最多四个候选，歧义判断使用完整候选集；研究状态作为对象附加，不再二次转义成 JSON 字符串。
20. **原生流过早把错误工具名当成执行资格失败。** 实测出现 `research_method_run?`，在有效终态前就被流监督拒绝，未能进入后续 wire 格式恢复。现在执行前的错误流名称归入格式错误，原本地引擎有机会按既有上限纠正；可靠终态中的未支持原生工具仍拒绝。没有按名称相似度执行、补猜工具、扩大权限或重放操作；未知收费请求和在途操作不允许这条恢复。
21. **方法评估重复要求填写已冻结的问题。** 实测原生引擎反复漏填 `input.question`。引擎工具接口允许省略该字段，后端使用同任务计划中完整的用户原始请求；不是模型推断的新目标。明确提供的问题不改写，空字符串/错误类型仍拒绝，超出领域 API 长度的原请求也不静默截断；分析类型与来源观测引用仍需模型明确选择并通过原合同。实际回执保存最终评估问题，底层领域 API 保持显式必填。
22. **产物已验收后仍反复操作完成步骤。** 完成状态提供明确的最终交付指引：必要时通过 task_control 读取原任务的真实回执，然后回答。原始工具结果及固定分析/摘要交付仍保留；不把已完成步骤重新开放，不允许新的计算或任意文件读取。模型若仍不遵循，原任务的请求/时间上限继续生效，不承诺无限纠错。
23. **明确的数量被当作未知单位。** 实际合同回归中，“最多八个配方”的 `count` 单位被拒绝。现在已知的 count 值必须匹配用户明确计数对象/量词相邻的同一整数；未知结果允许 value=null 保留明确的计数单位，不自动填数。不能借用温度数字、默认数量或小数后缀。物理单位继续保留大小写，并补上词边界，避免把 MPa/µm 内的 Pa/m 当作相同单位。原 29/30 负例保留，不改成通过。

每轮只附加最新权威状态，移除用户消息中的重复旧状态，减少上下文开销与状态冲突。

新增隔离验收的失败诊断，仅记录最后十二个 Pi 工具/模型错误；不默认收集完整模型响应。移除未使用的类型描述生成器和未通过实测的计划函数调用方案，以及论文验收脚本默认收集完整模型响应的调试路径。没有另建工具循环、科学执行器、计划数据库或材料统计算法。

## 可重复执行

```bash
# 不消费外部 API；SDK/原生执行、合同、数值、Skills 等统一回归
npm run ua:closure:verify

# 需要 LM Studio 加载同一个 gpt-oss-20b；依次执行，不争抢本地模型
npm run ua:closure:live
# 全量目标报告必须完成；复测读取该报告的实际失败项，不用写死的案例列表
npm run ua5:goals -- --failed-only

# 单独检查桌面实际工作流
npm run ua:closure:workflows
npm run ua:closure:workflows -- --numeric-only
npm run ua:closure:workflows -- --planned --protocol chat-completions
# 无 --protocol 时检验产品自动选择，并核对持久化的冻结连接
npm run ua:closure:workflows -- --planned
# 显式四组合诊断；包含受限协议，失败不得覆盖为“已支持”
npm run ua6:agents -- --matrix

# 用户已授权的本地真实 PDF；不外发全文，默认先检查 Pi
npm run ua:closure:workflows -- --rpsme-only --pi-only --pdf /absolute/path/approved.pdf

# 真实只读 MOOS 与桌面回归；MOOS 路径/本机后端需就绪
npm run ua4:moos
npm run ua7:ui
npm run ua7:m6-live
```

`ua:closure:live` 包含目标合同、四组合基础文件工具、默认两引擎论文工具和桌面抽取/统计任务；任一项失败返回非零，不把测试失败隐藏为完成。该命令也包含自动协议选择的计划执行链；`--matrix` 另检查包括受限 Responses 在内的四组合论文链。`--planned` 额外验证实际解释→分解→执行→产物，而非仅返回计划 JSON。脚本使用隔离项目/数据库和合成来源，不调用付费供应商或改动用户原项目。显式 `--pdf` 的真实论文项目保留，报告记录其路径，便于检查文件和失败回执；原 PDF 不改写。
