# 安装能力误答：原因、修复和验收边界

2026-10-06，用户先问“你可以自己安装 skill吗”，模型回答需要未授权的 `skill_installer`；随后发送“安装 Skill frontend-design”，应用真实安装成功。

## 查明的原因

1. 两个入口不同。明确安装命令由桌面宿主下载、校验、注册；一般询问进入模型。宿主安装能力不等同于一个模型执行工具。
2. 原生 Codex 会话恢复存在指令更新缺口。该会话创建于 05:30 UTC，其日志中的 `session_meta.base_instructions` 没有后来新增的安装说明；恢复后仍保留原始基础指令和多次错误回答。仅给 `thread/resume` 传新说明没有使本次记录获得新基础说明。
3. 没有实际权限拒绝。05:55 UTC 的任务权限记录包含 read/search/terminal/patch/network/science；并不存在名为 `skill_installer` 的拒绝回执。模型编造了工具名称和原因。
4. 模型回答本身仍不稳定。隔离实测中，即使读取了真实能力回执，也曾把宿主安装动作称为 `skill_installer`，或把“模型不能直接执行安装”表述成“我无法安装”。因此不能只修改提示词就宣布解决。

以上记录由本机数据库和独立引擎会话只读核对，没有删除用户历史、已安装扩展或改变账户权限。

## 本次实现

- **统一宿主事实**：安装合同在 `packages/skills/src/installation-capability.ts` 定义；能力帮助、共享模型指令和只读 `skill_capabilities` 工具共用它。
- **能力询问与执行分开**：普通安装能力询问直接展示应用帮助，无需模型或云账户，不触发下载。明确安装命令仍复用原安装服务和真实回执。此范围只覆盖 Skill 安装帮助，不代替科研任务理解。
- **恢复会话刷新指令**：Codex 模型请求转换后、监督和计量前补齐最新应用指导。保留原生指令、用户消息和工具证据；新会话已含当前指导时不重复增加。旧会话可能多占一份指导的输入 Token。
- **只读能力查询**：Pi/Codex 共用 `skill_capabilities`，返回当前扩展启用状态及安装边界。停用或损坏的指令不能报告为已启用；依赖和脚本可运行性仍须独立检查。
- **简单问答不建科研计划**：能力问题进入直接答复路径，不产生科学计算计划或扩大权限。

## 验收

```sh
npm run check
npm test
npm run build:desktop
node_modules/.bin/electron apps/desktop/skill-install-ui-smoke.cjs
# 可选：检查模型直接回答的语义；失败也保存诊断，不能替代产品路径验收
npx tsx scripts/agent/skill-capabilities-live.ts
```

回归包括旧基础指令与错误历史保留、新指导更新、重复注入防止、中英文能力问题、询问不安装、真实对话先问再安装、无需模型/账户、权限过滤、扩展状态变化和哈希篡改。

真实模型诊断使用当前 LM Studio `openai/gpt-oss-20b` 与 MaterialsX 自带 Codex App Server，在临时项目运行，不接触用户会话、不下载外部 Skill、不调用付费 API。诊断必须分别记录“实际读取能力”和“语义回答正确”；工具调用成功不能算语义通过。

本次桌面产品路径和代码回归通过：439 项测试中 438 通过、1 项既有环境跳过。模型直接答复的重复探针仍出现恢复后未读取更新能力的情况，最新记录因此为未通过；不得把前一次成功子集当作稳定资格。后续探针同时保存带时间的不可覆盖诊断和最新摘要。

## 继续归入统一 UA 计划

2026-10-06 后续重构已接入 [动态能力、状态纠错与回答核对](authoritative-state-refactor.md)。以下“本次只补 Skill 安装”和重复探针未通过是先前修复的历史范围；当前工程范围与最新验证以该重构附件及统一计划 5.4 节为准。旧失败记录仍保留，不以新成功结果覆盖历史。

- **UA.1/UA.5**：逐步把安装、模型下载、MOOS、论文、文件、终端、科学计算等宿主能力纳入同一动态事实目录，分清“已注册、已配置、已授权、已安装、实测可运行”。本次只补 Skill 安装，不宣称已覆盖全部能力。
- **UA.3/UA.4**：拒绝或成功的能力声明应有实际状态/回执支持；模型应根据新证据纠正旧结论。不要靠追加互相冲突的提示词维护能力状态。
- **UA.14**：同一任务集比较模型、协议、引擎和恢复历史。包含能力问答、缺配置、无权限、错误工具参数、失败后修复和真实文件交付，分别评价技术与语义。

使用 Codex App Server 提供执行框架，不会把连接的本地模型变成 Codex 所用模型。更换模型可能改善理解、规划和纠错，但不能补上宿主缺失的工具、错误状态或伪造的回执。本次修复不等于通过完整科研智能验收。
