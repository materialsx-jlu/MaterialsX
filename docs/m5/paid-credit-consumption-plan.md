# M5.3B：真实积分模型消费

2026-10-01。状态：本计划的指定账户真实消费闭环已实现并完成本机验收；生产输入边界和采购对账尚未确定。实施、启动与限制见 [实施文档](paid-credit-consumption.md)。

## 已确认的销售价格

供应商路由：RootFlowAI → `gpt-5.6-sol`，MaterialsX 模型别名 `materials-research`。以下是 **MaterialsX 对用户的积分售价**，不是 RootFlowAI 采购费率。

| 计费项 | 每 10,000 Token | 每 1,000,000 Token | 每 Token |
| --- | ---: | ---: | ---: |
| 普通输入（未命中缓存） | 10 积分 | 1000 积分 | 0.001 积分 |
| 缓存命中输入 | 1 积分 | 100 积分 | 0.0001 积分 |
| 输出 | 100 积分 | 10000 积分 | 0.01 积分 |

此前联调的充值比例为 ¥1 = 1000 积分。按这个比例，三项每万 Token 的积分售价分别折合 ¥0.01 / ¥0.001 / ¥0.10；这是充值比例下的销售换算，不用于反推供应商成本，也不是可提现余额。

计算公式：

```text
普通输入 = 输入总 Token - 已确认缓存输入 Token
消费积分 = 普通输入 × 0.001 + 缓存输入 × 0.0001 + 输出 × 0.01
```

例如：上游输入总量 20,000，其中缓存 10,000；输出 10,000，则消费 **10 + 1 + 100 = 111 积分**。不能把输入总量按普通费率全收后，再重复加收缓存输入。若推理 Token 已包含在输出总量中，也不另行重复加收。

首版只定义上述三项。长上下文阶梯、缓存写入、图像、音频、按次服务及工具费用没有得到本次授权，不能据此发明收费项或倍率。供应商 usage 缺项或计量口径不能确认时，进入待核对状态，未知不当零。

## 实施精度

为按用户给出的费率逐 Token 精确计算，真实消费按 0.0001 积分作为最小单位设计。现有测试账本按请求合并分子后向上取整到整数 `test-credit`；不将这一测试规则套到真实积分，使 1 个缓存输入 Token 的 0.0001 积分变成 1 积分。

真实消费内部使用 **1 积分 = 10,000 个整数子单位**：普通输入每 Token 10 子单位，缓存输入 1 子单位，输出 100 子单位。这样三项都可精确按 Token 结算，不用浮点数，也不逐项、逐片段向上取整。钱包展示最多四位小数。

实现时需新增明确的计量版本及兼容接口；现有 1010 积分不得被缩小或放大。迁移必须保留原不可变流水，逐账户验证新旧价值一致，并保留回滚/恢复依据。不能直接重写旧流水来改变历史含义。007 迁移采用增量子单位余额保留旧发放流水，详见实施文档。

## 实施范围

本子阶段属于原 M5.3（MX-504），连接 M5.2 网关，复用 M5.4 支付权益与 M5.5 桌面/后台展示。M5.6 为此闭环之后的付费 Beta 验收，不代替本次扣费实现。

1. 发布不可变销售价格版本，记录这次用户授权、模型/路由、生效时间和精度规则；旧任务继续使用原价格快照。
2. 核定可保证的输入/输出预留边界，预留不假定缓存优惠；现有 UTF-8 字节测试估计不能未经验证直接作为真实收费上界。
3. 将有效的 `paid-credit` 批次接入独立真实消费路径，检查账户、订阅、余额及任务预算；测试路线继续只消费 `test-credit`。
4. 预留事务成功后才向 RootFlowAI 分发。供应商 Key 保留服务端，桌面只使用 MaterialsX 身份令牌。
5. 保留现有 SSE 流式呈现、Pi 工具和多轮请求；可靠终态 usage 到达后结算实际消费，释放多余预留。同一请求重复回执不能重复扣费。
6. 调用失败、取消、供应商仍执行或 usage 缺失时，根据真实执行证据决定释放/结算/待核对，不能根据客户端关闭界面认定免费或重新生成。
7. 桌面展示普通/缓存输入/输出 Token、销售价格版本、本次扣减、剩余真实积分及费用状态；后台展示消费与采购成本，采购费率未知保持未知。

实施状态：销售版本已发布，本机指定账户已通过真实调用验收；固定风险预留上限用于付费联调，未被认定为生产 Token 上界。生产售卖保持关闭。

## 验收

- 上述 111 积分示例精确成立；缓存输入从总输入扣除，推理输出不重复计费。
- 按 0.0001 积分精度测试小额 Token、大量小请求、多轮工具、预算预留与释放；不按 SSE 增量事件重复累计最终 usage。
- 并发不能超余额，同 request/event 幂等，缺失缓存量不能按零结算，价格更新不影响旧任务。
- 历史实付的 1000 + 10 积分价值保持，真实/测试积分不会相互挪用；账本从流水重建一致，重启与中断恢复可核对。
- 经授权的一次真实 RootFlowAI 调用：流式回答、可靠 usage、积分真实扣减、钱包、任务账单和后台一致。
- 采购费率与输入上界未确定的部分要显式保留；不得用销售价伪装采购成本或利润已知。
