## 本次范围

这是受控开发环境的真实小额支付，不能表示一般商业销售已经开放。生产价格、采购费率、正式退款政策、发票及完整生产部署仍未验收。真实积分不会被 `test-credit` 技术测试模型调用消耗，当前云生成保持关闭。真实原路退款未执行。

- 新增 `wechat-pilot` 开关，仅允许开发环境、固定本机账户服务 Origin、`materialsx_local_dev` 数据库、关闭的云生成，以及指定 ID 对应的开发账户。
- 真实套餐严格匹配两个不可变快照：100 分 / 1000 积分 / 一个自然月；1 分 / 10 积分 / 30 天积分包。历史积分包只允许补记既有实付，不出现在销售目录。
- 新下单总量固定为该账户的一笔 100 分订阅，重复请求使用同一幂等键；并发或结果不明时也不能自动创建第二笔。历史 1 分补记最多一笔，重复导入不会重复发放。
- API 只接受套餐 ID 和渠道，不接受客户端指定金额、积分、账户归属或“已付款”状态。普通账户不能调用管理员模拟成功。
- 新订阅通过正常 PKCE 登录、订单 API、持久任务和微信官方 SDK Native 下单；客户端离线或关闭页面不会伪造到账。
- 新付款的 RSA/AES 成功通知与签名主动查询均已通过；金额、CNY、商户、AppID、订单及交易一致后，在同一数据库事务中写入付款、积分流水、积分批次与订阅账期。
- 原 1 分订单的历史通知证据保留在先前独立探针报告。本轮平台补记依据新签名查单；没有把旧通知伪装为新平台回调。
- `006_paid_credits.sql` 为既有积分批次新增不可改写的单位，原有记录默认 `test-credit`，微信实付使用 `paid-credit`。钱包分别聚合，两类流水显示单位，测试预留 SQL 只分配测试批次。运行角色不能提高余额、改单位、改金额或发布价格。
- 订阅沿用 UTC 锚点的自然月算法（月末夹到目标月末），UI 使用本地时间展示。真实续期与测试续期分开；本次没有自动续费或代扣。
- 联调退款仅使用现有人工申请、核算、审批与原路渠道流程；复杂退款及正式政策待定。本次没有提出、批准或提交真实退款。

## 私有配置与启动

商户 YAML 和 PEM 保留在外部服务的私有目录，MaterialsX 只保存引用。`runtime/wechat-pay/connection.env`、本机账户配置、授权快照、原订单和二维码都在 Git 忽略的私有目录中，不进入仓库、Issue 或公开日志。

本次已完成并关闭 ngrok 及回调进程；本机账户服务恢复默认 `MATERIALSX_PAYMENT_MODE=disabled`。重启后余额和订阅继续存在。**不要再次扫描已付二维码，也不要删除数据库或改套餐 ID 来突破本次金额限制。**

维护者未来明确授权另一笔联调时，应先审核新的独立授权与金额约束。本次脚本只可查询/恢复原订单，不能用于自动循环实付。

```sh
# 普通本机服务：不会启动收款
npm run identity:local
# 查询已入账余额、订单与订阅；不创建订单
npm run m5:payments:pilot-client -- --inspect
# 支付/权限/账本集成测试：只在临时数据库中运行合成证据
npm run m5:payments:db-check
```

受控联调的内部步骤为：创建仅代理 `127.0.0.1:8899` 的 25 分钟 ngrok 入口并保存私有授权 → `identity:local -- --wechat-pilot` 显式启动 → `wechat-pilot-operation --publish` 固定发布 → `--import` 签名补记 → `--serve` 启动仅回调监听和持久订单 worker → `pilot-client --create` 创建唯一授权订单并本地渲染二维码 → 用户微信付款 → `--watch` 查询到账 → `operation --verify` 双重验证、重建账本 → MFA 财务查询 → 关闭自己的隧道/回调进程 → 恢复默认服务。

ngrok 不代理账户服务 8788，不开放运营后台。实际公网 `/live` 为 204，`/ops` 和订单 API 为 404；关闭后本机 4040/8899 均不再监听。请求内容检查被禁用；仅 ngrok 子进程取消不受免费账户支持的代理环境变量。

二维码使用本地 [node-qrcode](https://github.com/soldair/node-qrcode) 生成，不向二维码网站发送付款 URL。MIT 声明保留在 `docs/third-party/QRCODE_LICENSE.txt`，依赖清单已更新。
