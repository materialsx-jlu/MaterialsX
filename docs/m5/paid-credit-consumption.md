# M5.3B：真实积分消费实施与验收

2026-10-01。真实积分消费已在指定本机开发账户完成 RootFlowAI 联调；通用生产售卖、供应商采购对账及 M5.6 付费 Beta 尚未完成。

## 已交付

- RootFlowAI `gpt-5.6-sol` / Responses SSE / Pi 多轮只读工具，平台别名 `materials-research`。
- 不可变销售版本 `paid-sol-20261001-v1`。每万 Token 普通输入 / 缓存输入 / 输出分别 **10 / 1 / 100 积分**；缓存从总输入扣除，推理输出不重复收费。
- 内部一个积分等于 10000 个整数子单位，按 `10 × (输入总量 − 缓存量) + 缓存量 + 100 × 输出量` 精确结算。HTTP 钱包、流水和任务账单使用最多四位小数的字符串，无浮点金融运算。
- 有效订阅、账户/会话/设备、指定账户、批次生效及过期、账户 UTC 日/月限额、任务预算和并发准入。测试路线只消费 `test-credit`；真实路线只消费 `paid-credit`。
- 按最早过期顺序跨批次预留，事务提交后才分发。可靠终态 usage 后扣减并释放多余预留；终态/Worker 重放不再次扣费。
- 未分发调用可释放；已分发但缺失输入、缓存或输出用量，或者用量超过预留边界，保留待核对。取消界面不等于供应商停止计费。Worker 24 小时告警、72 小时转人工，永不重新生成。
- 桌面显示真实余额、普通/缓存/输出 Token、价格版本、实际扣减和预留；任务账单及 CSV 保留计费模式。趋势和运营汇总将真实消费与测试消费分列，未知采购成本保持未知。
- 已有小数消费或预留的原订单不能按旧整数退款规则批准退款；先展示实际余额并人工核对。真实退款政策、部分小数退款计算尚待下一阶段确定。

## 预留边界及限制

RootFlow [接口文档](https://rootflowai.com/docs/api/reference) 没有提供这条具体路由可验证的输入 Token 预估接口。首版因此采用 **指定账户、有限额度的付费联调**，没有宣称已证明生产输入上界。

`paid-pilot-ceiling-v1` 2026-10-07 起拒绝超过 131072 UTF-8 字节（128KiB）的规范化原生请求体，按固定 **131072 输入 Token** 和实际 `max_output_tokens`（1–131072）的无缓存价格预留。以每次最多输出 1024 Token 为例，预留 **141.312 积分**；本机当前输出上限 8192 Token，对应预留 **212.992 积分**；实际消费按终态用量结算。小任务也需要足够的预留余额，预算低于预留额度会在分发前被拒绝。过长的文献提示或历史需分块/新建任务，不能借此声称完整 PDF 或任意长上下文已验收。

131072 是平台联调风险预留上限，**不是供应商已验证的上下文窗口、Token 计数或成本保证**。如上游超出该上限，任务转人工核对，不能超出用户预留/预算自动补扣；超额供应商暴露由平台承担。开放通用生产付费前仍需取得可信输入计量、核定输出（含推理）约束、采购费率和超额处置政策。当前采购成本为 unknown，不能从售价反推利润。

## 007 迁移及历史价值

新增 `007_paid_consumption.sql`，不更改 001–006 的校验和，也不重写旧不可变流水。

- 旧 `credit_grants.credits`、整数余额字段和发放流水保持原单位。
- 真实消费写入 `paid_held_subunits` / `paid_consumed_subunits`；新请求、分配及流水注明 precision=10000。旧流水 precision=1，数值没有缩放。
- 统一流水 ID/cursor，展示时按流水自身精度换算；跨批次一次请求可以有多条预留和结算流水，不能用流水条数当作模型调用数。
- 数据库余额守恒约束及流水精度触发器；受限 runtime 只能更新余额和业务状态，不能改批次面额、精度、价格或日/月政策。
- 校验分别重建旧整数余额、新子单位余额、请求分配和退款冻结/回收。实际迁移前私有备份及两条原发放流水基线均已保存，两条旧记录逐字段保持不变，1010 积分价值没有变化。

关闭消费可重启默认本机服务；**不能回滚到不识别 007 的旧消费代码继续运行**，那会误读小数余额。备份恢复需要先关闭调用，并核对备份后已产生的供应商用量及账单，不能直接抹掉真实消费。

## 本机运行

默认 `npm run identity:local` 仍关闭云生成和新支付。当前已运行显式付费模式：

```bash
npm run identity:local -- --paid-cloud
```

密钥仅保存在被 Git 忽略的 `runtime/m5-local/paid-cloud.json`（目录 700、文件 600），主进程只持 MaterialsX 账户令牌。私有配置格式如下；不要把真实 Key 复制到此文档或仓库：

```json
{
  "version": 1,
  "accountEmail": "developer@materialsx.local",
  "model": "gpt-5.6-sol",
  "apiKey": "<SERVER_ONLY_ROOTFLOWAI_KEY>"
}
```

启动器发布经确认的不可变销售版本，使用已有真实支付积分，不创建补发或新支付。指定账户默认日/月上限各 1000 积分；后台暂停云调用仍有效。API 和恢复 Worker 使用受限数据库角色。支付模式保持 disabled，无公网隧道。

桌面：开发版 → 设置 → 平台模型 → `materials-research`；任务积分上限默认 500（可填最多四位小数）。每轮发送前显示真实费率、预算、文件/历史范围并由用户确认。云服务中心 → 用量 可查看钱包、每个任务和每次请求。

停止 API、Worker 和专用 PostgreSQL：

```bash
npm run identity:local -- --stop
```

读取既有测试账单而不再次调用模型：

```bash
npm run m5:paid:live -- --verify-existing
npm run m5:paid:admin-check
```

`npm run m5:paid:live -- --authorized-local-paid-call` **会实际消费积分和调用供应商**，仅用于明确授权的新验收。管理员检查使用 MFA；同一期 TOTP 不能重复登录。

## 实际验收

一个公开合成 Si 文件，经 Pi 工具读取和最终回答共 **2 次真实请求**，均收到可靠终态用量并 settled。扣减 **5.668 积分**，真实余额 **1010 → 1004.332**，预留 **0**。钱包、按任务汇总的账单、跨批次不可变流水和管理员 MFA 汇总一致；采购成本仍未知。没有再次付款、补发或退款，也没有上传真实科研文件。

初次验收脚本误以为每请求只对应一条结算流水，在已完成两轮调用后的最终流水检查失败。已修正为按请求跨批次求和，并只读取既有账单复核，**没有再次生成**。原流式增量条数未持久保存，复核报告明确为 null，不能把重建数据称为新的流式实测。已执行的首轮 Pi 检查确认收到了增量、只读工具流程及包含 14 的最终回答；本轮验证不替代材料科学质量审核。

自动检查：实际 PostgreSQL / race 全套回归、受限角色的真实消费事务、0.0001 精度、111 积分公式、小数退款保护、恢复重放、缺失缓存用量保留、真实余额耗尽时不能借用测试积分；TypeScript 测试、桌面/后台类型检查及构建、OpenAPI 漂移和公开候选文件密钥扫描。Windows 实机、公网 TLS、生产备份恢复演练和供应商采购对账不在本机验收范围。

脱敏数据见 [paid-credit-validation.json](paid-credit-validation.json)，私有请求编号、密钥、账户登录资料及数据库备份不提交仓库。
