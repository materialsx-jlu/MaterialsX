# M5.0 计费与预算规范

此规范用于 MX-504 的生产实现和验收。当前新建的 QuoteFen 仅用于接入探针上界估计，不替代现有开发账本，也不代表生产收费已实现。

2026-10-01 用户明确解除本轮诊断金额上限。CLI 的显式 `--unbudgeted-test` 仅供授权联调：跳过金额预估/预留，不确认采购价格，仍限调用数与输出，不改本规范的生产结算要求。报告以 `budgetPolicy: waived-for-diagnostic-test` 区分；金额字段零不能解释为实际成本零。下面的30元累计预算保护适用于默认有价测试模式。

## 单位和价格

认证 token、模型 Token、MaterialsX credits、人民币分、供应商站内额度是不同单位，禁止相互混用。

采购价格版本记录 model/group/membership、币种或供应商额度、有效输入/输出/缓存价格、阶梯/计费方式、换算、证据和生效时间。销售价格版本单独记录 credits 费率和公布内容；商品、退款政策及额度授予绑定原版本。

RootFlowAI 的 `$` 为站内额度标识，不能作为 USD；其有效价依赖模型分组和会员档。已含倍率的价格不再次乘倍率。当前公开推荐分组页面不能确认该测试账户的 `gpt-5.6` 价格，缺失价格不按零处理。[供应商计费说明](https://rootflowai.com/docs/guide/pricing)

正式计费使用整数最小单位或经过审定的定点尺度，持久金额与 wire 均避免浮点。若价目需要比分/百万 Token 更小的尺度，应扩大定点精度再版本化，不向下截断。本期 CLI 只支持正整数人民币分/百万 Token 的核对价；更复杂阶梯、按次、多模态或独立费用组合不使用这个简化探针。

## usage 归一化

| 标准字段 | Responses | Chat Completions |
| --- | --- | --- |
| 总输入 | input_tokens | prompt_tokens |
| 总输出 | output_tokens | completion_tokens |
| 缓存读 | input_tokens_details.cached_tokens | prompt_tokens_details.cached_tokens |
| 推理子集 | output_tokens_details.reasoning_tokens | completion_tokens_details.reasoning_tokens |

本期 OpenAI 文本口径：缓存读是总输入子集，推理是总输出子集；普通输入 = 总输入 − 缓存读。若缓存字段缺失，普通输入与缓存均保留未知，不能编造缓存零。缓存写未得到可靠独立口径时不推导、不加收。

供应商累计 usage 以最终有效累计值更新，不逐事件相加。负值、小数、缓存大于总输入、推理大于输出、超过安全整数的数量拒绝归一化，转人工/日志核对。仅保存计量字段，不保存完整科研响应。

Pi 的 usage/cost 只用于显示/兼容观察。合成例子 input=10、cache=2，Pi 输出普通 input=8；服务端必须从原生 usage 记录总 input=10。SDK 缺字段时可能默认零，不能拿 SDK 默认值作为真实计费依据。

## 正式预留与结算合同

```text
验证主体/任务/模型/价格 → 服务端估计输入与最大输出 → 事务预留
→ 记录 request/attempt/版本 → 上游执行 → 可靠 usage → 事务结算/释放差额
```

- 预算包括账户余额、任务最大 credits、调用数、最大输出、时长、账户日/月限额及平台采购上限。任一边界不足先拒绝，不启动上游。
- token 上限依据目标模型与账户实测，不统一限制为 2700。超上下文按已公开的分块/压缩策略执行，原文证据不静默截断。
- 使用经验证 tokenizer/上游计数或审定的保守上界；无法锁定成本上界的参数组合不能正式售卖。
- 预留采用无缓存优惠的上界；结算优惠只按可靠 usage 与冻结价格版本。推理若含在总输出，不能另加一次。
- 同一 request 使用同一价格/路由快照；重复创建/结算/释放须参数核对和事务幂等。跨请求文本相同不能当成同一付费调用。
- 可用 = 有效授予 − 已结算消耗 − 有效预留，按即将到期优先选择额度来源。来源保留到退款冲正。
- usage 不明保留预留并待对账；失败确认无用量才释放。TTL 不证明请求停止，不能仅凭超时退回余额。
- 退款锁定原订单与额度来源，核对未结算调用并冻结可回收部分；按渠道成功证据追加冲正，不改历史，也不从其他订单额度中任意回收。

## 舍入与探针预算

同一次调用的互不重叠计费项在同一精度下先求和，再向上取整到最小扣款单位；不把每个 SSE 分片分别舍入。例子仅用于验证算法，不是供应商报价：

```text
普通输入 10,000 × 200 分 / 1,000,000
输出     1,000 × 800 分 / 1,000,000
总额 = 2.8 分，探针按上界取整为 3 分
```

QuoteFen 使用 big.Int 中间乘积并检查 int64 溢出。本期探针每次按请求 UTF-8 字节数加 4096 协议余量估计输入、256 输出估计上界；累计保留每次整笔预算，即使报错也不当作免费后释放，最多六次生成。

字节余量不是已验证的模型 tokenizer，256 不是已证明上游绝不超出的限制。未知独立费用、阶梯或忽略参数仍可能突破估计；真实付费前必须核对账户文本计费，观察 usage 超上界立即停止，超时尝试先对账。CLI 在固定 runtime 文件中先持久化每次上界，并以独占 lock 限制同一测试目录并发；重新执行不会重置30元累计预算，不自动释放失败/未知尝试。生产 M5 必须用 PostgreSQL 事务预算和真实对账替代该本地保护。

## 验收到生产前的差距

本期验证单位、未知/零、重叠 usage、整数舍入/溢出、预算拒绝与失败停止；MX-504 再实现 PostgreSQL 锁、额度批次、持久幂等、账本守恒、价格阶梯、账户/任务预算、对账 Worker 和跨实例竞争测试。通过探针单元测试不能标记这些生产能力完成。
